# Забор результатов Batch API через прокси (фикс 403 forbidden)

Исследование: `thoughts/research/2026-07-29-batch-results-proxy.md`

## Проблема

Batch-режим ESTIMATE_FROM_LIST на проде не может завершиться: пачка считается и
оплачивается, а на шаге забора результатов SDK уходит **напрямую** на `api.anthropic.com`
(абсолютный `results_url` игнорирует `base_url` прокси) и получает `403 forbidden —
Request not allowed` (геоблок РФ). Задача падает в `failed`, оплаченный результат забрать
нечем: `resume` для `failed` + `batch_pending` отдаёт 409, а кнопка на фронте предлагает
только полный пересчёт с нуля.

## Критерии приёмки

1. Любой запрос SDK, включая забор результатов пачки, уходит на хост `ANTHROPIC_BASE_URL`,
   а не на `api.anthropic.com`.
2. `collect_claude_batch` корректно разбирает JSONL-ответ (тот же результат, что и раньше).
3. Задачу в статусе `failed` с чекпоинтом `batch_pending` можно вернуть в `processing`
   без пересчёта — поллер добирает уже оплаченную пачку.
4. На карточке такой задачи есть кнопка «Продолжить» с пояснением, что пересчёта не будет.
5. Поведение локально (без `ANTHROPIC_BASE_URL`) не меняется.

## Не входит в задачу

- Переезд на другой способ обхода геоблока.
- Изменение логики самого расчёта сметы, добора цен, стоимости.
- Ретроспективный разбор других упавших задач.

## Фазы

### [x] Фаза 1 — запрос результатов через прокси

`backend/app/services/claude_service.py`:
- подкласс `_ProxiedAsyncAnthropic(anthropic.AsyncAnthropic)` с переопределением
  `_prepare_url`: абсолютный URL с хостом `api.anthropic.com` → относительный путь,
  дальше базовая реализация склеивает его с `base_url` посредника;
- `_get_client()` создаёт этот подкласс вместо `anthropic.AsyncAnthropic`.

Тест `backend/tests/test_batch_results_proxy.py` (пишется первым, red):
через `httpx.MockTransport` перехватываем фактические исходящие запросы
`collect_claude_batch` и проверяем, что все они ушли на хост посредника, а результат
распарсился. Тест не завязан на приватные методы SDK — переживёт апгрейд.

### [x] Фаза 2 — возобновление упавшей batch-задачи без пересчёта

`backend/app/routers/tasks.py` (`resume_task`): вернуть задачу в `processing` для любого
возобновляемого статуса, если `is_batch_pending(progress_data)` — не только для `paused`.
Пачка оплачена, результаты у Anthropic живут 29 дней, добирает `batch_poller`.

`frontend/src/pages/TaskStatus.tsx`: показывать блок «Продолжить» для
`progress_data._stage === 'batch_pending'` с пояснением «Пачка уже посчитана и оплачена —
продолжение заберёт готовый результат, повторного расчёта не будет».

### [ ] Фаза 3 — гейты и деплой

`pytest`, `ruff`, `tsc --noEmit`, `npm test` — зелёные. Коммит, деплой на Timeweb,
проверка на реальной упавшей задаче `90c4e0eb-0425-4209-9035-b27a243bd249`.

## Challenge Log

1. **Решает ли проблему?** Да: критерий 1 снимает 403, критерии 3-4 возвращают уже
   оплаченный результат пользователю.
2. **Самое ли эффективное решение?** Рассмотрены 4 варианта (см. research). Ручной
   httpx-запрос (B) дублирует авторизацию и ретраи SDK; транспорт-обёртка (D) прячет
   переписывание от глаз. Выбран C — 6 строк, вся машинерия SDK сохранена.
3. **Нет ли кода ради кода?** Правки строго по критериям: транспорт, resume-ветка, кнопка.
   Рефакторинг `collect_claude_batch` (в т.ч. висящий там `import inspect`) не трогаем.

## Итог

Фазы 1-2 реализованы, гейты пройдены. Фаза 3 закрыта частично: код на сервере,
подтверждения на реальной пачке пока нет.

- Фаза 1: `_ProxiedAsyncAnthropic._prepare_url` в `claude_service.py` — абсолютные
  URL Anthropic приводятся к относительному пути и уходят через посредника. Тест
  `backend/tests/test_batch_results_proxy.py` (5 кейсов) проверяет фактические
  исходящие запросы через `httpx.MockTransport`; до фикса падал ровно так же, как
  прод: `retrieve` → на посредника, `/results` → на api.anthropic.com.
- Фаза 2: `resume_task` возвращает `failed`/`paused` + `batch_pending` в
  `processing` без пересчёта (`cancelled` намеренно исключён); на карточке задачи
  появился блок «▶ Продолжить — забрать готовый расчёт». Тесты: 2 бэкенд-кейса в
  `test_paused_resume_dead_end.py`, 3 фронт-кейса в `TaskStatus.test.tsx`.
- Попутно: `_date` в `resume_from_batch` использовался без импорта (ruff F821) —
  NameError на задачах без `current_date` в чекпоинте, то есть ровно на
  возобновлении. Импорт добавлен.

Гейты: pytest 418 passed / 18 failed, ruff clean, tsc 0 ошибок, vitest 65 passed.
Все 18 падений — предсуществующие и к этой задаче не относятся: проверено
сравнением полного прогона до и после правок (на чистом дереве те же 18).
Файлы: `test_rate_limit_retry.py` (11, устаревший способ мокинга `_client`),
`test_admin_queue_health.py` (3), `test_balance_pause.py` (2),
`test_pdf_ocr_extractor.py` (2). Требуют отдельной задачи.

Осталось: убедиться на проде, что посредник пропускает GET
`/v1/messages/batches/<id>/results` со стримом — проверяется первой же
возобновлённой задачей (`90c4e0eb-0425-4209-9035-b27a243bd249`).
