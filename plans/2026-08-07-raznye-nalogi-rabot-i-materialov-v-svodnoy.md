# Разные ставки налога на работы и материалы в разделе сводной

## Проблема

В блоке «Разбивка по разделам» у раздела два поля «Налог %» — рядом с работами и
рядом с материалами, — но за ними стоит одно поле данных `tax_pct`. Меняешь
ставку у работ — она же меняется у материалов, и наоборот. На практике так не
бывает: работы у раздела может вести самозанятый (22% — НДС уже в цене), а
материалы закупает подрядчик с НДС (0% — добавляем 22%).

## Цель

Ставка налога работ и ставка налога материалов раздела задаются и хранятся
независимо. Всё остальное в бланке — без изменений до копейки.

## Решение

Раздел получает два поля: `tax_pct_works` и `tax_pct_materials`. Старое поле
`tax_pct` остаётся как запасное значение для уже сохранённых сводных: поля нет —
берём `tax_pct`, нет и его — 0. Миграции не нужно: разделы лежат в JSON
(`summary_estimates.sections`), схема их не типизирует (`list[Any]`).

Правило чтения одно и то же на экране и в файле:
`ставка работ = tax_pct_works ?? tax_pct ?? 0`, аналогично для материалов.

При правке любой из двух ставок в раздел записываются **обе** — вторая своим
текущим действующим значением. Иначе старый `tax_pct` продолжал бы влиять на
непойманную половину, и число менялось бы «само» при следующем открытии.

Альтернативы, которые отверг:
- **Переименовать `tax_pct` → два поля с миграцией данных.** Миграция JSON-снимка
  ради поля, у которого есть дешёвый fallback, — лишний риск на проде.
- **Хранить одну ставку и флаг «раздельно».** Два поля проще: флаг пришлось бы
  учитывать в четырёх местах расчёта.

## Фазы

### [x] Фаза 1. Экран: два независимых поля

- `frontend/src/types/summary.ts` — `SectionTab.tax_pct_works` /
  `tax_pct_materials`, `SectionCalcRow` отдаёт обе ставки.
- `frontend/src/stores/summaryEditorStore.ts` — `sectionTaxPct(sec, side)`,
  расчёт по своей ставке на каждую половину; `updateSectionTaxPct(idx, side, v)`
  пишет обе; `refreshSections` не теряет ни одну.
- `frontend/src/components/summary/SummarySheet.tsx` — поля независимы, подсветка
  своя у каждой половины.
- Тесты: правка ставки работ не трогает материалы; регресс бланка не сдвинулся.

### [x] Фаза 2. Файл сводной

- `backend/app/utils/summary_calc.py` — то же правило чтения, `section_totals`
  отдаёт обе ставки.
- `backend/app/utils/xlsx_summary.py` — в правой таблице две колонки налога.
- Тесты: раздел с разными ставками считается по каждой из них; старый раздел с
  одним `tax_pct` считается как раньше.

## Итог

Реализовано целиком. Экран и файл читают ставки по одному правилу; сохранённые
сводные со старым `tax_pct` считаются как считались.
