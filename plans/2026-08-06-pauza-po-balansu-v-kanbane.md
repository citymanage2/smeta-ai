# Пауза по балансу API — видимость в канбане

## Проблема

При исчерпании баланса Anthropic задача не падает в `failed`, а уходит в статус `paused`
(`backend/app/services/task_processor.py:1658-1668`). Это сделано намеренно: `resume_poller`
каждые 10 минут пытается возобновить такие задачи с сохранённого чекпоинта.

В канбане статусы разбираются плоским набором условий (`CardStageContent.tsx`), и ветки
для `paused` нет ни в стадии «Смета», ни в «Полнота»:

| статус | стадия «Смета» / «Полнота» |
|---|---|
| `pending` / `processing` | спиннер + прогресс |
| `completed` | файлы + «↺ Перезапустить» |
| `failed` / `cancelled` | бейдж + блок запуска |
| **`paused`** | **пусто — ни бейджа, ни кнопки, ни стрелки на карточку** |

`canCreate` = `task === null || failed || cancelled` — `paused` туда не входит, `RestartBtn`
рисуется только для `completed`. Итог: карточка показывает заголовок стадии и под ним ничего.
Пользователь видит «мёртвую» смету без единого объяснения и без выхода.

В стадии «Перечень» дыры нет: там ветвление через финальный `return`, и `paused` попадает
в общий блок с бейджем. В «Оптимизации» бейдж рисуется всегда (`launchBlock`), но кнопки
продолжения нет.

Эталон поведения уже есть на странице задачи (`TaskStatus.tsx`, `paused-block` +
`resume-now-button`) и в панели этапа (`StageProcessingPanel.tsx`) — в канбан он не доехал.

## Цель

Задача на паузе видна и управляема прямо на доске: понятно, что произошло, что прогресс
сохранён, и есть кнопка немедленного продолжения (не дожидаясь 10-минутного поллера).

## Критерии приёмки

1. Стадия «Смета» с `estimate_task.status === 'paused'` показывает бейдж «● На паузе»,
   пояснение про баланс API и кнопку «Продолжить сейчас».
2. То же для стадии «Полнота».
3. Стадия «Оптимизация» на паузе — к существующему бейджу добавляется кнопка продолжения.
4. Стадия «Перечень» на паузе — пояснение и кнопка добавляются к существующему бейджу.
5. Кнопка дёргает `POST /tasks/{id}/resume` (`resumeTask`) и обновляет доску, чтобы статус
   сменился без ожидания поллинга.
6. Ошибка запроса показывается текстом рядом с кнопкой, кнопка снова доступна.
7. Блок запуска новой задачи (`canCreate`) на паузе не появляется: пауза — не терминальный
   статус, повторный запуск потерял бы сохранённый прогресс.

## Вне рамок

- Изменения бэкенда: `/tasks/{id}/resume` уже принимает `paused` и не требует чекпоинта
  (`routers/tasks.py:811-849`).
- Пуш-уведомления о паузе — уже есть в `useGlobalTaskPoller`.
- Автопополнение баланса, алерты администратору.

## Фазы

### [x] Фаза 1. Тесты (red)

`frontend/src/__tests__/kanbanPausedStage.test.tsx` — рендер `CardStageContent` с карточкой
в каждой из четырёх стадий со статусом `paused`:

- виден текст «На паузе» и упоминание баланса;
- есть кнопка «Продолжить сейчас», клик вызывает `resumeTask(taskId)`;
- на стадии «Смета» при `paused` нет кнопки «Создать смету»;
- ошибка `resumeTask` → сообщение на экране, кнопка снова активна.

### [x] Фаза 2. Компонент и ветки (green)

  (`#fffbeb` / `#fcd34d` / `#b45309`), текст, кнопка, локальные `loading` и `error`.

  в `CardStageContent` — `resumeTask` + `fetchMeta` + `fetchCards(card.project_id)`.

- `canCreate` / `canStart` не трогаем — `paused` в них и так не входит; проверить, что
  блок запуска при паузе не рисуется.
- `PausedBlock` в `ListStage` (общий финальный блок) и в `OptimizationStage` (`launchBlock`).
