# План: перевод смет на единый источник правды — из админки

**Связанный план:** `plans/2026-08-02-edinyy-redaktor-tablic.md` (Фаза 5)
**Статус:** completed (2026-08-04)
**Размер:** M — стадии 1–10 методики `bulletproof`
**Ветка:** `feature/estimate-migration-ui`

---

## Проблема

После Фазы 5 смета хранится в одном месте — рабочей версии (`EstimateVersion`).
У смет, посчитанных до этого, версии может не быть, а у части — два хранилища
разошлись. Разовый скрипт `backend/scripts/migrate_estimate_items.py` это чинит,
но **запускается только из консоли сервера**: с деплоем он не идёт (на старте
выполняется лишь `alembic upgrade head`), а прямого доступа к боевой базе у
исполнителя нет.

Пользователь — не разработчик. Просить его копировать команды в консоль
контейнера значит превратить безопасную операцию в рискованную.

## Цель

Перевод смет выполняется из админки: сначала отчёт (ничего не меняется), потом
применение — с возможностью не трогать активные тендеры и разобрать расхождения
по одному.

---

## Область работ

### Входит

- отчёт «что будет сделано» без изменений в данных;
- создание недостающих рабочих версий (сметы без версии);
- разбор расхождений **по одной смете**: видно оба итога, человек выбирает
  сторону-победителя;
- исключение выбранных смет из операции (активные тендеры);
- повторный запуск безопасен — операция идемпотентна;
- права: только `admin`.

### Не входит

- изменение самой логики миграции — она написана и покрыта тестами в Фазе 5;
- фоновое выполнение с прогрессом: создание версий не пересобирает файлы и идёт
  быстро, а разбор расхождений выполняется поштучно;
- удаление скрипта — он остаётся как запасной путь для консоли.

---

## Критерии приёмки

- [x] В админке есть раздел «Перевод смет» с кнопкой «Проверить», которая
      показывает сводку и списки: сколько смет совпадает, скольким нужна версия,
      где расхождения.
- [x] Отчёт не меняет ни одной записи в базе.
- [x] Кнопка «Создать недостающие версии» создаёт версии тем сметам, у которых
      их нет, и **не трогает** сметы с расхождением.
- [x] Сметы, отмеченные как «не трогать», пропускаются.
- [x] Для сметы с расхождением видны оба итога (расчёт и редактор) и число
      расходящихся позиций; выбор стороны применяется только к ней.
- [x] Перед перезаписью строк обе стороны сохраняются в историю задачи.
- [x] Повторный запуск ничего не меняет.
- [x] Раздел доступен только администратору.

---

## Ключевые решения

1. **Логика переезжает в `app/services/estimate_migration.py`.** Сейчас она
   лежит в `scripts/`, а импортировать скрипт из приложения нельзя. Скрипт
   становится тонкой обёрткой над сервисом и продолжает работать как раньше
   (его тесты — тоже).
2. **Разбор расхождений — поштучный.** В скрипте `--prefer` применялся ко всем
   конфликтам сразу. В интерфейсе это опасно: у каждой сметы своя история, и
   «взять из расчёта» для одной может быть верным, а для другой — потерей
   правок. Поэтому сторона-победитель выбирается для конкретной сметы.
3. **Синхронные запросы, без очереди.** Создание версий не пересобирает xlsx
   (`ensure_working_version` файл не трогает), поэтому идёт быстро. Разбор
   расхождения пересобирает файл, но выполняется по одной смете.

- **Файлы:** `app/services/estimate_migration.py` (новый, перенос логики),

- **Эндпоинты:**
  | Метод | Назначение |
  |---|---|
  | `GET /admin/estimates/migration` | отчёт, ничего не меняет |
  | `POST /admin/estimates/migration/apply` | создать недостающие версии (`exclude[]`) |
  | `POST /admin/estimates/migration/resolve` | разобрать расхождение по одной смете (`task_id`, `prefer`) |
- **TDD:** отчёт не меняет данные; применение создаёт версии и пропускает
  конфликты; исключённая смета не трогается; разбор расхождения пишет бэкап в
  историю; повторный запуск идемпотентен; не-админ получает отказ.

### Фаза 2. Админка: раздел «Перевод смет» [x]

- **Файлы:** `frontend/src/pages/Admin.tsx` (новая вкладка),
  `frontend/src/api/admin.ts`,
  тесты: `frontend/src/__tests__/estimateMigrationPanel.test.tsx`
- **Изменения:** вкладка со сводкой, списком смет, галочками «не трогать» и
  разбором расхождений по одной.
- **TDD:** сводка показывает числа из отчёта; «Создать недостающие версии»
  отправляет исключения; расхождение показывает оба итога; выбор стороны уходит
  на сервер с идентификатором конкретной сметы.

### Фаза 3. Расхождение объяснено словами [x]

**Зачем.** На боевых данных нашлось 9 расхождений, и у шести из них итоги
совпадают до рубля, а «расходится позиций» показывает сотни. По такому отчёту
решение принять нельзя: непонятно, изменились ли цифры, или строки просто
переставлены местами. А цена ошибки — потерянные правки человека.

- **Файлы:** `app/services/estimate_migration.py`, `app/routers/admin.py`,
  `frontend/src/api/admin.ts`,
  `frontend/src/components/admin/EstimateMigrationPanel.tsx`,
  тесты: `backend/tests/test_estimate_migration_api.py`,
  `frontend/src/__tests__/estimateMigrationPanel.test.tsx`
- **Что добавляем в отчёт по каждому расхождению:**
  | Поле | Смысл |
  |---|---|
  | число строк с каждой стороны | «343 против 345» — сразу видно, что состав разный |
  | признак «отличается только порядок» | набор строк совпадает, переставлены местами |
  | признак «итоги совпадают» | деньги одинаковые, разница в чём-то другом |
  | примеры различий (до 3) | «Кладка стен: цена 1000 ₽ против 777 ₽» |
- **TDD:** переставленные строки дают «только порядок»; изменённая цена даёт
  пример с обеими величинами; разное число строк видно в отчёте; примеры
  ограничены тремя; на экране расхождение объяснено словами, а не числом.

### Фаза 4. Отчёт не падает на строках без чисел [x]

**Зачем.** Первая же проверка на боевых данных после Фазы 3 вернула «Не удалось
получить отчёт». Причина — заголовок раздела: у такой строки нет ни количества,
ни цен, а пример различия печатал количество как число. Одна такая строка
роняла отчёт по всем 146 сметам.

- **Файлы:** `app/services/estimate_migration.py` (`_money`, `_row_text`),
  `frontend/src/components/admin/EstimateMigrationPanel.tsx` (`describeError`),
  тесты: `backend/tests/test_estimate_migration_api.py`,
  `frontend/src/__tests__/estimateMigrationPanel.test.tsx`
- **Что сделано:**
  - строка без количества и цен описывается словами, а не форматируется как
    число: «без количества и цен», прочерк вместо отсутствующей величины;
  - причина отказа сервера показывается на экране — код ответа и текст. У
    администратора нет доступа к логам контейнера, а без причины и «нет сети»,
    и сбой внутри отчёта выглядят одинаково.
- **TDD:** строка-заголовок не роняет `describe_diff`; отчёт по API отдаёт 200
  для сметы с разделами; на экране видна причина ошибки, а не «попробуйте ещё
  раз».

## Итог

**Реализован:** да, обе фазы.

**Что получилось.** В админке появилась вкладка «Перевод смет». Кнопка
«Проверить» показывает сводку и ничего не меняет; сметы, которым нужна рабочая
версия, перечислены списком с галочками «не трогать» для активных тендеров;
расхождения разбираются по одной смете — видно оба итога и число расходящихся
позиций, а прежнее состояние уходит в историю сметы.

**Отклонения от плана (осознанные):**

1. **Разбор расхождений сделан поштучным**, а не флагом `--prefer` на все сразу,
   как в консольном скрипте. У каждой сметы своя история: «взять из расчёта» для
   одной может быть верным, а для другой — потерей правок человека.
2. **Скрипт не удалён.** Он остался запасным путём для консоли и теперь тонкая
   обёртка над тем же сервисом — его прежние тесты продолжают работать без
   изменений.
3. **Кнопка применения блокируется, когда отмечены все сметы** — иначе она
   выглядела бы работающей, ничего не делая.

**Гейты:** бэкенд 921 passed / 9 skipped, ruff чист, фронтенд 277 passed, tsc чист.

**Что показала работа на боевых данных (2026-08-04).** Проверка нашла 146 смет:
43 в порядке, 54 без рабочей версии, 9 с расхождением, 40 пустых. У шести из
девяти расхождений итоги совпали до рубля, а «расходится позиций» показывало
сотни — по такому отчёту решение принять нельзя. Отсюда и родилась Фаза 3:
теперь видно число строк с каждой стороны, сказано прямо «итоги совпадают» и
«отличается только порядок», и показаны примеры того, что именно разошлось.

**Не задеплоено** — ждёт отдельной команды.
