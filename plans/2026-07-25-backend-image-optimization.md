# Оптимизация размера backend-образа

**Дата:** 2026-07-25
**Проблема:** диск backend-App на Timeweb занят на 27 ГБ (из 50). Основная причина —
тяжёлый Docker-образ, накопленный ×N пересборок. Один образ раздут CUDA-сборкой PyTorch.

## Диагноз

`backend/requirements.txt` содержит `sentence-transformers>=3.0.0`, которая транзитивно
тянет `torch`. `pip install` по умолчанию ставит torch с CUDA-библиотеками NVIDIA
(`nvidia-cuda-*`, `nvidia-cudnn-*` и т.п.) — это **~4–5 ГБ**, бесполезных на сервере без GPU.

Ключевой факт: `embedding_service.py:18` — дефолтный движок эмбеддингов **`fastembed`**
(ONNX, без torch). `sentence-transformers`/torch нужны только для:
- `retraining_service` — дообучение модели (редкая тяжёлая операция);
- inference дообученной модели (`reload_model(model_type="sentence_transformers")`).

→ CPU-only torch безопасен: обычный поиск цен (fastembed) не затрагивается,
дообучение просто идёт на CPU (медленнее, но корректно).
