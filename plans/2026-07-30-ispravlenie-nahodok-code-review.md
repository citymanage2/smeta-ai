# Исправление находок код-ревью (2026-07-30)

Находки из ревью всего проекта. Каждая была подтверждена экспериментом или
чтением цепочки вызовов — гипотезы без доказательства не включались.

## Фаза 1 — цены от ИИ: приведение типа и валидация [x]

Доказано запуском: `work_price="1500"` (строка) при `qty=3` →
`TypeError: type str doesn't define __round__`. Хуже падения: к этому моменту
все запросы к ИИ оплачены, а чекпоинт `_stage="pre_excel"` уже сохранён — при
возобновлении задача идёт сразу в сборку Excel с ТЕМИ ЖЕ данными
([task_processor.py:2246]) и падает снова. Перезапуск не помогает никогда.

Отрицательная цена (`-1500`) не падает вовсе — даёт смету с
`grand_total = -4635.0`, которая уйдёт на тендер.

Защита в два рубежа:
1. На входе от ИИ — чтобы в чекпоинт попадали уже чистые данные.
2. В генераторах Excel — чтобы уже сохранённые «грязные» чекпоинты не роняли
   задачу навсегда. Это и лечит застрявшие задачи без правки БД.

- `app/utils/price_coercion.py`: `coerce_price` / `coerce_qty`.
- Применить в `xlsx_exporter`, `excel_service`, `task_processor`.

## Фаза 2 — права на каталог расценок [x]

одна и та же (`PriceWork`), по ней считаются все сметы всех пользователей.

## Фаза 3 — перезагрузка прайса на каждую позицию [x]

`_apply_chunk_items` вызывает `_cache_priced_item` для КАЖДОЙ позиции →
`save_to_cache` → фоновая задача → `load_cache(db)` = 4 полных SELECT без лимита
+ пересборка numpy-матриц эмбеддингов. Смета на 458 позиций → до 458 полных
перезагрузок прайса.

- Обновлять кеш точечно вместо полной перезагрузки.

## Фаза 4 — расхождение копеек в сводных итогах [x]

`excel_service._row_cost_dict` не округляет, итоги суммируют неокруглённое, а
Excel показывает 2 знака. Проверено: три строки по 33.4665 → пользователь видит
33.47×3 = 100.41, а итог 100.40.

NB: `xlsx_exporter` уже округляет построчно — там расхождения нет, править не надо.

### Что сделано по фазам

1. `app/utils/price_coercion.py` — `coerce_price` (положительное конечное число
   либо None) и `coerce_qty` (неотрицательное, мусор → 0). Понимает `"1 500,50"`,
   `"1500 руб."`; отбрасывает NaN/inf, отрицательное, ноль, bool и абсурдные
   порядки (> 1 млрд за единицу). Применено на входе от ИИ (`task_processor`,
   плюс `_ids_without_price` и `_cache_priced_item`) и в обоих генераторах Excel.
   Отбракованная цена пишется в примечание позиции — видно человеку.
2. Изменяющие операции каталога (6 обработчиков) → `get_manager_user`
   (`admin | head_of_sales`). Чтение и экспорт остались доступны всем. В UI
   кнопки правки/удаления/добавления скрыты за `isManager`, вместо них
   «только просмотр» — чтобы исполнитель не получал 403 без объяснения.
3. Полная перезагрузка кеша убрана из фоновой задачи генерации эмбеддинга.
   Запись и так добавляется в память точечно, поэтому поиск по точному
   совпадению работает сразу; вектор подхватывается при следующей штатной
   загрузке (старт процесса или изменение прайса админом).
4. `_row_cost_dict` округляет до копеек. Проверено: расхождение «сумма
   показанных строк» vs «показанный итог» стало 0.00 (было 0.01 на трёх строках).
5. Фоновые задачи держатся в модульном `_background_tasks` с
   `add_done_callback(discard)`.
6. `npm audit fix` (без мажоров): высоких уязвимостей **8 → 2**.

### Что НЕ сделано и почему

- **Vite 5 → 8** (три мажорные версии) не обновлял. Все три оставшиеся
  уязвимости Vite относятся к **dev-серверу** (`server.fs.deny` bypass,
  launch-editor, Optimized Deps), причём две — Windows-специфичные. Прод
  раздаёт статику через Nginx, dev-сервер там не запускается, разработка идёт
  на macOS. Прыжок через три мажора требует проверки всей сборки и, вероятно,
  обновления `@vitejs/plugin-react` и `vitest` — реальный риск сломать деплой
  ради уязвимости, которой на проде нет. Отдельная задача.
- **Замена `xlsx` (SheetJS) 0.18.5.** Фикса в npm нет: SheetJS публикует
  актуальные версии только на своём CDN, что меняет источник зависимости и
  требует доступа к нему при сборке в Docker. Библиотека используется лишь в
  тестовой вкладке «Онлайн редактор ТЕСТ»
  (`fortuneSheetConverter.ts`, `SpreadsheetTestEditor.tsx`). Отдельная задача:
  либо переход на CDN-версию, либо замена на `exceljs`.
- **`pip-audit`** не установлен — уязвимости Python-зависимостей не проверены.
  Это остаётся пробелом ревью.
