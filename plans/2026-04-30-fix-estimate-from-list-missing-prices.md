# Фикс: «Цена не определена» в задаче «Смета из перечня»

**Дата:** 2026-04-30  
**Статус:** завершён

---

## Проблема

При выполнении задачи «Смета из перечня» (ESTIMATE_FROM_LIST) большинство позиций
получало пометку «Цена не определена» вместо реальной цены.

### Три причины

1. **Несовпадение имён (главная).**  
   Сопоставление результатов Claude с исходными позициями делалось по точному
   совпадению строки имени: `claude_results.get(name)`. Claude регулярно возвращал
   имена в слегка изменённом виде (сокращения, другой порядок слов, иная
   транскрипция) — lookup давал `None`, позиция получала «Цена не определена».

2. **Claude пропускал позиции в батче.**  
   25 позиций + веб-поиск = огромная нагрузка. Claude мог вернуть `items` с меньшим
   числом элементов. Проверки полноты ответа не было.

3. **Падение чанка → весь батч теряется.**  
   При ошибке чанка после 3 retry: `continue` — все 25 позиций сразу получали
   «Цена не определена».

---

## Решение: индексная адресация (Вариант А)

Вместо сопоставления по имени — по числовому `id` (= позиция в исходном `items`).

### Фаза 1 — Реализация [x]

- [x] Обновить `PROMPT_ESTIMATE_FROM_LIST`: добавить поле `id` во входной JSON и
  обязательный возврат того же `id` в каждом элементе ответа.
- [x] Шаг 1: каждому `enriched` назначается `"_id": gidx` (global index в `items`).
  Вместо списков `matched`/`unmatched` — словари `matched_by_gidx`/`unmatched_by_gidx`,
  ключ = `gidx`.
- [x] Шаг 2: во вспомогательной функции `_call_claude_chunk` в JSON к Claude
  добавлено поле `"id": it["_id"]`. Словарь `claude_results` теперь `dict[int, dict]`,
  ключ = `int(item_id)`, не строка.
- [x] Шаг 2: после всех основных чанков — проверка пропущенных `id`.
  Пропущенные позиции повторно отправляются в Claude батчами по 5 штук.
  Оставшиеся после retry логируются как `warning`.
- [x] Шаг 3: финальная сборка через `enumerate(items)` + lookup по `gidx`.
  Ни одного строкового сравнения имён в критическом пути.

---

## Итог

Реализован целиком. Все три причины устранены:
- Причина 1 (несовпадение имён) — устранена: lookup по числовому id.
- Причина 2 (Claude пропустил позицию) — устранена: retry пропущенных id батчами по 5.
- Причина 3 (падение чанка) — частично улучшено: каждый чанк обрабатывается
  отдельно, пропущенные на retry-проходе, лог `warning` с именами позиций.
