# Исправление парсинга сметы и улучшения редактора

**Дата:** 2026-05-22
**Статус:** в работе

## Проблемы

### 1. Неверная детекция колонок (estimate_parser.py)
Excel-файл в формате «Гранд-смета» имеет 4 ценовые колонки:
- Col E: "Цена за ед. изм. Работы" — единичная цена работы (НЕ детектировалась)
- Col F: "Стоимость работ руб." — итоговая стоимость работ (ошибочно читалась как price_work)
- Col G: "Цена за ед. изм. Материала" — единичная цена материала (детектировалась верно)
- Col H: "Стоимость Материала руб." — итоговая стоимость материала (НЕ детектировалась)

Следствия:
- price_work = итого (col F), cost = qty × итого — в 4× больше реального
- Материальные строки с ценой только в col H → type="work" через fallback

Причина: "работа" ≠ "работы" (падеж), col E не совпадала ни с одним ключевым словом.

### 2. Нельзя менять тип строки в редакторе
TypeBadgeCell только отображал тип, без возможности редактирования.

### 3. Нельзя переставлять строки
Нет механизма изменения порядка строк в редакторе.

## Решение

### Фаза 1: Парсер [ ]
- Добавить `"работ"` в `_PRICE_WORK_KW` — col E детектируется первой (unit price)
- Добавить `price_material_total` slot в `_detect_columns` — col H детектируется как fallback
- При выводе типа: если `price_material=None` но `price_material_total>0` → type="material"
- Восстановление единичной цены: `price_material = total / qty`

### Фаза 2: Редактор [ ]
- `TypeCell`: кликабельный бейдж → select dropdown (work/material/section)
- `MoveCell`: кнопки ▲/▼ в отдельной колонке
- Новые обработчики в GridContext: `onTypeChange`, `onMoveRow`
