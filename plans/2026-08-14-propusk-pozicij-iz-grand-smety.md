# Пропуск позиций при формировании перечня из гранд-сметы

## Проблема

В перечне, собранном из ЛСР (ГРАНД-Смета), не хватает позиций. На примере
раздела «Оборудование» пожарной сигнализации:

- позиция №3 «Контроллер радиоканальных и проводных устройств Панель-2-ПРО (S3)
  исп.Л» — шт, 1, 35 182,38 руб. — в перечень не попала совсем;
- работа №4 «Извещатель ПС автоматический…» в перечне есть, а самих извещателей
  (отдельные позиции оборудования ниже) — нет;
- и так почти по всему разделу.

Неполный перечень = неполная смета = финансовые потери на тендере.

## Причина (доказана)

`file_parser._is_total_row` отбрасывает строку, если в наименовании нашлось хоть
что-то из `_TOTAL_KEYWORDS`. Аббревиатуры в этом наборе записаны без границы
слова слева: `сп\b`, `нр\b`, `зп\b`, `фот\b`. Поиск идёт `re.search` по всей
строке, поэтому `сп\b` совпадает внутри слова **«исп.»** — сокращения
«исполнение», которое стоит в наименовании почти любого оборудования ОПС,
электрики и автоматики:

```
«…Панель-2-ПРО (S3) исп.Л»          → сп\b совпало → строка выброшена
«Извещатель … ИП 212-141 исп.01»    → сп\b совпало → строка выброшена
«Блок резервного питания РИП-12 исп.01» → выброшена
«Труба гофрированная ПВХ, Респ. Татарстан» → выброшена («Респ.»)
```

Отбрасывание происходит **до** отправки чанка в Claude: ИИ этих строк не видит
вовсе, поэтому в логах и в ответе модели пропуск ничем не проявляется.

Ресурсы внутри расценки (канифоль, дюбели, припои) при этом в перечне остаются —
у них своя цена, их держит страховка `_has_own_cost`. Отсюда и картина «мелочь
из расценки есть, а само оборудование пропало».

## Решение

Два слоя — фильтр и страховка, плюс отдельно видимость потерь на стороне ИИ.

1. **Служебное слово — это целое слово.** `_TOTAL_KEYWORDS` получает границу
   слова с обеих сторон для всех аббревиатур и слов-итогов.
2. **Позиция сметы итоговой строкой не бывает.** Строка, у которой есть номер в
   «№ п/п», единица измерения и объём, не отбрасывается ни как итоговая, ни как
   мусорная — как бы она ни называлась (наименование может содержать и «СП
   484.1311500», и «в том числе»).
3. **Номер позиции нормализуется.** В «№ п/п» ГРАНД-Смета печатает под номером
   пометку вида «О» (оборудование) — в ячейке оказывается `"3\nО"`. В колонку
   «№ в исходной смете» едет номер `3`.
4. **Страховка-предупреждение.** `attach_source_numbers` возвращает номера
   позиций исходной сметы, для которых ИИ не вернул ни одной строки. Задача
   пишет в ход выполнения `⚠ ИИ не вернул N позиций исходной сметы: №…` — и на
   перечне, и на проверке полноты. Автоматически ничего не дописывается: молча
   восстановленная позиция с чужим наименованием хуже видимого предупреждения
   (решение пользователя 14.08.2026).

## Фазы

### [x] Фаза 1. Фильтр итоговых строк работает по целым словам

- `_TOTAL_KEYWORDS` переписан с `\b` с обеих сторон.
- Тест с точными наименованиями: «исп.Л», «исп.01», «Респ.», «дисп.» остаются;
  «Итого прямые затраты», «Всего по позиции», «НР …», «СП …», «ФОТ», «НДС 20%»
  по-прежнему отбрасываются.

### [x] Фаза 2. Пронумерованная позиция не отбрасывается никогда

- В `_parse_grand_sheet` единица, объём и номер считаются до отбраковки;
  строка-позиция (номер + единица + объём) переживает `_is_total_row` и
  `_is_trash_row`.
- Проценты (НР/СП строкой с `%`) и нормо-часы фильтруются как раньше.
- Номер вида `"3\nО"` нормализуется в `3`.

### [x] Фаза 3. Потери на стороне ИИ видны

- `attach_source_numbers` возвращает список непривязанных номеров.
- `_handle_list_from_grand_xlsx` и `_handle_check_completeness` копят их по
  чанкам (переживает resume через `progress_data`) и в конце пишут
  предупреждение в ход выполнения.
