# Стадии каждой сметы прямо на странице проекта

**Дата:** 2026-08-04
**Файлы:** `frontend/src/components/SmetaList.tsx`, `frontend/src/components/pipeline/PipelineStepper.tsx`, `frontend/src/pages/ProjectCardPage.tsx`

## Проблема

На странице проекта список смет показывает только текущий этап («Полнота») и состояние («Готово»).
Чтобы понять, что уже сделано и что осталось, менеджер обязан открыть карточку сметы.
При нескольких сметах в проекте это N переходов туда-обратно, чтобы просто увидеть картину.

## Что делаем

В строке сметы показываем ту же дорожку из четырёх стадий, что и внутри карточки,
а под ней — те же свёрнутые секции с файлами задач.

Решения, согласованные с пользователем:

1. Дорожка **заменяет** колонки «Этап» и «Состояние» — они дублируют её.
2. Узлы дорожки **не кликабельны**: это индикатор, а не навигация.
3. Под дорожкой — свёрнутые секции стадий с файлами (`CardStageContent`), как внутри сметы.
4. Переход в смету остаётся: по названию сметы и по стрелке рядом с ним
   (клик по всей строке убираем — иначе он перехватывал бы клики по аккордеонам и кнопкам файлов).

## Что НЕ делаем

- Не трогаем канбан и страницу сметы — состояние узлов считает та же `computeNodeState`.
- Не заводим второй источник правды о стадиях: `PIPELINE_STAGES`, `computeNodeState`, `computeGuard` остаются едиными.
- Не меняем колонку «Сумма» (сейчас всегда «—») — это отдельная задача.

## Критерии приёмки

- [x] В строке сметы видны все четыре стадии с их состояниями (готово / идёт / ошибка / ожидает / заблокирована).
- [x] Колонок «Этап» и «Состояние» в таблице больше нет.
- [x] Узлы дорожки не кликабельны и не навигируют.
- [x] Под дорожкой — свёрнутые секции стадий с файлами, как внутри карточки сметы.
- [x] Клик по названию сметы открывает карточку сметы.
- [x] Клик по аккордеону/кнопке файла не уводит со страницы проекта.
- [x] Состояние узлов совпадает со степпером внутри карточки (одна функция на оба места).
