## Challenge Log

**Проблема.** Целевые суммы по разделам живут вне сервиса, отклонение считается
руками после каждой правки.

**Выбранное решение.** Цель — атрибут раздела сводной (`target_works`,
`target_materials` в `summary_estimates.sections[i]`), база целей и цель на
объект — настройки бланка (`overrides.target_basis`,
`overrides.target_total_for_customer`). Отклонение — производная величина,
считается в двух зеркальных расчётах (экран и файл) и нигде не хранится.

**Альтернативы:**

1. **Отдельная таблица `optimization_targets`** — отклонена: миграция, второй
   писатель для куска бланка, ручная синхронизация состава разделов. Цель живёт
   ровно столько, сколько живёт раздел, — значит, ей место в разделе.
2. **Словарь целей в `overrides` (`{card_id: {...}}`)** — отклонена: при
   удалении раздела цель осталась бы сиротой, а `SummaryOverrides` — строгая
   pydantic-модель, произвольные ключи она режет.
3. **Хранить и отклонение тоже** — отклонена: сохранённое отклонение устаревает
   в момент правки строки и начинает врать. Отклонение — арифметика над
   числами, которые уже есть.

**Почему выбранное лучше.** Ноль миграций для самих целей, цель едет тем же
путём, что и ставка налога раздела (проверенный путь), переживает смену версии
и исчезает вместе с разделом. Единственная новая колонка БД —
`projects.summary_target_total` — витрина для списка проектов, ровно по образцу
существующего `projects.summary_total`.

## Правила, которые нельзя нарушить

1. **Цель не задана ≠ цель 0.** `null` — прочерк и никакой подсветки; `0` —
   заданная цель, отклонение равно факту, процент не считается.
2. **Экран и файл считают по одной формуле** (правило проекта №4). Числа
   отклонений закреплены тестом с точными значениями и на клиенте, и на сервере.
3. **ИТОГО целей считает только разделы с целью.** Иначе факт всех разделов
   сравнивался бы с целью половины — цифра врала бы молча.
4. **Переключение базы не пересчитывает цели.** Цель — ввод человека; менять
   его число автоматически нельзя. База подписана в бланке.
5. **Нет целей — файл как раньше.** Ни колонок, ни строк цели в xlsx.

## Проблемы и решения

| # | Проблема | Решение |
|---|---|---|
| 1 | Несохранённая цель терялась бы после «Применить» в разделе | `refreshSections` мержит локальные `target_*`, как уже мержит `tax_pct_*` |
| 2 | Смена версии раздела могла бы стереть цель | `set_sections` кладёт `{**kept, **fresh}` — цель в `kept`; закрыть тестом |
| 3 | `SummaryOverrides` режет незнакомые ключи | Объявить `target_basis` и `target_total_for_customer` полями схемы; тест на сохранность через PUT |
| 4 | Деление на ноль в проценте отклонения | Процент только при цели > 0, иначе `null` |
| 5 | Список проектов не может читать JSON сводной (GROUP BY по json невозможен, тесты на SQLite) | Витрина `projects.summary_target_total`, пишется там же, где `summary_total` |
| 6 | Отрицательная цель | Ввод не принимает значения < 0 (`min=0`), сервер трактует отрицательную как отсутствие цели |
| 7 | Строки вместо чисел в JSON (`"1000"`) | Приведение через `_num` / `Number` на обеих сторонах |
