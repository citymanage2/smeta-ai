# Рефакторинг задачи «Перечень из Гранд-сметы»

## Контекст

Текущая реализация `LIST_FROM_GRAND` отправляет весь Excel-файл целиком в Claude одним запросом.
На файлах ~1500 строк задача зависает на 8+ минут без результата. Причины:
- Слишком много токенов на входе (все колонки всех строк)
- Слишком большой JSON на выходе
- Нет защиты от сбоя на полпути — промежуточные результаты теряются

## Решение

Двухшаговая архитектура с чанкингом на Шаге 1.

### Шаг 1 — `LIST_FROM_GRAND` (рефакторинг)

Задача: извлечь перечень работ и материалов из гранд-сметы.

- Excel предварительно парсится: оставляем только нужные колонки (наименование, ед. изм., количество), убираем итоговые строки и пустые
- Отфильтрованные строки делятся на чанки по 250 строк
- Каждый чанк обрабатывается отдельным запросом в Claude
- После каждого чанка накопленные items сохраняются в `task.progress_data`
- После всех чанков — генерация итогового Excel

### Поведение при сбое (утверждено)

Если сервис упал на чанке N из M:
1. В `progress_data` уже сохранены items чанков 1..N-1
2. Сохраняется частичный Excel из накопленных items — слот `partial_N` (например, `partial_1`, `partial_2`...), чтобы поддерживать несколько падений подряд
3. Задача переходит в статус `failed` с сообщением: «Обработано N из M частей. Частичный результат доступен для скачивания.»
4. Пользователь видит: «3 из 6 частей обработано» + кнопку «Скачать частичный результат» + кнопку «Продолжить»
5. По кнопке «Продолжить» — задача возобновляется с чанка N, items из `progress_data` берутся как есть, токены на уже обработанное не тратятся
6. После завершения — сохраняется финальный Excel (слот `result`), все частичные остаются как история

### Проверка полноты (утверждено)

- Кнопка «Проверить полноту перечня» появляется на той же странице задачи после успешного завершения `LIST_FROM_GRAND`
- По нажатию — проверка запускается и её прогресс отображается **в том же окне**, никуда не переходим
- В бэкенде это отдельная задача `CHECK_LIST_COMPLETENESS`, но фронтенд показывает её встроенно в страницу исходной задачи

### Шаг 2 — `CHECK_LIST_COMPLETENESS` (новая задача)

Задача: проверить полноту материалов по ГЭСН для каждой работы.

- Запускается вручную пользователем после получения результата Шага 1
- На вход — компактный перечень из `progress_data` source-задачи (не исходный Excel)
- Если items > 300 — также разбивается на чанки
- Результат — дополненный Excel с обоснованиями в поле notes и changes_summary

}

ВАЖНО: отвечай ТОЛЬКО валидным JSON. Никакого текста до { или после }.

## Фазы реализации

### Фаза 1 — Умный парсинг Excel для гранд-сметы [x]

Файл: `backend/app/utils/file_parser.py`

- Написать функцию `parse_xlsx_grand(data: bytes) -> list[dict]`
  - Читает Excel через openpyxl
  - Автоматически определяет колонки с наименованием, ед. изм., количеством (по заголовкам или эвристике)
  - Пропускает строки: полностью пустые, итоговые (содержат слова «итого», «всего», «сумма»), чисто числовые
  - Возвращает список словарей `{name, unit, quantity}`
- Написать функцию `chunk_rows(rows: list[dict], chunk_size: int = 250) -> list[list[dict]]`
  - Делит список на части по `chunk_size` строк

### Фаза 2 — Чанкинг в `_handle_list_from_grand` + кнопка «Продолжить» [x]

Файлы: `backend/app/services/task_processor.py`, `backend/app/routers/tasks.py`

**Реализовано:**

- Промпт заменён на новый (Шаг 1): извлекаем позиции как есть, без добавлений по нормативам
- `save_result` принимает необязательный параметр `slot: str = "result"` — теперь можно сохранять `partial_1`, `partial_2` и т.д.
- Добавлен метод `_save_progress_data(data: dict)` — атомарно записывает прогресс в `task.progress_data` после каждого чанка
- `_handle_list_from_grand` полностью переписан:
  1. Читает `progress_data` — если `chunks_done > 0`, это resume (пропускает уже обработанные чанки)
  2. Ищет Excel в `task.input_file_data` по MIME-типу, декодирует из base64
  3. Парсит через `parse_xlsx_grand`, делит на чанки через `chunk_rows`
  4. Для каждого чанка: `rows_to_text` → Claude → merge items → `_save_progress_data`
  5. При падении на чанке N: сохраняет частичный Excel в слот `partial_{partial_count+1}`, обновляет `partial_count` в `progress_data`, пробрасывает исключение
  6. После всех чанков — финальный Excel в слот `result`
- **Исправлен баг**: `process()` теперь вызывает `update_status("completed")` после успешного завершения (раньше задача зависала в статусе `"processing"` навсегда)
- **Исправлен синтаксис Python 3.9**: `int | None` → `Optional[int]`, `list[dict]` → `"list[dict]"` в `file_parser.py`
- Добавлен `progress_data: Optional[dict]` в `TaskStatusResponse` — фронтенд теперь получает прогресс из статуса задачи

**Endpoint `POST /tasks/{task_id}/resume` (`routers/tasks.py`):**
- Проверяет: задача в статусе `failed`, тип `LIST_FROM_GRAND`, в `progress_data` есть `chunks_done`
- Сбрасывает статус на `pending`, очищает `error_message`
- Запускает обработку в background (та же `_run_task_in_background`)
- `_handle_list_from_grand` сам обнаружит `chunks_done > 0` и продолжит с места остановки
- Возвращает `task_id`

> Примечание: endpoint resume реализован здесь (Фаза 2) и не нужен в Фазе 4.

### Фаза 3 — Новый тип задачи `CHECK_LIST_COMPLETENESS` [x]

Файлы: `backend/app/services/task_processor.py`, `backend/app/constants.py`, `backend/app/services/excel_service.py`

**Реализовано:**

- `constants.py`:
  - Добавлен `"CHECK_LIST_COMPLETENESS"` в `TASK_TYPE_LABELS`
  - `LIST_FROM_GRAND` **убран** из `ESTIMATE_TASK_TYPES` — система больше не пытается извлечь итоговую стоимость из результата перечня. `CHECK_LIST_COMPLETENESS` туда тоже не добавлен. Оба типа задач не являются сметами — итоговой суммы в них нет.

- `excel_service.py` — `generate_list`:
  - Добавлена колонка «Примечание» (6-я) прямо в лист «Перечень» рядом с каждой строкой
  - Для задачи `LIST_FROM_GRAND` поле `notes` всегда пустое — колонка есть, но пустая
  - Для задачи `CHECK_LIST_COMPLETENESS` колонка содержит обоснование от Claude (ссылку на ГЭСН, пояснение корректировки и т.д.)

- `task_processor.py`:
  - Добавлен `PROMPT_CHECK_COMPLETENESS` (промпт Шага 2, утверждённый)
  - Добавлена функция `_chunk_by_work_boundaries(items, max_chunk_size=200)`:
    - Режет перечень на части не более 200 позиций
    - **Граница всегда на «Работе»** — все материалы, относящиеся к одной работе, никогда не разрываются между чанками
    - Используется только если items > 300, иначе один запрос
  - Написан `_handle_check_completeness(task)`:
    1. Читает `source_task_id` из `task.user_prompt` (plain UUID-строка)
    2. Загружает source-задачу из БД, проверяет что она типа `LIST_FROM_GRAND`
    3. Берёт `items` из `source_task.progress_data["items"]`
    4. Если items ≤ 300 — один запрос; если > 300 — `_chunk_by_work_boundaries`
    5. Для каждого чанка: JSON → Claude → накапливает `items` и `changes_summary`
    6. `changes_summary` от всех чанков объединяется через `\n\n`
    7. Генерирует Excel через `generate_list(all_items, changes_summary=...)` и сохраняет в слот `result`
  - Добавлен роутинг в `process()`: `CHECK_LIST_COMPLETENESS` → `_handle_check_completeness`

### Фаза 4 — Endpoint для запуска проверки полноты [x]

Файл: `backend/app/routers/tasks.py`

- `POST /tasks/check-completeness`
  - Принимает JSON body: `{ "source_task_id": "uuid" }`
  - Проверяет что source-задача существует, тип `LIST_FROM_GRAND`, статус `completed`
  - Создаёт задачу `CHECK_LIST_COMPLETENESS`, записывает `source_task_id` в `user_prompt`
  - Наследует `project_id` из source-задачи
  - Запускает в background
  - Возвращает `task_id` новой задачи

> Примечание: endpoint resume реализован в Фазе 2.

### Фаза 5 — Frontend [x]

Файлы: `frontend/src/pages/TaskStatus.tsx`, `frontend/src/types.ts`, `frontend/src/api/tasks.ts`

- `types.ts`: добавить `CHECK_LIST_COMPLETENESS` в `TaskType` и `TASK_TYPE_LABELS`
- `api/tasks.ts`:
  - Добавить `checkCompleteness(sourceTaskId: string)` → POST /tasks/check-completeness
  - Добавить `resumeTask(taskId: string)` → POST /tasks/{task_id}/resume

- `TaskStatusResponse` в `api/tasks.ts` — добавить поле `progress_data?: Record<string, unknown>`

- `TaskStatus.tsx`:
  - **При статусе `failed` + тип `LIST_FROM_GRAND` + есть `chunks_done` в `progress_data`:**
    - Показать сообщение: «Обработано N из M частей» (N = `chunks_done`, M = `total_chunks` из `progress_data`)
    - Кнопка «Скачать частичный результат» (если среди результатов задачи есть слот `partial_*`)
    - Кнопка «Продолжить» → вызвать `resumeTask(taskId)`, задача возобновляется
  - **При статусе `completed` + тип `LIST_FROM_GRAND`:**
    - Показать карточку «Хотите проверить полноту материалов по ГЭСН?»
    - Кнопка «Да, проверить» → `checkCompleteness(taskId)` → создаётся задача `CHECK_LIST_COMPLETENESS`
    - Прогресс и результат проверки отображаются **прямо на этой же странице** (не переходим никуда)
    - Для этого: после `checkCompleteness` сохраняем `checkTaskId` в локальный state, опрашиваем его статус и рендерим ниже на странице
