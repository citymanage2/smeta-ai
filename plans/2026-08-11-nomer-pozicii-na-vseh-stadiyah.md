# Номер позиции исходной сметы — на всех стадиях

Дата: 2026-08-11
Тип: расширение функции (размер L)
Предшественник: `plans/2026-08-06-nomer-pozicii-iz-ishodnoj-smety.md`

## 1. Задача

Колонка «№ в исходной смете» есть только в перечне. Нужна на всех стадиях:
полнота, смета, версии оптимизации, разделы сводной — и в редакторе, и в
скачиваемом файле.

Зачем: сверка со сметой заказчика нужна не один раз на перечне, а на каждом
шаге — особенно когда защищаешь смету перед заказчиком и надо мгновенно
показать, откуда взялась строка.

## 2. Исследование

### Пять типов документов — два формата строк

| Документ | Формат строки | Где колонка |
|---|---|---|
| Перечень | `generic` (`cells`) | **готово** |
| Полнота | `generic` (`cells`) | нужен номер в позициях |
| Смета | `estimate` (типизированная) | нужно поле + колонка |
| Версии оптимизации | `estimate` | наследует от сметы |
| Разделы сводной | `estimate` | наследует от сметы |

Значит работы ровно две: (а) донести номер до позиций полноты, (б) провести
поле через типизированную строку сметы. Оптимизация и сводная получают его
даром: версия оптимизации строится из строк сметы, а `_build_sections_snapshot`
копирует строки версии как есть.

### Как номер доедет до полноты

`_handle_check_completeness` берёт позиции перечня (`source_no` в них уже есть),
режет на чанки и отдаёт ИИ **без** номера (`_without_source_no` — решение
предыдущего плана). ИИ переписывает чанк целиком и возвращает позиции.

Номер возвращается тем же `attach_source_numbers`, что и на перечне: позиции
ответа сопоставляются с позициями того же чанка по наименованию. Функция уже
универсальна — читает `name` и `source_no`, а откуда пришла строка, ей неважно.

Материалы, дописанные ИИ, и комплекты по нормам расхода номера не получают: в
исходной смете этих строк нет. Пустая ячейка — не потеря, а факт.

### Как номер доедет до сметы

`estimate_rows.PASSTHROUGH_FIELDS` — готовый механизм проброса полей позиции
через строку документа (там уже едут `price_list_name`, `sources`, `notes`,
`sheet`). Номер добавляется туда же и дальше едет сам: `items_to_rows` →
`EstimateVersion.rows` → редактор → `rows_to_items` → xlsx.

Единственная ручная точка — `_run_estimate_step3`: он собирает итоговые позиции
**заново** из перечисленных полей в трёх ветках (вычет, цена от ИИ, цены нет).
Что не перечислено — теряется. Ветка `matched` копирует позицию целиком и номер
сохраняет сама.

### Проверено на регрессии заранее

| Что могло сломаться | Проверка |
|---|---|
| `extract_total_cost` (итог задачи из файла) | берёт **последнее** число в строке «итого/всего», подпись остаётся в колонке 1 → сдвиг безопасен |
| `xlsx_optimizer._map_columns` (разбор сметы для оптимизации) | колонки ищутся по названиям; «№ в исходной смете» не попадает ни под один ключ (`наименование`, `тип`, `ед`+`изм`, `кол`, `цена`, `стоим`, `итого`, `ндс`) |
| `xlsx_cost_parser._parse_list_worksheet` (загруженный перечень → смета) | колонки по шапке; fallback на фиксированную раскладку срабатывает, только если «Наименование» не найдено |
| Старые сметы без номера | поле необязательное, колонка условная — файл и редактор остаются прежними |

Миграция БД не нужна: `EstimateVersion.rows` — JSON-колонка, схема строки не
отражена в DDL.

## 3. Границы

**В границах:** полнота, смета, версии оптимизации, разделы сводной — редактор
и скачиваемый файл.

**Вне границ:**
- **Файл оптимизации** (`generate_optimized_xlsx`) — он дописывает колонки в
  *исходный файл заказчика*, где нумерация и так своя. Документ оптимизации в
  редакторе колонку получает.
- **Бланк сводной сметы** (`generate_summary_xlsx`) — это агрегат по разделам с
  фиксированными строками (коэффициент, непредвиденные, прибыль, НДС), а не
  перечень позиций. Разделы сводной в редакторе колонку получают.
- **Перечень из PDF-скана и из проекта** — номера нет в источнике.

## 4. Критерии приёмки

1. Полнота: у позиции, пришедшей из перечня, номер сохранён; у дописанной ИИ и
   у комплекта по нормам — пусто.
2. Смета: колонка «№ в исходной смете» первая, до сквозного «№», и в файле, и в
   редакторе.
3. Номер переживает правку строки сметы в редакторе и пересборку файла.
4. Версия оптимизации и раздел сводной наследуют номер от строк сметы.
5. Колонка появляется только при наличии номеров: смета из файла заказчика без
   них выглядит ровно как раньше.
6. Итог задачи (`task.cost`) и «ВСЕГО ПО СМЕТЕ» из файла не сдвигаются.
7. Смета, посчитанная до этой правки, открывается и скачивается без ошибок.
