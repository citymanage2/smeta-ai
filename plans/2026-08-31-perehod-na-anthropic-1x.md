# Переход на anthropic 1.x (httpx2)

## Зачем

31.08.2026 задачи начали падать на первом же обращении к ИИ:

```
TypeError: Invalid `http_client` argument;
Expected an instance of `httpx2.AsyncClient` but got <class 'httpx.AsyncClient'>
```

Причина: вышел мажор **anthropic 1.x** (на PyPI 1.2.0), у которого HTTP-слой
переехал с `httpx` на его поддерживаемый форк `httpx2` (`httpx2<3,>=2.0.0`).
В `backend/requirements.txt` стояло `anthropic>=0.55.0` — без верхней границы,
поэтому очередная пересборка образа поставила 1.2.0. Наш общий HTTP-клиент
(`claude_service._http_client`) создавался из старого `httpx`, и SDK отклонял
его при конструировании клиента. Пакеты называются по-разному (`httpx` и
`httpx2`), поэтому pip не увидел конфликта и поставил оба.

Локально ошибки не было: там осталась anthropic 0.85.0.

## Решение

Переезжаем на 1.x целиком, а не откатываемся пином на 0.x: 0.x больше не
развивается, а разница для нашего кода — механическая (см. фазы). Заодно
закрываем исходную дыру: **верхняя граница мажора в requirements**, чтобы
следующий мажор SDK не приезжал на прод сам.

Что даёт 1.x нам конкретно: те же методы и те же типы, но `httpx2` вместо
неподдерживаемого `httpx`, куда идут security-фиксы.

## Что НЕ меняется

- Модель, промпты, параметры запроса (`thinking`, `output_config.effort`,
  web search, кеширование) — не трогаем: это миграция SDK, а не модели.
- Обход геоблока: `_ProxiedAsyncAnthropic._prepare_url` в 1.x остался с той же
  сигнатурой (проверено в исходниках 1.2.0), меняется только тип `httpx.URL` →
  `httpx2.URL`.
- `httpx` остаётся в зависимостях: на нём держатся тесты FastAPI
  (`AsyncClient` + `ASGITransport` в `tests/conftest.py`) — это наш собственный
  HTTP-клиент к приложению, к SDK он отношения не имеет.

## Фазы

### [x] Фаза 1. Зависимости

- `backend/requirements.txt`: `anthropic>=1.2.0,<2` (была `>=0.55.0`).
- Туда же `httpx2>=2.0,<3` — импортируем напрямую, значит объявляем явно
  (транзитивно он всё равно приезжает с SDK).
- `httpx==0.28.0` остаётся — для тестов приложения.
- Python: 1.x требует ≥3.10, у нас `python:3.12-slim` — менять нечего.

### [x] Фаза 2. Код сервиса

`backend/app/services/claude_service.py` — единственный файл приложения, где
живёт SDK:

- `import httpx` → `import httpx2`;
- общий `_http_client` и его `Timeout` — из `httpx2` (это и была причина сбоя);
- `_prepare_url` — аннотация и разбор URL на `httpx2.URL`;
- сетевые исключения в ретраях (`RemoteProtocolError`, `ReadTimeout`) — из
  `httpx2`: их поднимает SDK, а он теперь работает на httpx2, и старые классы
  больше не ловятся.

### [x] Фаза 3. Тесты

Тесты, которые собирают ответы/ошибки SDK вручную, переводятся на `httpx2`
(иначе они проверяют объекты, которых SDK уже не отдаёт):

- `test_batch_results_proxy.py` — `MockTransport`, `Request`, `Response`, `URL`;
- `test_balance_pause.py`, `test_balance_pause_via_proxy.py`,
  `test_balance_pause_hardening.py`, `test_rate_limit_retry.py`,
  `test_api_rate_limit_counter.py`, `test_admin_api_health.py` — `httpx.Response`
  для `APIStatusError` / `RateLimitError`.

`tests/conftest.py` не трогаем — там `httpx` к приложению, а не к SDK.

### [x] Фаза 4. Проверка

- Полный прогон backend-тестов на Python 3.12+ с реально установленными
  anthropic 1.2.0 и httpx2 (в 3.9 они не ставятся — гоняем в venv 3.13).
- Отдельно — тест обхода геоблока для batch: он проверяет фактически исходящие
  запросы, то есть ровно то, что мог сломать переезд на другой HTTP-слой.

## Итог

Реализован целиком. Задачи снова доходят до ИИ, а мажорный пин закрывает
повторение той же аварии.

Осталось за скобками (отдельным решением пользователя):
`tg_bot/requirements.txt` — там тот же незакрытый `anthropic>=0.55.0`. Бот
клиент создаёт без `http_client`, поэтому именно эта авария ему не грозит, но
верхнюю границу мажора стоит поставить и там.
