# Общее правило для задач и подзадач

Этот документ описывает архитектуру, которую нужно воспроизводить при добавлении любого нового типа задачи или подзадачи.

---

## 1. Классификация задач

| Класс | Примеры | Особенности |
|---|---|---|
| **Основная задача** | LIST_FROM_GRAND, LIST_FROM_PROJECT | Создаётся через `POST /tasks`, принимает файлы |
| **Подзадача** | CHECK_LIST_COMPLETENESS, CHECK_PROJECT_COMPLETENESS | Создаётся кнопкой из карточки основной задачи, связана через `user_prompt = source_task_id` |

Подзадача всегда запускается только после того, как основная задача завершена (`status = completed`). Она читает данные основной задачи через `source_task.progress_data`.

---

## 2. Модель данных (таблица `tasks`)

```
id               UUID, PK
task_type        STRING  — тип задачи из TASK_TYPE_LABELS (constants.py)
status           STRING  — pending | processing | completed | failed | cancelled
user_prompt      TEXT    — для подзадачи: source_task_id; для основной: доп. требования
input_file_data  JSON[]  — список файлов: {name, mime_type, size_bytes, content_b64}
progress_message STRING  — текущее сообщение прогресса (показывается в UI)
progress_data    JSONB   — чекпоинт: {chunks_done, total_chunks, items, summaries, ...}
error_message    TEXT    — сообщение об ошибке при status=failed
estimation_status STRING — not_applicable | unestimated | estimated | optimized
project_id       UUID FK — привязка к проекту
name             STRING  — человекочитаемое имя задачи (опционально)
created_at / updated_at
```

Результаты хранятся в отдельной таблице `task_results`:
```
task_id   FK → tasks
file_name, mime_type, file_data (bytes)
slot      — "result" (финал), "estimate", "optimized", "partial_N" (промежуточный)
```

---

## 3. Цикл жизни задачи

```
[создание] → pending
             ↓ (background task запущен)
          processing
             ↓ (успех)        ↓ (ошибка)     ↓ (отмена)
          completed          failed          cancelled
                              ↓ (resume)      ↓ (resume)
                           pending →→→→→→→→→→→
```

- **pending → processing**: переход в начале `TaskProcessor.process()`
- **processing → completed**: в конце `process()` при успехе
- **processing → failed**: при любом не пойманном исключении в `process()`
- **processing → cancelled**: через `POST /tasks/{id}/cancel` (пишет в БД, фоновый процесс проверяет при следующем `_check_cancelled()`)
- **failed/cancelled → pending**: через `POST /tasks/{id}/resume` (только для RESUMABLE_TYPES)

## 4. Бэкенд: шаблон обработчика

### 4.1 Простая задача (один вызов Claude, без чанков)

```python
async def _handle_my_task(self, task: Task) -> None:
    await self.update_progress("Анализ файлов...")
    
    messages, image_blocks = self._build_messages_with_files(task, PROMPT_MY_TASK)
    data = await self._call_claude_json(
        messages,
        system_prompt=SYSTEM_BASE,
        image_data=image_blocks or None,
    )
    
    items = data.get("items", [])
    await self._save_progress_data({"items": items})
    await self.update_progress(f"Найдено {len(items)} позиций. Формирование Excel...")
    
    excel_data = generate_list(items)
    await self.save_result("Результат.xlsx", _XLSX_MIME, excel_data)
```

### 4.2 Тяжёлая задача (чанки + resume + отмена)

```python
async def _handle_heavy_task(self, task: Task) -> None:
    # --- Загрузка чекпоинта ---
    progress_data = task.progress_data or {}
    start_chunk = progress_data.get("chunks_done", 0)
    accumulated_items: list = list(progress_data.get("items", []))

    # --- Подготовка данных и чанков ---
    items = ...  # распарсить входные данные
    chunks = _chunk_by_work_boundaries(items, max_chunk_size=25)
    total_chunks = len(chunks)

    if start_chunk > 0:
        await self.update_progress(f"Возобновление с части {start_chunk + 1} из {total_chunks}...")
    else:
        await self.update_progress(f"Файл разбит на {total_chunks} частей...")

    for i in range(start_chunk, total_chunks):
        # --- Проверка отмены ДО начала чанка ---
        try:
            await self._check_cancelled()
        except TaskCancelledError:
            if accumulated_items:
                await self._save_partial(accumulated_items, i, total_chunks)
            raise

        await self.update_progress(f"Обработка части {i + 1} из {total_chunks}...")

        messages = [...]

        # --- Вызов Claude с поддержкой прерывания ---
        try:
            data = await self._interruptible_claude_json(
                messages,
                system_prompt=SYSTEM_BASE,
                processing_timeout=1200.0,
            )
        except TaskCancelledError:
            # Кнопка «Стоп» была нажата ПОКА шёл вызов Claude
            if accumulated_items:
                await self._save_partial(accumulated_items, i, total_chunks)
            raise
        except Exception:
            if accumulated_items:
                await self._save_partial(accumulated_items, i, total_chunks)
            raise

        # --- Накапливаем и сохраняем чекпоинт ---
        accumulated_items.extend(data.get("items", []))
        await self._save_progress_data({
            "chunks_done": i + 1,
            "total_chunks": total_chunks,
            "items": accumulated_items,
        })

    # --- Финальный результат ---
    excel_data = generate_list(accumulated_items)
    await self.save_result("Результат.xlsx", _XLSX_MIME, excel_data)
```

### 4.3 Вспомогательный метод `_save_partial`

Для тяжёлых задач удобно выделить отдельный метод:

```python
async def _save_partial(self, items: list, chunk_idx: int, total: int) -> None:
    excel_data = generate_list(items)
    await self.save_result(
        f"Частичный_результат_{chunk_idx}_из_{total}.xlsx",
        _XLSX_MIME,
        excel_data,
        slot=f"partial_{chunk_idx}",
    )
    await self.update_progress(
        f"Остановлено на части {chunk_idx + 1} из {total}. Частичный результат сохранён."
    )
```

## 5. Чанкинг: функция `_chunk_by_work_boundaries`

Делит список позиций на чанки, всегда начиная новый чанк на строке типа `"Работа"`.  
Это гарантирует, что материалы к одной работе никогда не разрываются между чанками.

```python
chunks = _chunk_by_work_boundaries(items, max_chunk_size=25)
```

- `max_chunk_size=25` — оптимальный размер для 1200-секундного таймаута
- Чанк может быть длиннее, если между работами больше 25 строк материалов — это нормально

---

## 6. Ключевые методы `TaskProcessor`

| Метод | Назначение |
|---|---|
| `update_status(status, error)` | Меняет `task.status` в БД |
| `update_progress(message)` | Обновляет `task.progress_message` (показывается в UI каждые 3 сек) |
| `_save_progress_data(data)` | Записывает чекпоинт в `task.progress_data` |
| `save_result(name, mime, bytes, slot)` | Сохраняет файл в `task_results` |
| `_check_cancelled()` | Читает БД; бросает `TaskCancelledError` если `status=cancelled` |
| `_call_claude_json(...)` | Вызов Claude → JSON, с авто-ретраем парсинга |
| `_interruptible_claude_json(...)` | То же, но каждые 30 сек проверяет отмену из БД |

## 8. Шаблон fetch-функции (фронтенд)

Для каждой подзадачи свой `fetchXxxStatus`. **Критически важно**: не останавливать поллинг при разовой ошибке.

```typescript
const xxxFetchErrorCount = useRef(0);

const fetchXxxStatus = useCallback(async (cid: string) => {
  try {
    const data = await getTaskStatus(cid);
    xxxFetchErrorCount.current = 0;           // сброс при успехе
    setXxxTask(data);
    if (data.status === 'pending' || data.status === 'processing') startXxxTimer();
    if (data.progress_message) {
      setXxxProgressLog((prev) => {
        const last = prev[prev.length - 1];
        return last === data.progress_message ? prev : [...prev, data.progress_message!];
      });
    }
    if (data.status === 'completed') {
      const res = await getTaskResults(cid);
      setXxxResults(res);
      stopXxxPolling();
    } else if (data.status === 'failed' || data.status === 'cancelled') {
      const res = await getTaskResults(cid);
      setXxxResults(res);
      stopXxxPolling();
    }
  } catch {
    xxxFetchErrorCount.current += 1;
    if (xxxFetchErrorCount.current >= 5) {   // ~15 сек без связи
      stopXxxPolling();
      setError('Задача прервана: потеряно соединение с сервером.');
    }
  }
}, [stopXxxPolling, startXxxTimer]);
```

## 9. Правило восстановления состояния после обновления страницы

При монтировании `TaskStatus` вызывается `getRelatedChecks(taskId)` — эндпоинт ищет в БД подзадачи по `user_prompt = taskId`. Для каждой найденной подзадачи:
- `setXxxTaskId(check.task_id)` — восстанавливает ID
- `fetchXxxStatus(check.task_id)` — загружает текущий статус и результаты
- Если задача ещё выполняется — запускается polling

Это значит: **любая новая подзадача должна создаваться с `user_prompt = source_task_id`**, чтобы эндпоинт `related-checks` мог её найти. При расширении `related-checks` добавить новый тип в список `check_types`.

## 10. Тайм-ауты и лимиты

| Параметр | Значение | Где задаётся |
|---|---|---|
| Тайм-аут одного вызова Claude | `processing_timeout=1200.0` (20 мин) | `_interruptible_claude_json(...)` |
| Проверка отмены во время вызова | каждые 30 сек | `cancel_check_interval=30.0` |
| Размер чанка | `max_chunk_size=25` позиций | `_chunk_by_work_boundaries(...)` |
| Интервал поллинга (фронтенд) | 3 сек | `setInterval(..., 3000)` |
| Порог отказа поллинга | 5 подряд ошибок | `fetchErrorCount >= 5` |
| Предупреждение о долгой задаче | > 15 мин (900 сек) | условие в JSX |

## 11. Слоты результатов

| Слот | Назначение |
|---|---|
| `result` | Основной финальный файл (любая задача) |
| `estimate` | Excel со стоимостью (ESTIMATE_TASK_TYPES) |
| `optimized` | Оптимизированная версия |
| `partial_N` | Промежуточный файл при остановке/ошибке на чанке N |

Скачивание — через `GET /tasks/{id}/results/{file_id}/download`.
