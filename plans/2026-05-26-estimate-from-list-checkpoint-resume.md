# Чекпоинт и возобновление задачи ESTIMATE_FROM_LIST

## Проблема
Задача «Смета из перечня» зависала навсегда на этапе «Формирование Excel сметы».
Причина: concurrent use одной asyncpg-сессии — `call_claude` писал лог через `db.flush()`
пока `_check_cancelled` параллельно читал через тот же `self.db`, что портило состояние соединения.
При следующем `await db.commit()` (в `save_result`) соединение не отвечало, задача зависала на 300+ минут.

## Решение

### Фаза 1: Исправление основного бага [x]
Файл: `backend/app/services/claude_service.py`
- Логгирование `ApiCallLog` переведено на независимую сессию (`AsyncSessionLocal()`)
  вместо переданного `db` — устраняет concurrent use

### Фаза 2: Чекпоинт + возобновление [x]
Файл: `backend/app/services/task_processor.py`
- После всех Claude-чанков (перед шагом 3) сохраняется чекпоинт в `progress_data`:
  `{_stage: "pre_excel", items: [...], matched: {...}, claude_results: {...}}`
  — через независимую сессию (не `self.db`)
- Шаг 3 вынесен в отдельный метод `_run_estimate_step3()`
- При старте задачи: если `_stage == "pre_excel"` — данные восстанавливаются из чекпоинта,
  шаги 0-2 пропускаются, выполняется только шаг 3

Файл: `backend/app/routers/tasks.py`
- `ESTIMATE_FROM_LIST` добавлен в `RESUMABLE_TYPES`
- Условие наличия чекпоинта расширено: `chunks_done` ИЛИ `_stage == "pre_excel"`

### Фаза 3: UI [x]
Файл: `frontend/src/pages/TaskStatus.tsx`
- Для задач `ESTIMATE_FROM_LIST` с `progress_data._stage === "pre_excel"` показывается блок
  «Продолжить» + «Перезапустить с начала» (аналогично блоку LIST_FROM_GRAND)
- Сообщение: «Данные от Claude сохранены. Задача зависла на этапе формирования Excel.
  Нажмите «Продолжить» — токены повторно тратиться не будут.»

## Итог
Реализован полностью. После деплоя: при зависании на шаге Excel
пользователь нажимает «Стоп» → появляется кнопка «Продолжить» → задача
возобновляется с сохранёнными данными, минуя повторные вызовы Claude.
