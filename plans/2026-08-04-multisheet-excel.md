## Принятое решение

**Лист — поле строки, а не отдельная сущность хранилища.** Строки всех листов лежат одним
массивом в `EstimateVersion.rows`, каждая несёт `sheet: "<имя листа>"`. Вкладка в редакторе —
фильтр по этому полю. Генераторы xlsx группируют строки по `sheet` и пишут по листу на группу.

Почему не иначе (Challenge Log):

1. **Решает ли задачу?** Да. Признак листа едет по циклу вместе с позицией
   (`progress_data['items']` → полнота → смета → оптимизация), поэтому «весь цикл по всем
   вкладкам» получается без единой новой связи между задачами.
2. **Самое ли эффективное?** Альтернативы — лист как версия (`estimate_versions.sheet_name`) и
   лист как карточка. Первая ломает смысл версии (версия = вариант оптимизации) и требует
   миграции БД, нового параметра в 14 ручках и матрицы версия×лист в `estimate_store`,
   `primary_version_id`, сводной. Вторая разносит один тендер по нескольким карточкам. Выбранный
   вариант — единственный, который не трогает версии, права, черновик, `rev` и сводную. Та же
   модель у промышленных импортёров таблиц (SheetJS, pandas `sheet_name=None`).
3. **Нет ли кода ради кода?** Каждый пункт ниже привязан к критерию приёмки. Попутных
   рефакторингов нет; `wb.active` заменяется только там, где это меняет поведение по спецификации.

## Решения пользователя

* Итоги сметы: блок итогов на **каждом** листе + отдельный лист «Итого по смете» со сводкой и
  строкой «ВСЕГО». `task.cost` = ВСЕГО. (C3, C4, C5)
* Файл перечня при нескольких листах: лист на источник + «Пояснительная записка», без сквозных
  «Работы»/«Материалы». (A4)
* Итоги на экране: «ИТОГО по листу «‹имя›»» и «ВСЕГО по смете» одновременно. (E8)

## Фаза 1 — Фундамент: признак листа и работа с именами `[x]`

**Файлы:** `backend/app/utils/sheet_names.py` (новый), `backend/app/utils/xlsx_generic.py`,
`backend/app/utils/estimate_rows.py`, тесты.

1. Новый модуль `sheet_names.py`:
   * `safe_sheet_title(name, used)` — вычищает `: \ / ? * [ ]`, обрезает до 31 символа, пустое →
     `Лист`, дубли получают суффикс ` (2)`.
   * `group_by_sheet(records, key)` → `list[tuple[str | None, list]]` в порядке первого появления.
2. `xlsx_generic.parse_xlsx_to_generic_rows(file_bytes, sheets=None)`:
   * обходит `wb.worksheets` (или только перечисленные в `sheets`, в их порядке);
   * шапка ищется в каждом листе отдельно;
   * лист без строк данных пропускается;
   * каждая строка получает `"sheet": <имя листа>`.
3. `xlsx_generic.rows_to_xlsx(rows)`: лист на группу, **свой** порядок колонок у каждого листа,
   имя листа через `safe_sheet_title`.
4. `estimate_rows`: `sheet` в `PASSTHROUGH_FIELDS` — переносится позиция↔строка в обе стороны.

**Гейт:** круговой прогон многолистового xlsx → строки → xlsx → строки даёт те же листы, строки и
колонки. Однолистовой файл ведёт себя как раньше (A5, F1).

## Фаза 2 — Перечень и полнота `[x]`

**Файлы:** `backend/app/utils/file_parser.py`, `backend/app/services/excel_service.py`,
`backend/app/services/task_processor.py`, `backend/app/services/document_service.py`.

1. `parse_xlsx_grand`: разбор вынесен в `_parse_grand_sheet(ws)`; обходятся все листы, строки
   помечаются листом. Fallback-режим («шапку не нашли — берём всё подряд») включается только если
   **ни один** лист не дал строк обычным путём — иначе титульный лист засорил бы перечень (A2).
2. `chunk_rows`: чанк не пересекает границу листа (A3).
3. `excel_service.generate_list`:
   * `data_sheet_titles(items)` — какие листы данных будут в файле;
   * один лист → прежние 4 листа (A5); несколько → лист на источник + «Пояснительная записка» (A4).
4. `task_processor._handle_list_from_grand_xlsx`: позиции, вернувшиеся из ИИ по чанку, получают
   лист этого чанка.
5. `task_processor._handle_check_completeness`: чанки внутри листа, позиции получают лист чанка
   (B1–B3).
6. `_create_initial_generic_version(..., sheets=...)` — V0 собирается только из листов данных.
   `document_service.ensure_versions` для старых задач исключает служебные листы наших же
   генераторов.

**Гейт:** тест «перечень из двухлистовой гранд-сметы» — позиции обоих листов, вкладки по именам,
титульный лист не создал вкладку. Тест «полнота сохраняет вкладки».

## Фаза 3 — Смета и оптимизация `[x]`

**Файлы:** `backend/app/utils/xlsx_cost_parser.py`, `backend/app/services/estimate_parser.py`,
`backend/app/utils/xlsx_exporter.py`, `backend/app/utils/xlsx_optimizer.py`,
`backend/app/utils/xlsx_statement.py`.

1. `parse_list_sheet`: файл нашего старого формата (есть лист «Перечень» **и** листы «Работы» и
   «Материалы») читается по-прежнему — только «Перечень». Любой другой файл читается по всем
   листам с данными, позиции получают лист (C1).
2. `parse_estimate_excel`: все листы, `sheet` в строке, `link_materials_to_works` не связывает
   материал с работой соседнего листа (C2, D1).
3. `generate_estimate_xlsx`: лист на группу со своим блоком итогов; при нескольких листах —
   лист «Итого по смете» со сводкой и «ВСЕГО»; возвращаемый итог = ВСЕГО (C3–C6).
4. `xlsx_optimizer.parse_estimate_xlsx` / `generate_optimized_xlsx`: все листы, позиция
   адресуется парой (лист, строка) (D3).
5. `xlsx_statement.generate_statement_xlsx`: лист на группу (E10).

**Гейт:** тест с точными числами — итог каждого листа, «ВСЕГО», `task.cost` и итог, посчитанный
формулой фронта, совпадают до копейки (G1, G2). Тест «смета из одного листа = прежний файл» (C6).

## Фаза 4 — Редактор `[x]`

**Файлы:** `frontend/src/components/editor/adapters/*`, `stores/documentEditor.ts`,
`components/editor/DocumentEditor.tsx`, `components/editor/rowOps.ts`,
`components/editor/actions/priceInsert.ts`, `utils/estimateCalc.ts`,
`pages/ProjectCardPage.tsx`, `components/editor/DocumentEditor.css`.

1. `EditorAdapter.sheetOf(row)` + перенос листа через `toGrid`/`fromGrid` в обоих адаптерах.
2. Стор: `sheet` (активный лист), `sheets` (список с числом строк), `setSheet`. Правило: в
   `rows` всегда **все** строки документа; вкладка — только фильтр показа (E7).
3. `DocumentEditor`: полоса вкладок листов (E1, E2); `displayedRows` фильтруется листом до
   фильтров «Все/Работы/Материалы» и поиска (E3); колонки считаются по строкам активного листа
   (E4); добавление строки, вставка из прайса и из буфера ставят активный лист (E5); удаление и
   перетаскивание — внутри листа (E6).
4. Итоги: «ИТОГО по листу» + «ВСЕГО по смете» (E8).
5. Активный лист в адресе (`?sheet=`) (E9).

**Гейт:** `npx tsc --noEmit`, `npm run lint`, `npm test`; тесты на фильтрацию по вкладке, на то,
что «Применить» шлёт все строки, и на однолистовой документ без вкладок.

## Итог

Реализован целиком. Все пять фаз закрыты, критерии приёмки A–G выполнены.

Гейты на момент завершения: backend — `ruff` чисто, 1033 теста зелёные (было 966);
frontend — `tsc --noEmit` чисто, 333 теста зелёные (было 319).

Что сделано:

* Лист стал полем строки и позиции (`sheet`) — признак едет по всему циклу вместе с данными,
  новых связей между задачами не понадобилось, миграция БД не нужна.
* Все точки разбора Excel читают все листы: гранд-смета, generic-перечень, чужая смета,
  загруженный файл для сметы, разбор для ABC-оптимизации.
* Все генераторы пишут лист на лист: перечень, смета, оптимизированный файл, выгрузка-ведомость.
* Смета получила блок итогов на каждом листе и лист «Итого по смете» со строкой «ВСЕГО»;
  `task.cost` = «ВСЕГО».
* Редактор получил полосу вкладок листов, правку внутри вкладки, колонки по вкладке, снятие
  отметок при переключении, двойной блок итогов и лист в адресе страницы.
* Однолистовые файлы и документы, созданные до правки, ведут себя ровно как раньше.

Два дефекта, найденных проверкой и закрытых тестами:

1. Шаг 3 сборки сметы пересобирал позиции из фиксированного набора полей и терял лист — позиции
   с ценой от ИИ, без цены и вычеты уезжали бы на вкладку «Прочее».
2. Лист из ссылки (`?sheet=`) «съедался» до того, как список листов появлялся, и вкладка из
   присланной коллегой ссылки не открывалась.

Что осталось за рамками (по спецификации, раздел «Не входит»): переименование, добавление и
удаление листов из редактора, перенос строк между листами мышкой, ветка задач из PDF-проекта.
