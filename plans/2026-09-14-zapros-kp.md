# План: запрос КП у отдела производства работ

Дата: 2026-09-14
Спецификация: `specs/2026-09-14-zapros-kp.md`
Исследование: `thoughts/research/2026-09-14-zapros-kp.md`
Статус: planning

## Решение одной строкой

Две новые роли, которым по умолчанию закрыто всё, кроме своих запросов; запрос
КП — отдельные таблицы «запрос → позиции-снимки → КП → цены»; ИИ разбирает файл
КП в фоне, человек подтверждает; менеджер продаж через предпросмотр одной
транзакцией создаёт версию оптимизации «Цены из КП».

## Решения пользователя (14.09.2026)

| Развилка | Решение |
|---|---|
| Как цены из КП попадают в запрос | ИИ разбирает файл КП, человек проверяет |
| Несколько КП на позицию | Минимальная цена по умолчанию, выбор можно сменить |
| Когда цены идут в оптимизацию | Кнопкой, новой версией |
| Доступ новых ролей | Только свои задачи КП |

## Challenge Log

1. **Решает ли проблему?** Критерии 1–5 — фаза 1 (+ фильтр внутри роутера в
   фазе 2); 6–11 — фазы 2–3; 12–14, 17–21 — фазы 4–5; 15–16 — фаза 6; 22–30 —
   фазы 3 и 7. Сверка — таблица в конце.
2. **Самое ли эффективное решение?**
   * Новый `task_type` в `tasks` отвергнут: `pending` = job в очереди, статусы
     кормят ETA и метрики — пришлось бы обходить исключениями; исполнителя и
     позиций у `Task` нет.
   * Цены прямо в полях строк отвергнуты: нарушают «у строки один писатель» и
     исчезают при пересчёте.
   * Сужение `can_access` отвергнуто: половина роутеров его не зовёт.
     Зависимость на `include_router` + тест по `app.routes` закрывает и
     будущие ручки.
   * Модель «запрос / позиции / предложения / матрица цен» — стандарт
     закупочных систем (Ariba RFQ, 1С:ERP, Битрикс24 «Тендеры»).
3. **Нет ли кода ради кода?** Не делаем: отправку поставщикам, запись в прайс,
   дедлайны, почту/Telegram, запрос из сводной. Две правки существующего кода
   оправданы критериями: вынос клонирования версии в сервис (без него критерий
   30 невыполним — см. проблему 10) и чтение `source_no` в `estimate_parser`
   (критерий 25; попутно чинится захват этой колонки как «№»).

## Модель данных (миграция `052_kp_requests.py`, `IF NOT EXISTS`)

```
kp_requests
  id UUID PK
  project_id UUID FK projects ON DELETE CASCADE
  card_id UUID FK workflow_cards ON DELETE CASCADE
  source_kind VARCHAR(16)        -- list | completeness | estimate | optimization
  source_task_id UUID NULL       -- задача документа (для optimization — сопоставление по row_id)
  source_version_id UUID NULL
  category VARCHAR(16)           -- material | work
  status VARCHAR(16)             -- new | in_progress | done | cancelled
  author_id INT FK users SET NULL
  assignee_id INT FK users SET NULL
  author_comment TEXT, report TEXT
  applied_at TIMESTAMPTZ NULL, applied_version_id UUID NULL
  created_at, updated_at, taken_at, completed_at, deleted_at
  INDEX (assignee_id, status), INDEX (card_id)

kp_request_items                 -- снимок позиции на момент запроса
  id UUID PK
  request_id UUID FK kp_requests CASCADE
  position INT
  item_type VARCHAR(16)          -- material | work
  name TEXT, unit VARCHAR(64) NULL, qty NUMERIC NULL
  sheet VARCHAR(128) NULL, source_no VARCHAR(64) NULL
  source_row_ids JSONB           -- row_id всех строк группы выделения
  selected_offer_id UUID NULL FK kp_offers SET NULL

kp_offers                        -- одно КП = один файл от поставщика
  id UUID PK
  request_id UUID FK kp_requests CASCADE
  supplier_name TEXT, offer_date DATE NULL
  vat_mode VARCHAR(16)           -- with_vat | without_vat | no_vat
  file_name, mime_type, size_bytes, storage_key
  parse_status VARCHAR(16) NULL  -- queued | processing | parsed | failed
  parse_error TEXT NULL, parse_started_at, parse_cost NUMERIC NULL
  created_by INT FK users SET NULL, created_at, deleted_at

kp_offer_prices                  -- матрица «позиция × КП»
  id UUID PK
  offer_id UUID FK kp_offers CASCADE
  item_id UUID FK kp_request_items CASCADE
  price NUMERIC                  -- цена за единицу КП, как в файле
  unit VARCHAR(64) NULL
  name_in_offer TEXT NULL
  source VARCHAR(8)              -- ai | manual
  confidence VARCHAR(8) NULL     -- high | medium | low
  confirmed BOOLEAN
  UNIQUE (offer_id, item_id)
```

Приведённая цена **не хранится** — считается на лету (`kp_pricing`), как
отклонение от цели (правило №16): иначе правка НДС или единицы оставила бы
устаревшее число.
