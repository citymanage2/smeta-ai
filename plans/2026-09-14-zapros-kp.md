# План: запрос КП у отдела производства работ

Дата: 2026-09-14
Спецификация: `specs/2026-09-14-zapros-kp.md`
Исследование: `thoughts/research/2026-09-14-zapros-kp.md`
Статус: in progress (фазы 1–3 готовы)

## Решение одной строкой

Две новые роли, которым по умолчанию закрыто всё, кроме запросов своей роли;
запрос КП — отдельные таблицы «запрос → позиции-снимки → КП → цены», адресован
роли целиком; ИИ разбирает файл КП в фоне, человек подтверждает; при завершении
подтверждённые цены пишутся в прайс, а в оптимизацию — кнопкой через
предпросмотр, одной транзакцией, новой версией.

## Решения пользователя (14.09.2026)

| Вопрос | Решение |
|---|---|
| Как цены из КП попадают в запрос | ИИ разбирает файл КП, человек проверяет |
| Несколько КП на позицию | Минимальная цена по умолчанию, выбор можно сменить |
| Когда цены идут в оптимизацию | Кнопкой, новой версией |
| Доступ новых ролей | Только запросы своей роли |
| НДС | У КП: «с НДС / без НДС» и ставка (по умолчанию 22 %) |
| КП «работа с материалами» | Отметка и подсветка, ничего не обнулять; в прайс работ не писать |
| Доставка, сроки, партия | Только в отчёте |
| Кому адресован запрос | Всем сотрудникам роли одновременно (обе роли) |
| Что видит исполнитель | Позиции + вложения автора |
| Уведомления | Счётчик в интерфейсе |
| Цены из КП в прайс | Напрямую при завершении; у работы ключ «КП: <поставщик>», приоритет выше «Из смет» |

## Challenge Log

1. **Решает ли проблему?** Критерии 1–5 — фазы 1–2; 6–12 — фазы 2–3; 13–22 —
   фазы 4–6; 23–28 — фаза 7; 29–37 — фазы 3 и 8. Сверка — таблица в конце.
2. **Самое ли эффективное решение?**
   * Новый `task_type` в `tasks` отвергнут: `pending` = job в очереди, статусы
     кормят ETA и метрики; исполнителя, позиций и вложений у `Task` нет.
   * Цены прямо в полях строк отвергнуты: нарушают «у строки один писатель».
   * Сужение `can_access` отвергнуто: половина роутеров его не зовёт.
     Зависимость на `include_router` + тест по `app.routes` закрывает и будущие
     ручки.
   * Запись в прайс — через существующий `price_bulk.add_items` с параметром
     подрядчика, а не свой путь: правила единиц (№8), даты цены (№15) и ключа
     позиции (№19) остаются одни на все пути записи.
   * Модель «запрос / позиции / предложения / матрица цен» — стандарт
     закупочных систем (Ariba RFQ, 1С:ERP, Битрикс24 «Тендеры»).
3. **Нет ли кода ради кода?** Не делаем: отправку поставщикам, учёт доставки,
   дедлайны, почту/Telegram, запрос из сводной, роль руководителя производства.
   Правки существующего кода оправданы критериями: `price_min` (26),
   `price_bulk` — ключ подрядчика (23), вынос клонирования версии (37),
   `source_no` в `estimate_parser` (32).

| 28 | `create_manual_version` — обработчик с `commit`; не копирует `coefficient` и `task_type` | `estimate_versions_service.clone_version` без `commit`, копирует строки, проценты, `coefficient`, `task_type`; роут зовёт его же, ответ прежний | 8 |

## Модель данных (миграция `052_kp_requests.py`, `IF NOT EXISTS`)

```
kp_requests
  id UUID PK
  project_id UUID FK projects ON DELETE CASCADE
  card_id UUID FK workflow_cards ON DELETE CASCADE
  source_kind VARCHAR(16)          -- list | completeness | estimate | optimization
  source_task_id UUID NULL
  source_version_id UUID NULL
  category VARCHAR(16)             -- material | work
  target_role VARCHAR(32)          -- supply_manager | contractor_manager
  status VARCHAR(16)               -- new | in_progress | done | cancelled
  author_id INT FK users SET NULL
  taken_by_id INT FK users SET NULL, taken_at
  completed_by_id INT FK users SET NULL, completed_at
  author_comment TEXT, report TEXT
  pricelist_status VARCHAR(16) NULL   -- done | failed
  pricelist_summary JSONB NULL        -- {added, updated, skipped{причина: n}, written[{kind, name_key, contractor, value}]}
  pricelist_error TEXT NULL, pricelist_written_at
  applied_at TIMESTAMPTZ NULL, applied_version_id UUID NULL
  created_at, updated_at, deleted_at
  INDEX (target_role, status), INDEX (card_id)

kp_request_files                   -- вложения автора
  id UUID PK
  request_id UUID FK kp_requests CASCADE
  file_name, mime_type, size_bytes, storage_key
  uploaded_by INT FK users SET NULL, created_at, deleted_at

kp_request_items                   -- снимок позиции
  id UUID PK
  request_id UUID FK kp_requests CASCADE
  position INT
  item_type VARCHAR(16)            -- material | work
  name TEXT, unit VARCHAR(64) NULL, qty NUMERIC NULL
  sheet VARCHAR(128) NULL, source_no VARCHAR(64) NULL
  source_row_ids JSONB
  selected_offer_id UUID NULL FK kp_offers SET NULL

kp_offers
  id UUID PK
  request_id UUID FK kp_requests CASCADE
  supplier_name TEXT, offer_date DATE NULL
  vat_mode VARCHAR(16)             -- with_vat | without_vat
  vat_rate NUMERIC(5,2) NULL       -- при with_vat; по умолчанию 22
  includes_materials BOOLEAN DEFAULT false   -- только для работ
  file_name, mime_type, size_bytes, storage_key
  parse_status VARCHAR(16) NULL    -- queued | processing | parsed | failed
  parse_error TEXT NULL, parse_started_at, parse_cost NUMERIC NULL
  created_by INT FK users SET NULL, created_at, deleted_at

kp_offer_prices
  id UUID PK
  offer_id UUID FK kp_offers CASCADE
  item_id UUID FK kp_request_items CASCADE
  price NUMERIC                    -- за единицу КП, как в файле
  unit VARCHAR(64) NULL
  name_in_offer TEXT NULL
  includes_materials BOOLEAN NULL  -- NULL = как у КП
  source VARCHAR(8)                -- ai | manual
  confidence VARCHAR(8) NULL
  confirmed BOOLEAN
  UNIQUE (offer_id, item_id)
```

Приведённая цена **не хранится** — считается на лету (`kp_pricing`), как
отклонение от цели (правило №16).
