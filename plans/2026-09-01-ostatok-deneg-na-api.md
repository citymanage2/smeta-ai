# План: остаток денег на Claude API в реальном времени

Спека: `specs/2026-09-01-ostatok-deneg-na-api.md`
Исследование: `thoughts/research/2026-09-01-ostatok-deneg-claude-api.md`

## Challenge Log

**1. Решает ли это проблему?**
Проблема — «деньги кончаются молча». Критерии 3+4 дают цифру, критерий 7 даёт
предупреждение до остановки работы. Критерий 1 (прайс) не косметика: без него
цифра врёт на треть в опасную сторону — сервис считает, что денег меньше.

**2. Самое ли эффективное решение?**
Три подхода разобраны в исследовании. «Только свой лог» вечно копит ошибку прайса;
«только cost_report» не показывает свежую смету и не работает без админ-ключа.
Гибрид берёт точность от официальных данных и свежесть от своих, а без админ-ключа
деградирует до рабочего состояния вместо отказа.

**3. Нет ли кода ради кода?**
Лента браузерных уведомлений о низком остатке — выброшена: сегодня она умеет
показывать только события со списком задач, переделка ленты к задаче не относится.
Настройка порога в интерфейсе — выброшена: порог считается из собственного темпа
расхода за неделю, настраивать нечего. Прогноз на месяц — выброшен, не в спеке.

## Ключевые решения

- **Граница источников — начало текущего дня UTC.** Всё до неё берётся из
  `cost_report`, всё после — из `api_call_log`. Ни одна трата не считается дважды.
- **`amount` в cost_report — в центах**, строкой: `"123.45"` = $1.23. Делим на 100.
- **Синхронизация перезаписывает последние 3 дня**, а не только вчерашний:
  дневной бакет дозаполняется какое-то время после полуночи.
- **Порог не настраивается**, а считается: остаток / (расход за 7 дней / 7).
  Меньше 3 дней — предупреждение, меньше 1 — тревога.
- **Без `ANTHROPIC_ADMIN_KEY` фича живёт** на одном `api_call_log` и подписывает,
  что официальная сверка не подключена.

## Фазы

### [ ] Фаза 1 — действующий прайс моделей

`backend/app/services/claude_service.py`, `_COST_PER_TOKEN`.
Anthropic отменил повышение до $3/$15: цена Sonnet 5 $2/$10 стала стандартной.
Ставим действующие: вход $2, выход $10, запись кеша 5m $2.50, чтение кеша $0.20.
`default` (неизвестная модель) остаётся консервативным — занижать нельзя.
Тест: `tests/test_api_cost_pricing.py` — точные числа по каждой категории и
половинная цена для батча.

### [ ] Фаза 2 — хранилище

`backend/app/models/api_balance.py`:
- `ApiBalanceTopup` — пополнение: `amount_usd` Numeric(12,2), `happened_on` Date,
  `note`, `created_by`, `created_at`.
- `ApiCostDay` — официальная стоимость дня: `day` Date (PK), `amount_usd`
  Numeric(12,6), `synced_at`. Upsert по дню — повторная синхронизация не двоит.

Миграция `backend/alembic/versions/047_api_balance.py`, обе таблицы с `IF NOT EXISTS`.

### [ ] Фаза 3 — клиент Usage & Cost API

`backend/app/services/anthropic_admin.py`: `fetch_cost_days(start, end)` →
`dict[date, Decimal]`. Raw HTTP через `httpx` (в SDK этих эндпоинтов нет),
`x-api-key: ANTHROPIC_ADMIN_KEY` + `anthropic-version: 2023-06-01`, база —
`ANTHROPIC_BASE_URL` при наличии (прод ходит через свой прокси). Пагинация по
`next_page`. Центы → доллары. Ключ не задан → `None`, а не исключение.
Тесты: разбор реального ответа (центы!), пагинация, пустой день, 401.

### [ ] Фаза 4 — расчёт остатка

`backend/app/services/balance_service.py`:
- `sync_cost_days(db)` — тянет последние 3 дня и upsert'ит; пишет `synced_at`.
- `compute_balance(db)` → пополнения, официальные траты до начала сегодняшнего дня
  UTC, свои траты после неё, остаток, дата последнего пополнения, время последней
  удачной сверки, «хватит на N дней» и «на N смет».
Тесты: границы источников не пересекаются; идемпотентность; поведение без ключа;
остаток ушёл в минус (пополнение не внесли) — показывается как есть, не обнуляется.

### [ ] Фаза 5 — HTTP

`POST /admin/api-balance/topups`, `DELETE /admin/api-balance/topups/{id}`.
Права — менеджер (как весь дашборд). Тесты: чужая роль получает 403.

### [ ] Фаза 6 — фоновая синхронизация

`backend/app/worker.py`: job раз в час, `max_instances=1`. Отказ Anthropic ловится
и логируется, последние известные данные остаются.
