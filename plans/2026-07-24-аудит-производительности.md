# План: Аудит производительности — реализация

**Дата:** 2026-07-24
**Ветка:** `feature/perf-audit-2026-07`
**Источник:** аудит по внешнему плану (P0–P3), адаптированный под стек FastAPI + SQLAlchemy + React/Vite/Zustand.

## Контекст

Стек проекта — не Next.js/Prisma, а FastAPI + SQLAlchemy (async) + PostgreSQL + React/Vite/Zustand/Axios. Аудит выявил: сильные стороны (индексы, агрегация в SQL, in-memory кэш прайса, идемпотентность, пул) и реальные проблемы (нет наблюдаемости, каталог цен грузит лишнее, нет code splitting, хаотичный polling, невиртуализированный GenericGrid, обработка смет в веб-процессе).

**Золотое правило:** каждую оптимизацию проверяем на базовой линии из Фазы 0. Без замера эффект не подтверждаем.

## Принципы

- Не оптимизируем вслепую: сначала наблюдаемость (Фаза 0), потом остальное.
- Не ломаем сильные стороны (пул, агрегация, кэш прайса — не трогаем).
- Коммит после каждой фазы, гейты (tsc/lint/pytest/ruff) перед `[x]`.
- Изменения моделей БД → сначала миграция с `IF NOT EXISTS`.

## Фаза 0: Наблюдаемость (разблокирует всё) — [ ]

Цель: появляется базовая линия — можно измерить эффект остальных фаз.

- **0.1** ASGI-middleware времени ответа: на каждый ответ лог `path, method, status, duration_ms` через structlog. Пропуск `/health` и статики.
- **0.2** env-флаг `SQL_ECHO` → `create_async_engine(echo=...)`; в docker-compose Postgres `command` с `log_min_duration_statement=200 -c log_connections=on`.
- **0.3** колонка `duration_ms` в `api_call_log` + миграция `030` (`IF NOT EXISTS`); писать длительность вызова Claude в claude_service.

Гейты: `py_compile`, `pytest -q`, `ruff check`.

## Фаза 1: Дешёвые высокоэффективные победы — [ ]

- **1.1** gzip в `frontend/nginx.conf` (`gzip on; gzip_types ...`).
- **1.2** `sourcemap: false` (или `'hidden'`) в прод-сборке `vite.config.ts`.
- **1.3** `healthCheckPath: /health` в `render.yaml` для backend-сервиса.
- **1.4** tie-breaker `, Task.id.desc()` в offset-сортировках (`tasks.py:1929`, `admin.py:326,367`).

## Фаза 2: Каталог цен — [ ]

- **2.1** `prices_catalog.list_catalog`: `defer(embedding)` / явный select; фильтр `ilike` + `order_by` + `offset/limit` в SQL; отдельный `func.count()` для total.
- **2.2** `price_service.save_to_cache`: прямой `WHERE` по нормализованному имени вместо загрузки всей таблицы; индекс на нормализованное имя (миграция).

## Фаза 3: N+1 в источниках сметы — [ ]

- **3.1** `tasks.get_estimate_sources`: один запрос `WHERE ... IN (source_ids)` + раскладка в dict вместо цикла с N запросами.

## Фаза 4: Code splitting фронта — [ ]

- **4.1** `React.lazy` по роутам в `App.tsx` + `Suspense` fallback.
- **4.2** динамический импорт тяжёлых библиотек: `xlsx` (в момент экспорта), `recharts` (при открытии дашборда), опционально `react-data-grid`.
- **4.3** (опц.) `manualChunks` в vite для vendor-разбиения.

## Фаза 5: Polling-политика + HTTP-кэш — [ ]

- **5.1** пауза по `document.hidden` в `useGlobalTaskPoller` и `useDashboardStats`; распараллелить последовательные `await` в глобальном поллере.
- **5.2** адаптивный интервал (backoff) для статусных поллеров.
- **5.3** (опц.) `ETag`/`Cache-Control: private` на `GET /workflow-cards`, `/dashboard`.

## Фаза 6: GenericGrid + оптимистичный drag-drop — [ ]

- **6.1** `React.memo` на `CellInput` + стабильный `onChange` (`useCallback`) — минимальный шаг.
- **6.2** виртуализация GenericGrid (окно видимых строк) — если перечни бывают >500 строк; иначе ограничиться 6.1.
- **6.3** debounce поиска в GenericGrid.
- **6.4** оптимистичный drag-drop канбана: сразу переставить карточку, откат при ошибке (`stores/kanban.ts`).

## Фаза 7: Вынос обработки смет в отдельный воркер — [ ]

Стратегическая, самая крупная. Сейчас фон (обработка смет: WeasyPrint, openpyxl, OCR, embeddings) живёт в том же uvicorn-процессе, что HTTP → CPU-шаги морозят сервер.

- **7.1** Краткосрочно: обернуть CPU-тяжёлые вызовы в `run_in_executor`/`asyncio.to_thread`.
- **7.2** Долгосрочно: вынести обработку в отдельный процесс (arq на Redis/Postgres или отдельный uvicorn-worker-loop). Поллеры (batch/resume) — в воркер. render.yaml — отдельный сервис.
