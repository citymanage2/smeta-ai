# Диагностика «почему задача висит» — кнопка в панели администратора

## Проблема

Задачи висят в «Обработке» часами. Админ (не разработчик) не может отличить
«работает медленно» от «мертва», и не может проверить, дошло ли пополнение
баланса AI-API. Единственный способ — логи сервера, что недоступно.

При этом на бэкенде уже есть два готовых эндпоинта, к которым не подключён UI:

- `GET /admin/api-health` — пробный вызов AI-API (max_tokens=1), вердикт
  `ok | no_balance | auth | unavailable | misconfigured` + подсказка.
  Отдельно сообщает, через посредника ли идут запросы (чей счёт пуст).
- `GET /admin/queue-health` — состояние durable-очереди `jobs`, вердикт
  `idle | ok | busy | stalled` + возраст старейшей задачи и число потерянных.

## Фаза 1 — подключить эндпоинты к фронтенду [x]

- `frontend/src/api/admin.ts`: типы `ApiHealth`, `QueueHealth`, функции
  `getApiHealth()`, `getQueueHealth()`.
- `frontend/src/pages/Admin.tsx`: компонент `HealthPanel` — кнопка
  «Проверить сейчас» запускает обе проверки разом (`Promise.all`), результат
  выводится двумя карточками с цветовым тоном по вердикту.
- Панель размещена над вкладками — видна на любой вкладке админки.

Проверено: `npx tsc --noEmit` — чисто; бэкенд-тесты
`test_admin_api_health.py`, `test_admin_queue_health.py` — 17 passed.

## Фаза 2 — прогресс внутри пачки чанков [ ]

`_process_chunks` ([task_processor.py:2373]) шлёт до 38 запросов пачками по 4 и
не пишет ни одного сообщения до конца всей группы. Отсюда многочасовая тишина.

- Обновлять прогресс по мере готовности каждого чанка: «Обработано N из M частей».

## Фаза 3 — предельный срок этапа [ ]

Сейчас этап отправки чанков не ограничен по времени: при недоступном API
автоповтор с бэкоффом до 900 с × 4 попытки × число чанков растягивается на часы.

- Общий дедлайн на этап; при превышении — задача падает с внятной ошибкой
  вместо вечной «Обработки».

## Фаза 4 — распознавание «нет баланса» через посредника [ ]

Через агрегатор ошибка нехватки средств может прийти не как 400, а как 429/5xx
— тогда вместо мгновенной паузы включается многочасовой автоповтор.

- Расширить `_raise_if_insufficient_balance` на такие обёртки.

## Фаза 5 — признак жизни в карточке задачи [ ]

Воркер шлёт heartbeat каждые 30 с ([task_processor.py:2592]), но только в лог.

- Показывать в карточке «последний сигнал: N секунд назад».
- Если сигнала нет дольше 3 минут — плашка «задача не отвечает» + «Перезапустить».

## Итог

Реализована Фаза 1: админ теперь видит причину зависания кнопкой в интерфейсе.
Фазы 2–5 не реализованы — устраняют сами причины многочасовых зависаний.
