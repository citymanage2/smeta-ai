# Plan: эталонный прайс из сметы
**Spec:** specs/2026-09-02-etalonnyy-prays-iz-smety.md
**Research:** thoughts/research/2026-09-02-etalonnyy-prays-iz-smety.md
**Status:** in_progress

## Challenge Log

**Проблема.** Цены из «правильной» сметы надо занести в прайс так, чтобы они
стали единственными: чужие цены по тем же позициям стёрты, а позиции с тем же
смыслом под другим названием — удалены с ведома человека.

**Выбранное решение.** Отдельный двухшаговый эндпоинт «эталон» рядом с
существующим импортом: `preview` (ничего не меняет, показывает вытеснение и
кандидатов-дублей) → `apply` (пишет цены и удаляет только отмеченное).
Состояние между шагами не хранится: шаг 2 принимает разобранные позиции JSON-ом.

**Рассмотренные альтернативы.**
1. **Флаг `mode=reference` у существующего `POST /admin/price-lists/{type}`** —
   отклонено: один эндпоинт с двумя противоположными семантиками (merge против
   вытеснения) и с обязательным подтверждением посередине; риск, что обычная
   загрузка прайса подрядчика однажды снесёт его цены из-за забытого флага.
2. **Полная перезаливка (`/prices/upload`, DELETE + INSERT)** — отклонено: она
   действительно делает цены единственными, но ценой сноса всего прайса; у нас
   эталон — на несколько десятков позиций, остальное должно остаться.
3. **Автоудаление дублей по порогу похожести** — отклонено решением
   пользователя и здравым смыслом: прайс общий, удаление необратимо, а ошибка
   векторного поиска стоит потерянной цены подрядчика.
4. **Хранить предпросмотр в БД (таблица черновиков операции)** — отклонено:
   миграция и протухающее состояние ради данных, которые спокойно живут на
   фронте секунду-две; эмбеддинги локальные, повторный проход бесплатен.
5. **Внешняя библиотека дедупликации (fuzzy / record linkage)** — отклонено:
   появился бы второй способ считать «та же позиция», не совпадающий с тем, как
   цену ищет расчёт сметы; расхождение этих двух мерок и есть источник ошибки.

**Почему выбранное лучше.** Работающий merge-импорт не меняется ни на строку;
новая семантика живёт в своём сервисе и своём эндпоинте; «дубль» определяется
ровно тем же `find_top_n_*`, которым потом позиция будет искаться при расчёте;
миграций нет.

## Problems

| # | Проблема | Решение | Статус |
|---|---|---|---|
| 1 | Работы и материалы в одном файле, а импорт требует выбрать тип заранее | Разбор по колонке «Тип» нашего формата сметы; простой прайс-формат — по селекту | done |
| 2 | Несводимые единицы (мешок ↔ кг): вытеснение исказит чужую цену | `unit_compat.compare_units`; `incompatible` → не вытесняем, причина в сводку | done |
| 3 | «100 м2» в файле — цена не за м2 | `unit_normalizer.unit_price_factor`, как в `price_bulk` | done |
| 4 | Дата «Цена от» не должна ехать у нетронутых позиций | `price_change.prices_changed` / `price_changed` перед проставлением даты | done |
| 5 | Нет векторов — поиск дублей молча пуст | Флаг `vectors_ready` в ответе + текст, как в `match-preview` | done |
| 6 | Кеш веб-поиска перебивает расчёт раньше ИИ | Записи кеша попадают в список дублей помеченными, удаляются по галочке | done |
| 7 | Большой файл вешает запрос | Потолок позиций (`MAX_REFERENCE_ITEMS`), отказ с понятным текстом | done |
| 8 | Расчёт не увидит новые цены | `price_service.load_cache(db)` после применения | done |

## Phases

### Phase 1: разбор файла и правила вытеснения (сервис, без HTTP)
- **Status:** completed
- **Files:** `backend/app/services/reference_price.py` (новый),
  `backend/tests/test_reference_price_parse.py` (новый)
- **Changes:** разбор двух форматов в единый список позиций
  `{kind, name, unit, price}`; нормализация единицы и кратности; отсев позиций
  без имени и без цены с причинами; расчёт плана вытеснения по текущему прайсу:
  что добавится, что переоценится, какие цены будут стёрты, где единица
  несводима.
- **TDD:** файл нашего формата сметы (обе колонки цен) → работы и материалы
  разобраны; «100 м2» и цена 500 → «м2» и 5; мешок против кг → `incompatible`,
  вытеснения нет; строка без цены → «без цены»; строка без имени → «без
  наименования»; превышение потолка → ошибка.
- **Gates:** pytest ✅ | ruff ✅
- **Impact:** ничего не импортирует из роутеров; чистые функции + чтение прайса.

### Phase 2: поиск кандидатов-дублей
- **Status:** completed
- **Files:** `backend/app/services/reference_price.py`,
  `backend/tests/test_reference_price_duplicates.py` (новый)
- **Changes:** для каждой позиции файла — top-N по прайсу и по кешу через
  `price_service.find_top_n_*`; из кандидатов убирается сама совпавшая позиция;
  порог показа ниже порога подбора цены (показать лишнее дешевле, чем скрыть);
  возвращается `{source: 'price'|'cache', id, name, unit, price, score}`.
- **TDD:** позиция с точным совпадением не попадает в дубли сама к себе; запись
  кеша с похожим названием попадает и помечена `cache`; без векторов список
  пуст и `vectors_ready=false`; кандидат ниже порога показа не возвращается.
- **Gates:** pytest ✅ | ruff ✅
- **Impact:** только чтение; `price_service` не меняется.

### Phase 3: HTTP-контракт (preview / apply)
- **Status:** completed
- **Files:** `backend/app/routers/prices_catalog.py` (не `admin.py` — прайс это
  управляющее действие менеджерских ролей, `get_manager_user`, и весь каталог
  живёт там же),
  `backend/tests/test_reference_price_api.py` (новый)
- **Changes:** `POST /prices/reference/preview` (файл + тип для
  простого формата) и `POST /prices/reference/apply` (позиции JSON +
  id отмеченных дублей). Применение: работам — `prices = {«Из смет»: цена}`,
  `min_price` через `compute_min_price`; материалам — `price`; дата — только
  при переоценке; удаление отмеченных из прайса и кеша; в конце
  `price_service.load_cache(db)`. Права — как у остального прайса.
- **TDD:** preview не меняет БД (снимок до/после); после apply у работы один
  ключ «Из смет» и `min_price` равен цене файла; неотмеченный дубль остался,
  отмеченный удалён; дата у позиции с той же ценой не сдвинулась; чужая роль
  получает 403; несводимая единица — позиция пропущена с причиной.
- **Gates:** pytest ✅ | ruff ✅
- **Impact:** существующий `POST /admin/price-lists/{type}` не трогаем — в тестах
  проверить, что merge всё ещё сохраняет цены подрядчиков.

## Открыто до получения файла пользователя

Разбор ГРАНД-Сметы в область не входит. Если присланный файл окажется
гранд-сметой, а не выгрузкой нашего формата, — это отдельная фаза с отдельным
решением пользователя (там цены базисные и с накрутками, честно взять «цену за
единицу» нельзя).

## Итог

**Функция реализована целиком.** Пять фаз закрыты, гейты пройдены: 40 новых
тестов бэкенда, 4 фронта, полный набор бэкенда зелёный, `tsc` без ошибок.

Что сознательно осталось за границей и почему:

1. **Разбор ГРАНД-Сметы.** Там цены базисные и с накрутками (НР, СП, ФОТ), а
   материалы сидят внутри расценки — «цену за единицу как в прайсе» оттуда не
   достать без отдельного решения пользователя. Принимаются: файл сметы нашего
   формата (колонка «Тип» + две колонки цен) и простая таблица
   «Наименование / Ед. изм. / Цена» с выбором типа.
2. **Проверка на реальном файле пользователя** пройдена: «Сводная РЖД
   Техническая 87.xlsx» → 444 позиции (192 работы, 252 материала), 496 строк
   без цены пропущено, 18 расхождений цен внутри разделов показаны поимённо.
3. **Слияние дублей с переносом цен подрядчиков** в выжившую позицию — только
   удаление отмеченного, как и договаривались.
