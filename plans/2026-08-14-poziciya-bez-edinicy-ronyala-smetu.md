# Позиция без единицы измерения роняла расчёт сметы

## Проблема

Стадия «Смета» падала с текстом ошибки `'unit'` — и падала повторно при каждом
перезапуске. По ходу выполнения было видно: прайс нашёл 119 из 171, два чанка
ушли в Claude, посчитан 1 из 2, дальше — ошибка.

`'unit'` — это `str(KeyError("unit"))`. Расчёт цен собирал JSON чанка так:

```python
[{"id": it["_id"], "type": it["type"], "name": it["name"], "unit": it["unit"], ...}]
```

Позиции для сметы берутся из `task.progress_data['items']` стадии «Полнота», а
те складываются из **сырого ответа ИИ** (`data.get("items", [])`). Поля `unit`
ИИ возвращает не всегда — одна такая позиция роняла весь этап. Не первый чанк, а
тот, в который она попала: первый успевал посчитаться, деньги за него уже
уплачены. Перезапуск читал те же позиции из той же задачи и падал снова —
поэтому «перезапускали несколько раз, ошибка».

Отдельная беда: сообщение. `str(e)` для `KeyError` печатает только ключ, и в
карточке стояло голое `'unit'` — по нему нельзя понять даже род ошибки.

## Фазы

### [x] Фаза 1. Контракт позиции

`backend/app/utils/item_contract.py` — `ensure_item_fields`: дописывает
отсутствующие `type`/`name`/`unit`/`quantity`, значения не трогает. Пустая
единица законна (CLAUDE.md, правило 8), отсутствующая — авария.

Применяется:
- когда ответ ИИ становится позициями задачи — перечень (Гранд-смета, PDF
  проекта), полнота;
- когда смета читает чужие позиции (шаг 0 `_handle_estimate_from_list`) и когда
  возобновляется из чекпоинта `pre_excel`. Это главное: чинит и те задачи, что
  уже лежат в базе с дырявыми строками, — им достаточно «Перезапустить».

### [x] Фаза 2. Мягкое чтение в самом расчёте

`_fetch_price_chunk` и `_submit_estimate_batch` берут поля через `.get()`:
второй рубеж на случай, если позиция придёт мимо контракта.

### [x] Фаза 3. Понятный текст ошибки

`backend/app/utils/error_text.py` — `describe_exception`: сообщение с кириллицей
(наше, написанное для человека) идёт как есть, техническое получает имя типа —
`KeyError: 'unit'` вместо `'unit'`. Используется при падении задачи и в строке
хода выполнения.

### [x] Фаза 4. Тесты

`backend/tests/test_item_without_unit.py` — 11 тестов: контракт (включая
`"unit": null` и неизменность исходного списка), отправка чанка и батча с
позицией без единицы, тексты ошибок.

## Итог

Реализовано целиком. Прогон: 1260 passed, 9 skipped.

Что осталось за рамками: почему ИИ иногда не возвращает `unit` — вопрос к
промпту полноты. Сейчас такая позиция доезжает до сметы с пустой единицей и
подбирается по названию (правило 8: «Единица не указана — берём как есть»).
