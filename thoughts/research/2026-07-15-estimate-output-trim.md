# Research: сокращение формата ответа ИИ в ESTIMATE_FROM_LIST (пункт 3)

Дата: 2026-07-15
Задача: уменьшить output-токены (~18% стоимости сметы), не сломав JSON-схему и сборку Excel.

## Что отправляем ИИ
Промпт `PROMPT_ESTIMATE_FROM_LIST` (task_processor.py:274). Просит вернуть на каждую позицию:
`id, type, name, unit, quantity, work_price, material_price, price_list_name, sources, notes`.

## КЛЮЧЕВАЯ НАХОДКА: что из ответа реально используется

Разобрал два потребителя ответа ИИ.

### Потребитель 1 — сохранение в кеш (task_processor.py:1846-1871)
Использует из ответа ИИ:
- `id` — маппинг
- `type` — тип для кеша ✅ используется
- `name` — ключ кеша ✅ используется
- `unit` — ед.изм в кеш ✅ используется
- `work_price` / `material_price` — цена ✅
- `sources` — источники в кеш ✅

### Потребитель 2 — сборка Excel, step3 (task_processor.py:2013-2025)
```python
"type":  item.get("type")             # ← ОРИГИНАЛ из перечня, НЕ из ответа ИИ
"name":  item.get("name")             # ← ОРИГИНАЛ, НЕ из ответа ИИ
"unit":  cr.get("unit") or item...    # ← из ответа ИИ (основной)
"quantity": item.get("quantity")      # ← ОРИГИНАЛ, НЕ из ответа ИИ
"work_price"/"material_price": cr...  # ← из ответа ИИ
"price_list_name": "Интернет"         # ← хардкод, НЕ из ответа ИИ
"notes": cr.get("sources") or cr.get("notes")  # ← Excel-примечание = sources ИИ, notes лишь fallback
```

### Итог: классификация полей ответа
| Поле | Используется? | Кем |
|---|---|---|
| `id` | ДА | маппинг |
| `type` | ДА | кеш |
| `name` | ДА | кеш (ключ) — **нельзя убирать, ещё и якорь id↔цена** |
| `unit` | ДА | Excel + кеш |
| `work_price`/`material_price` | ДА | Excel + кеш |
| `sources` | ДА | Excel «Примечание» + кеш |
| `quantity` | **НЕТ** | нигде (Excel берёт оригинал) |
| `price_list_name` | **НЕТ** | нигде (хардкод "Интернет") |
| `notes` (строка про НДС) | почти НЕТ | только fallback Excel-примечания, когда sources пуст (≈никогда, т.к. sources обязателен) |

## Выводы
1. **`quantity` и `price_list_name`** в ответе — чистый балласт. Убрать из требуемой схемы безопасно.
2. **`notes`** (обязательная фраза «Цена без НДС: X ₽ / Цена с НДС: Z ₽» на каждую позицию) — практически не показывается сметчику (Excel-примечание берёт `sources`). Это основная «вода».
   - НО: написание этой фразы служит **само-проверкой НДС** — заставляет ИИ реально поделить на 1.22. Полное удаление несёт риск, что ИИ станет менее аккуратен с НДС → цена с НДС попадёт в смету → **финансовая ошибка на тендере** (нарушение принципа «корректность важнее»).
3. **`name`, `type`** убирать НЕЛЬЗЯ — используются для кеша; `name` вдобавок якорь против рассинхрона id↔цена.
4. **3 источника (`sources`)** оставляем по решению пользователя — это и есть Excel-примечание.

## Рекомендация
Безопасный набор правок:
- Убрать `quantity` и `price_list_name` из требуемого JSON-ответа.
- Сжать `notes`: сохранить ПРАВИЛО «цены всегда без НДС, при необходимости делить на 1.22», но заменить обязательную развёрнутую фразу на **короткую пометку только когда НДС реально вычитался** (иначе пусто). Это убирает балласт, но сохраняет НДС-самопроверку там, где она важна.
- Ужать текстовые инструкции промпта (описание формата) — тоже output? нет, промпт это input/cache; второстепенно, но чистит.

Единственная реальная развилка для пользователя: **насколько агрессивно резать `notes`** (полностью убрать ради макс. экономии vs. оставить короткую НДС-пометку ради корректности). Требует решения — влияет на корректность цен.

## Ожидаемый эффект
Скромный: output ≈18% стоимости, режем малую его часть → ориентир −3–7% к счёту сметы. Риск — низкий при сохранении НДС-пометки.
