## Оценка текущего состояния промптов

### Сильные стороны (что уже хорошо)
- Детальная нормативная база (ГЭСН-2017, ФСНБ-2022, ФЕР/ТЕР)
- Структурированные JSON-схемы в промптах
- Batch-обработка для больших смет
- Retry-логика и web_search для поиска цен
- Контекстные примечания в notes-полях

### Слабые стороны (что нужно проработать)
- **Нет технических спеков** для каждого типа: что считается успешным результатом
- **Нет тест-кейсов** — невозможно верифицировать качество без эталонных входных/выходных данных
- **Промпты не версионированы** — нельзя откатиться к рабочей версии
- **Промпты смешаны с кодом** — трудно редактировать и тестировать изолированно
- **Нет метрик качества** — неизвестно, насколько точно Claude распознаёт конкретный тип документа

## Рекомендация по приоритету типов задач

Исходя из бизнес-задачи (быстро "перебивать" чужие сметы в корпоративный формат):

1. **SCAN_TO_EXCEL** — самый частый кейс, скан чужой сметы → Excel
2. **LIST_FROM_TZ** — базовый кейс: ТЗ → перечень
3. **SMETA_FROM_LIST** — расценивание перечня: занимает больше всего времени вручную
4. **SMETA_FROM_TZ** — быстрый путь ТЗ → смета
5. **COMPARE_PROJECT_SMETA** — верификация: проект vs смета
6. **LIST_FROM_PROJECT** — работа с проектной документацией
7. **SMETA_FROM_PROJECT** — полный цикл из проекта
8. **RESEARCH_PROJECT** — аудит документации
9. **LIST_FROM_TZ_PROJECT** — ТЗ + проект
10. **SMETA_FROM_TZ_PROJECT** — ТЗ + проект → смета
11. **SMETA_FROM_EDC_PROJECT** — ЭДЦ (редкий кейс)
12. **SMETA_FROM_GRAND_PROJECT** — Гранд-формат
13. **OPTIMIZE_SMETA** — оптимизация цен

## Вывод

Текущая архитектура **звуковая**: FastAPI + async PostgreSQL + Claude API, batch-обработка, retry-логика — всё на месте.

Главная проблема: **нет инфраструктуры качества** — ни спеков, ни тест-кейсов, ни версионирования промптов. Промпты написаны с нуля без итеративного тестирования.

**Оптимальная стратегия:** проходить по одному типу задачи, создавать спек + тест-кейсы, рефайнить промпт до приемлемого качества, фиксировать — и только потом переходить к следующему.
