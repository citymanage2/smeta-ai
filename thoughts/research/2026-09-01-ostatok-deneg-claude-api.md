# Исследование: остаток денег на Claude API в реальном времени

Дата: 01.09.2026. Задача размера M (bulletproof, стадия 1).

## Вопрос

Можно ли показывать в сервисе поле «сколько денег осталось на Claude API»,
обновляющееся в реальном времени.

## Что отдаёт Anthropic

| Что | Есть | Детали |
|---|---|---|
| Остаток кредитов / баланс | **Нет** | Эндпоинта не существует ни в SDK, ни в Admin API, ни в Console API. Проверено по `shared/admin-api.md` (skill claude-api, обновление 26.08.2026) и по live-документации Usage & Cost API |
| Сколько потрачено (Cost API) | Да | `GET /v1/organizations/cost_report`, бакеты **только по дням**, суммы в USD, задержка ~5 мин |
| Сколько токенов (Usage API) | Да | `GET /v1/organizations/usage_report/messages`, бакеты 1m/1h/1d |
| Жив ли счёт | Косвенно | Ошибка `credit balance` на реальном вызове. Уже используется: `admin.api_health` |

Ограничения обоих отчётов:
- **Не в SDK.** Только raw HTTP (`httpx`), заголовки `x-api-key` + `anthropic-version: 2023-06-01`.
- **Отдельный ключ** `sk-ant-admin01-...`, создаётся в Console. Рабочий ключ сервиса не подходит.
- **Только для организации.** На индивидуальном аккаунте Admin API не работает вовсе.
- Полить не чаще раза в минуту. Данные появляются «обычно в течение 5 минут, иногда дольше».
- Priority Tier в cost_report не попадает (мы им не пользуемся — не наш случай).

**Вывод по API: «остаток» не отдаёт никто. Сумму пополнения знает только человек,
который платил.** Любая реализация обязана иметь ручной ввод пополнений — это не
недоделка, а свойство предметной области.

## Что уже есть у нас

- `api_call_log` — строка на каждый вызов ИИ: токены, кеш, web-поиски, батч,
  `cost_usd`, признак «допа». Считается на месте вызова, в реальном времени.
- `dashboard.api_costs` — затраты за сегодня/неделю/месяц из этого же лога,
  блок «Расходы на API» на странице «Система».
- `api_health` — пробный вызов «деньги есть?», `resume_poller` — авто-возобновление
  задач после пополнения, `SystemEvent(balance_restored)` — уведомление.
- Прод ходит в Anthropic через свой прокси в ЕС (`ANTHROPIC_BASE_URL`) на настоящем
  Anthropic-ключе — биллинг наш, значит Admin API применим (в отличие от агрегатора).

То есть половина работы уже сделана: «сколько потрачено» считается мгновенно.
Не хватает только «сколько было» и сверки с официальными данными.

## Найденная ошибка в текущем расчёте (блокирует задачу)

`claude_service._COST_PER_TOKEN` считает `claude-sonnet-5` по $3/$15 за 1M с
комментарием: «до 31.08.2026 вводная цена $2/$10 — считаем по будущей, чтобы не
занизить». Срок вышел вчера, и официальный прайс сегодня говорит прямо:

> The $2/$10 pricing for Claude Sonnet 5, announced as introductory pricing through
> August 31, 2026, **is now the standard price. The previously scheduled increase to
> $3/$15 on September 1, 2026 will not occur.**

Актуальные цены Sonnet 5: вход $2, выход $10, запись кеша 5m $2.50, чтение кеша
$0.20 за 1M. У нас зашиты 3 / 15 / 3.75 / 0.30 — **завышение ровно в 1.5 раза по
всем четырём категориям.** Пока это был информационный дашборд, завышение было
безопасной страховкой. Под полем «остаток» оно превращается в постоянно убегающую
вниз цифру: сервис будет считать, что денег на треть меньше, чем есть.

Исправление прайса — обязательная первая фаза, а не сопутствующая уборка.

## Как считать остаток: сравнение подходов

**A. Только свой лог.** Остаток = пополнения − Σ`api_call_log.cost_usd`.
+ Работает без админ-ключа и без организации, мгновенно.
− Копит ошибку прайса вечно: любое расхождение с реальным биллингом никогда не
  исправляется, за месяцы набегает.

**B. Только cost_report.** Остаток = пополнения − официальные траты.
+ Точно до цента.
− Не «в реальном времени»: дневные бакеты + задержка. Смета за $10, посчитанная
  минуту назад, в цифре не видна — а это ровно тот момент, когда на неё смотрят.
− Не работает без админ-ключа: без него поля просто нет.

**C. Гибрид (выбран).** Закрытые дни — из cost_report, текущий день — из своего лога.
+ База точна до цента, хвост мгновенен.
+ Ошибка прайса ограничена расходом одного дня и обнуляется на следующий день,
  когда день закрывается и перезаписывается официальной цифрой.
+ Без админ-ключа деградирует до варианта A и продолжает работать.
− Нужна фоновая синхронизация и таблица дней.

Граница между источниками — **начало текущего дня UTC**, а не «now − 15 минут».
Гадать о свежести бакета нельзя (документация обещает 5 минут и честно
предупреждает, что бывает дольше), а ошибка в границе означает двойной учёт или
потерю трат. Детерминированная граница исключает и то, и другое.

Вчерашний день может дозаполняться после полуночи, поэтому синхронизация
перезаписывает последние 3 дня целиком (upsert по дате) — идемпотентно.

## Вывод

Делаем гибрид: таблица пополнений (ручной ввод) + таблица официальных дневных
трат (синхронизация раз в час) + хвост текущего дня из `api_call_log`.
Первой фазой — исправление прайса, без него любая цифра остатка неверна.
