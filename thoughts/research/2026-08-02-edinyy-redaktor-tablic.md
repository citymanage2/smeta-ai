### Два источника правды по смете (критично)

Для одной задачи `ESTIMATE_FROM_LIST` данные живут одновременно в:

| Хранилище | Кто пишет | Что делает при записи |
|---|---|---|
| `task.progress_data['items']` | `PATCH /tasks/{id}/estimate-items` (`tasks.py:1840`) | пересобирает xlsx в слот `estimate`, обновляет `task.cost` |
| `EstimateVersion(file_slot='estimate').rows` | `PUT /tasks/{id}/estimate/versions/{vid}/rows` (`estimate_versions.py:175`) | xlsx **не** пересобирает (регенерация только для LIST/COMPLETENESS), `task.cost` не трогает |

Правки расходятся молча. Пользователь может видеть три разных числа: на странице задачи, в редакторе и в скачанном файле.

## Паттерны кодовой базы

- **Frontend:** React 18 + TS, Vite, Zustand (сторы `stores/*.ts`), Axios (`api/*.ts`), стили — inline `style={{}}` и точечные `.css` рядом с компонентом. Роуты лениво грузятся через `lazy()` в `App.tsx`. Тесты — vitest + @testing-library.
- **Backend:** FastAPI, SQLAlchemy 2.0 async, роутеры `routers/*.py`, фоновая работа через `job_queue`, файлы через `storage_service` (S3 Timeweb), логи через structlog.
- **Правило проекта:** любое изменение `models/*.py` → миграция `alembic/versions/0NN_*.py` c `IF NOT EXISTS`. Последняя — `041_add_task_timing_and_volume.py`, следующая **042**.
- **RBAC:** `utils/permissions.py`, `can_access(owner_id, current_user, is_shared)`; роли `admin` / `head_of_sales` / `project_manager`.

## Риски и ограничения

| Риск | Суть | Митигация |
|---|---|---|
| **Расхождение данных при миграции сметы** | у смет, которые правили и в inline-таблице, и в редакторе, два разных состояния | dry-run отчёт по всем сметам с расхождениями до миграции; выбор победителя по `updated_at`; ручной разбор конфликтов; активные тендеры — по команде пользователя |
| **react-data-grid не умеет multi-cell paste** | подтверждено по `node_modules/react-data-grid/lib/index.d.ts:289` — `PasteEvent` содержит только `sourceRow/targetRow` (одна ячейка). Внешняя вставка из Excel не поддержана | пишем свой слой буфера: `paste`-слушатель на контейнере + якорь из `onSelectedCellChange` + разбор TSV → пакет обновлений строк |
| **Бета-версия грида** | `7.0.0-beta.47`, API может меняться | версия зафиксирована точно (без `^`) — уже так; апгрейд только осознанно |
| **Производительность 2000 строк** | у `EstimateGrid` виртуализация встроена, у `GenericGrid` — самописная | ядро на react-data-grid = виртуализация из коробки; бенчмарк-тест на 2000 строк в гейтах |
| **Стоимость «Найти аналоги»** | веб-поиск — основная статья расходов (смета ~$10, 68% — веб-поиск) | обязательное подтверждение с оценкой числа позиций; учёт в существующем лимите веб-поиска; выполнение через очередь, а не синхронно |
| **Прайс общий на всех** | любой менеджер может записать кривую цену | запись в псевдо-подрядчика «Из смет» (не смешивается с настоящими прайсами), нормализация ед. изм., лог в истории |
| **Потеря оригинала заказчика** | сейчас сохранение перечня перезаписывает и входной файл (`estimate_versions.py:212-229`) | входные файлы переводим в режим «только чтение» — решение пользователя (7.4) |
| **Одновременное редактирование** | сейчас тихая перезапись | `rev` у документа + баннер присутствия; при расхождении `rev` — 409 и предложение перезагрузить |
| **Объединение страниц ломает ссылки** | `/tasks/:id/status` в уведомлениях, письмах, закладках | старый роут остаётся и редиректит на страницу карточки с нужным этапом |

## Найденные best practices (WebSearch)

1. **react-data-grid и буфер обмена.** Мультиячеечное выделение и вставка из внешних источников в react-data-grid не поддержаны; сообщество решает это собственными обработчиками `copy`/`paste` поверх грида. Подтверждено и по установленным типам: `PasteEvent` работает с одной ячейкой. Вывод: слой буфера пишем сами, это ~150 строк и покрывается тестами.
2. **Трёхслойная архитектура сложных UI-примитивов** (ядро-редьюсер → headless-хук → компонент): ядро содержит чистую логику переходов состояния и ничего не знает про DOM, хук адаптирует её под React, компонент даёт API. Это ровно то, что нужно для «одна оболочка — два типа данных».
3. **Альтернативы с готовым буфером обмена платные:** AG Grid Enterprise (~$1000/разработчика в год), MUI X Premium (~$588), Syncfusion, Handsontable. Для внутреннего инструмента на 3-5 человек платить за одну функцию неоправданно.

## Вывод и рекомендация

**Рекомендуемый подход:** трёхслойный единый редактор.

```
┌─ DocumentEditor (оболочка) ──────────────────────────────┐
│  тулбар · поиск · вкладки · выделение · undo/redo        │
│  черновик+Применить · история · присутствие · ⛶          │
│  ┌─ адаптер документа ────────────────────────────────┐  │
│  │  generic (перечень, полнота)                       │  │
│  │  estimate (смета, оптимизация, разделы сводной)    │  │
│  │  колонки · валидация · пересчёт · доступные действия│ │
│  └────────────────────────────────────────────────────┘  │
│  ┌─ react-data-grid (отрисовка) + свой слой буфера ───┐  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

**Ключевые причины:**

1. **Не выбрасываем работающее.** `EstimateGrid` на react-data-grid уже умеет 90% требуемого списка (редактирование, Tab/стрелки, перетаскивание, виртуализация, ABC, отрицательный объём, связка работа→материалы). Самописная таблица `GenericGrid` не умеет ничего из этого и её проще удалить, чем дотягивать.
2. **Разный функционал у типов — это требование, а не проблема.** Слой адаптера ровно для этого: одна оболочка, разный набор колонок и разрешённых действий. Решение пользователя №2 и №7 ложатся в архитектуру напрямую.
3. **Бесплатно и без вендор-лока.** MIT-лицензия, единственная недостающая функция (мультиячеечный буфер) пишется сами за один заход и покрывается тестами.

**Отклонённые варианты:**

- **Fortune-Sheet как основной редактор** — работает с файлом, а не с данными; вся умная логика сметы (связь работа→материалы, пересчёт объёмов, ABC, проверки) на свободных ячейках не воспроизводится. Остаётся тестовой вкладкой в админке (решение 23).
- **Единый плоский формат для всех** — уничтожает умные функции сметы. Отклонено пользователем (решение 7 = вариант Б).
- **Платный грид (AG Grid Enterprise / MUI Premium)** — $600-1000 в год за одну функцию буфера обмена для внутреннего инструмента на несколько человек.
- **TanStack Table (headless)** — пришлось бы писать заново виртуализацию, редактирование ячеек и навигацию, которые в react-data-grid уже есть и уже работают в проде проекта.

**За чем следить:**

- миграция данных сметы — единственное необратимое действие во всём проекте, делать с dry-run и бэкапом;
- слой буфера обмена — тонкое место, тесты обязательны (вставка меньше/больше выделения, нечисловые значения, вставка в нередактируемую колонку);
- бюджет на «Найти аналоги» — без ограничителя легко улететь в деньги;
- переходный период: старый и новый редактор параллельно — следить, чтобы оба не писали в одно место одновременно.
