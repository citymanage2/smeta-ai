<objective>
Fix admin role display bug (BUG-03) by updating _initialize_users to sync password hashes with current environment variables on every startup.

Purpose: The admin user was created during a previous deployment with a different ADMIN_PASSWORD. The `_initialize_users` function only creates users if they don't exist — it never updates password hashes. When the admin enters their current password, it doesn't match the stale admin hash, so login falls through to the "user" role (which may match), returning role="user" instead of role="admin". The UI then displays "Пользователь" instead of "Администратор".

Output: Updated _initialize_users in main.py that checks and updates password hashes on every startup.
</objective>

```python
def hash_password(password: str) -> str:
    return bcrypt.hashpw(password.encode(), bcrypt.gensalt(rounds=12)).decode()

def verify_password(plain_password: str, hashed_password: str) -> bool:
    return bcrypt.checkpw(plain_password.encode(), hashed_password.encode())
```

**Step 2: Replace the `_initialize_users` function (lines 33-47) with:**

```python
async def _initialize_users() -> None:
    """Create or update default user and admin accounts.

    If a user for a role already exists but the password hash doesn't match
    the current environment variable, update the hash. This ensures password
    changes via env vars take effect after redeployment.
    """
    async with AsyncSessionLocal() as db:
        for role, password in [("user", settings.USER_PASSWORD), ("admin", settings.ADMIN_PASSWORD)]:
            result = await db.execute(select(User).where(User.role == role))
            existing = result.scalar_one_or_none()
            if not existing:
                user = User(
                    role=role,
                    password_hash=hash_password(password),
                )
                db.add(user)
                logger.info("Created default user", role=role)
            else:
                # Update password hash if env var changed since last deploy
                if not verify_password(password, existing.password_hash):
                    existing.password_hash = hash_password(password)
                    logger.info("Updated password hash for user", role=role)

        await db.commit()
```

The key change is the `else` branch: when a user for a given role already exists, it checks whether the current env var password matches the stored hash. If not, it re-hashes and updates. This runs on every startup (via the `lifespan` function), so any Render redeploy with a new `ADMIN_PASSWORD` env var will automatically update the stored hash.

**Why this fixes BUG-03:** After this change, when the backend starts on Render, it will detect that the admin user's stored hash doesn't match the current `ADMIN_PASSWORD` env var, re-hash it, and update the database. The next login with the admin password will match the admin role, and the backend will return `role: "admin"` — which the frontend auth flow correctly propagates to the UI as "Администратор".

**Do NOT modify any other function or code in main.py.** The lifespan function, create_app, error handlers, routes — all stay exactly as they are.
