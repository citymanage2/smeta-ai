**Header:**
```markdown
# E2E Post-Deployment Verification Checklist

**Purpose:** Step-by-step manual verification of all critical user flows after deployment.
**When to use:** After every production deployment or environment change.
**Prerequisites:** Access to the deployed frontend URL and backend URL. Know the user password and admin password (from environment variables USER_PASSWORD and ADMIN_PASSWORD).
```

**Section 1: Environment Verification**
- Step 1.1: Open `{BACKEND_URL}/health` in browser. Expected: JSON `{"status": "ok", "service": "Smeta AI"}`
- Step 1.2: Open `{FRONTEND_URL}` in browser. Expected: Login page loads, no console errors
- Step 1.3: Open `{FRONTEND_URL}/admin` directly in browser (not navigating from login). Expected: Redirected to login page (SPA routing works, no "Not Found")

**Section 2: User Authentication**
- Step 2.1: On login page, enter the user password and click login. Expected: Redirects to task creation page, role indicator shows "Пользователь"
- Step 2.2: Open browser DevTools > Application > Local Storage. Expected: auth token is stored
- Step 2.3: Refresh the page. Expected: Still on task creation page (session persists)
- Step 2.4: Log out (if logout button exists) or clear localStorage and refresh. Expected: Redirected to login page

**Section 3: Admin Authentication**
- Step 3.1: On login page, enter the admin password and click login. Expected: Redirects to admin panel or task creation, role indicator shows "Администратор" (NOT "Пользователь")
- Step 3.2: Navigate to `/admin`. Expected: Admin panel loads with task history table

**Section 4: Task Creation and Processing**
- Step 4.1: Log in as user. Navigate to task creation
- Step 4.2: Select task type "Список работ из ТЗ" (LIST_FROM_TZ)
- Step 4.3: Upload a small PDF file (any construction document)
- Step 4.4: Click submit. Expected: Navigates to task status page, shows task ID in URL
- Step 4.5: Watch status polling. Expected: Progress messages appear (e.g., "Анализ документов..."), status changes from "pending" to "processing" to "completed" or "failed"
- Step 4.6: If completed: download button appears. Click to download result file. Expected: Excel file downloads successfully, contains data (not empty)

**Section 5: Task Status Polling**
- Step 5.1: Open browser DevTools > Network tab during task processing
- Step 5.2: Verify polling requests go to `{BACKEND_URL}/tasks/{taskId}/status`
- Step 5.3: Verify responses return 200 (not 404) and contain `status`, `progress_message` fields

**Section 6: Result Download**
- Step 6.1: After a task completes, click the download button
- Step 6.2: Expected: File downloads with correct filename (Russian characters handled)
- Step 6.3: Open the downloaded file. Expected: Contains generated data (not empty/corrupt)

**Section 7: Admin Panel - Task History**
- Step 7.1: Log in as admin, navigate to `/admin`
- Step 7.2: Expected: Table shows all tasks with columns for date, task type, status
- Step 7.3: Verify pagination works: if more than 20 tasks exist, next page button should work
- Step 7.4: Click on a task row to expand details. Expected: Shows conversation transcript (chat_history)

**Section 8: Admin Panel - File Downloads**
- Step 8.1: In admin task history, find a completed task
- Step 8.2: Click to re-download the original uploaded file. Expected: Original file downloads correctly
- Step 8.3: Click to download the result file. Expected: Generated result downloads correctly

**Section 9: Error Handling**
- Step 9.1: Try to log in with wrong password. Expected: Error message "Неверный пароль" appears
- Step 9.2: Try to upload a .gsn file. Expected: Error message about unsupported format
- Step 9.3: Navigate to a non-existent task status URL (e.g., `/task/nonexistent/status`). Expected: Graceful error, not a crash

**Section 10: Cross-Browser / Edge Cases**
- Step 10.1: Test login flow in Chrome and Firefox
- Step 10.2: Test file upload with a large file (near 20MB limit)
- Step 10.3: Verify the app works on mobile viewport (responsive layout)
