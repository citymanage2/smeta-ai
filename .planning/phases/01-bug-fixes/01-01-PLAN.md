**Fix 1 — client.ts: Use VITE_API_BASE_URL env var for production API routing.**

The current `baseURL: '/api'` only works in dev because Vite proxies `/api` to `http://localhost:8000` and strips the `/api` prefix. In Render production, frontend and backend are separate services on different domains. API calls to `/api/tasks` hit the static site and get served `index.html` (due to the `/* /index.html 200` rewrite rule).

Replace the hardcoded `baseURL` in `client.ts` with:

```typescript
const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api',
  headers: {
    'Content-Type': 'application/json',
  },
});
```

This way:
- In dev: `VITE_API_BASE_URL` is not set, falls back to `/api`, Vite proxy handles it
- In production: `VITE_API_BASE_URL` is set to the backend service URL (e.g., `https://smeta-ai-backend.onrender.com`) in Render dashboard environment variables for the frontend build

The rest of client.ts (interceptors) stays unchanged.

**Fix 2 — TaskCreate.tsx: Guard against undefined task_id before navigation.**

In the `handleSubmit` function, after `const task = await createTask(...)`, add an explicit check before navigating:

After line `const task = await createTask(formData, (pct) => { ... });` and before `navigate(...)`, add:

```typescript
if (!task.task_id) {
  setError('Задача создана, но ID не получен. Попробуйте обновить страницу.');

}
```

This prevents the scenario where `task.task_id` is undefined/null/empty, which would cause navigation to `/task/undefined/status` and trigger the guard redirect back to `/task/create` (appearing as a "form reset").
