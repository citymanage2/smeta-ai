## Следующий шаг — Фаза 4

**Задача:** перечень из Гранд-сметы разбирается с мусорной первой строкой вида `2 / 3 / 1 / 4 / 5 / 6` — это строка нумерации колонок исходника, принятая за данные. Парсер берёт заголовками ровно первую строку файла (`backend/app/utils/xlsx_generic.py:22`), а в Гранд-смете шапка занимает две-три строки.

**Что сделать:**
- определять границу шапки: строка из одних последовательных номеров колонок в данные не попадает, многострочные заголовки склеиваются в одно название колонки;
- **обязателен регресс** на однострочных шапках: перечни, разобранные старым парсером, не должны «съехать»;
- проверить на реальных xlsx.

**Файлы:** `backend/app/utils/xlsx_generic.py`, новый `backend/tests/test_xlsx_generic_headers.py`, при необходимости `frontend/src/components/editor/adapters/genericAdapter.ts`.

Полный промпт запуска — в плане, раздел «Фаза 4».

## Принятые решения (не пересматривать без пользователя)

1. **Работаем с данными, не с файлом.** Fortune-Sheet отклонён как основной редактор: умная логика сметы на свободных ячейках не воспроизводится. Он остаётся тестовой вкладкой в админке — не трогать.
2. **Два формата данных под одной оболочкой.** Сводить перечень и смету в один плоский формат нельзя — потеряются связь работа→материалы, пересчёт объёмов, ABC, отрицательный объём.
3. **Платный грид не берём.** AG Grid Enterprise / MUI Premium — $600–1000 в год за буфер обмена; свой слой ~150 строк с тестами.
4. **Автосохранение в черновик + явная кнопка «Применить»** — для сметы важна осознанность.
5. **Входной файл заказчика неприкосновенен** (решение 7.4 пользователя).
6. **Присутствие не блокирует сохранение** — предупреждает; от затирания защищает `rev`.
7. **Менеджер правит только свои документы, руководитель отдела продаж — любые.** Смету на тендере не блокируем.
8. **Порядок подключения типов:** перечень → полнота → смета → оптимизация → сводная.
9. **Старый редактор держим параллельно** там, где он ещё нужен (смета, оптимизация — до Фаз 5–6).
10. **Глубина истории ограничена** (20 записей, снимки у 10): снимок весит столько же, сколько документ.

## Правила проекта, о которых легко забыть

- Любое изменение `backend/app/models/*.py` → **сначала** миграция `alembic/versions/0NN_*.py` с `IF NOT EXISTS`, потом коммит. Следующий номер — **043**.
- План в `plans/` актуализировать после каждой сессии: статусы фаз `[ ]`/`[x]`, Changelog, отклонения, блок «Итог».
- В конце сессии — рефлексия в `.business/история/YYYY-MM-DD-краткое-название.md` (папка не в git).
- Коммит после каждой завершённой задачи, осмысленным сообщением.
- Отвечать пользователю **на русском**. Пользователь не разработчик: объяснять простым языком, диагностику давать кнопкой в интерфейсе, а не командой в терминале.
- Деплой — только по явной команде пользователя.
