# 3. Правила работы

> Версия документа: 1.0 | Дата: 2026-05-22

---

## 3.1 Общие правила

### Один тендер — один проект

Для каждого тендера создавайте отдельный проект. Не смешивайте задачи по разным тендерам в одном проекте — это затрудняет поиск и контроль.

### Как называть проект

Название должно однозначно идентифицировать тендер. Свободная форма — главное, чтобы через неделю было понятно, о чём речь.

**Хорошо:**
- «ООО Альфа — благоустройство ул. Ленина, май 2026»
- «МКУ ДЕЗ — капремонт кровли ул. Садовая 12»

**Плохо:**
- «Тендер 1»
- «Смета»
- «Новый проект»

### Ответственность за результат

Сервис — вспомогательный инструмент. **Финальную ответственность за корректность сметы несёт менеджер**, подписывающий её передачу руководителю, и **руководитель отдела**, давший согласование на отправку заказчику.

### Обязательное согласование

Перед отправкой сметы заказчику — **обязательно передайте её руководителю отдела**. Самостоятельная отправка без согласования не допускается.

## 3.2 Правила работы с задачами

### Поддерживаемые форматы файлов

| Тип задачи | Принимаемые форматы |
|---|---|
| Перечень из Гранд-Сметы | `.xlsx`, `.xls`, `.xml`, `.pdf` |
| Перечень из проекта | `.pdf` |
| Смета из перечня | `.xlsx` |
| Оптимизация сметы | `.xlsx` |

> **Ограничения:** максимум 10 файлов за один раз, не более 20 МБ на файл.
> Формат `.gsn` (файлы Гранд-Сметы) **не поддерживается** — предварительно экспортируйте из Гранд-Сметы в `.xlsx` или `.xml`.

### Как готовить файлы к загрузке

- Если Гранд-Смета в формате `.gsn` — откройте её в программе Гранд-Смета и экспортируйте в Excel или XML перед загрузкой.
- Если PDF-файл — скан плохого качества, результат может быть неточным. По возможности используйте текстовый PDF.
- Если в Excel объединённые ячейки в нестандартных местах — возможны ошибки при парсинге.

### Статусы задач

| Статус | Что означает |
|---|---|
| Ожидание | Задача поставлена в очередь |
| Обрабатывается | ИИ работает с файлом |
| Готово | Результат доступен для просмотра и скачивания |
| Ошибка | Задача не выполнена — см. раздел [5. Поддержка](05-поддержка.md) |
| Отменено | Задача остановлена пользователем |

### Если позиции в результате неверны

Если после просмотра результата видите явные ошибки — не отправляйте смету. Действуйте так:

1. Проверьте исходный файл — возможно, там нестандартная структура.
2. Сообщите бизнес-ассистенту с описанием проблемы и примером некорректной позиции.
3. При необходимости откорректируйте вручную в редакторе оптимизации или в скачанном Excel.

## 3.3 Работа в проектах

### Структура задач внутри проекта

Задачи в проекте идут по цепочке:

```
Перечень (из Гранд-Сметы или из проекта)
    → Проверка полноты
        → Смета из перечня
            → Оптимизация (по необходимости)
```

Каждая последующая задача подтягивает результат предыдущей автоматически — вам не нужно вручную переносить файлы между шагами.

### Работа с результатами

- Скачайте итоговый Excel (кнопка «Скачать»).
- Перенесите данные в корпоративный шаблон CityManage.
- Передайте руководителю на проверку.

## 3.4 Работа с ценами — что делать при отсутствии цены

Сервис ищет цены в три шага:
1. Точное совпадение с корпоративным прайсом
2. Поиск по смыслу (похожие наименования)
3. Запрос к ИИ для поиска рыночной цены по Екатеринбургу

Если позиция в результате **без цены** или с явно неверной ценой:

**Вариант А — обновить конкретную позицию:**
Нажмите на кнопку обновления цены рядом с позицией в таблице — сервис повторно запросит цену.

**Вариант Б — проставить все пропущенные цены:**
Используйте кнопку «Проставить пропущенные цены» — сервис попробует заполнить все позиции без цены.

**Вариант В — сообщить администратору:**
Если цена так и не нашлась или явно неверна — напишите бизнес-ассистенту. Он добавит позицию в корпоративный прайс. После добавления можно перезапустить шаг «Смета из перечня».

> Не вписывайте цены «от руки» в сервисе без согласования — некорректные данные попадут в базу.

## 3.5 Обязанности сотрудников

Все сотрудники, работающие с Сервисом смет, обязаны:

- **Сообщать бизнес-ассистенту** о найденных ошибках в работе сервиса (некорректно извлечённые позиции, неверные цены, зависшие задачи).
- **Вносить предложения** по улучшению логики сервиса — если видите, что что-то можно сделать лучше, напишите бизнес-ассистенту.
- **Передавать смету на проверку** руководителю отдела перед каждой отправкой заказчику.
- **Не передавать учётные данные** другим сотрудникам.
