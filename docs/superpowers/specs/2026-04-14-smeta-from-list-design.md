# Дизайн: Смета из перечня + вспомогательные улучшения

**Дата:** 2026-04-14  
**Статус:** утверждён  
**Затронутые компоненты:** backend, frontend, plans/

---

## Scope

Три независимых блока изменений:

1. **Отображение исходного файла** в каждой задаче (TaskStatus)
2. **Автоименование задач** по имени исходного файла
3. **Новый тип задачи: Смета из перечня** (`ESTIMATE_FROM_LIST`)

---

## Блок 1 — Отображение исходного файла

### Проблема
На странице задачи (`TaskStatus`) нигде не показывается, из какого файла сделана задача. При 10 задачах одного типа пользователь не может понять, что в каждой.

### Решение
На странице `TaskStatus` добавляется секция **"Исходный файл"** (до результатов):
- Иконка файла (тип: PDF/Excel/etc)
- Имя файла
- Кнопка «Скачать»

**Backend:** новый endpoint `GET /tasks/{task_id}/input-file/{file_index}` — возвращает исходный файл из `task.input_file_data[file_index]` как binary download.

**Данные:** уже хранятся в `task.input_file_data` (список `{name, mime_type, size_bytes, content_b64}`). Нужно только отдать через API и отобразить на фронте.

---

## Блок 2 — Автоименование задач

### Проблема
Задачи называются только по типу: "Перечень из проекта" × 10 — невозможно различить.

### Решение
При создании задачи (`TaskCreate` форма на фронте):
1. Пользователь выбирает тип задачи и загружает файл(ы)
2. Сразу после выбора файла поле **"Название"** автоматически заполняется:
   ```
   [Метка типа задачи]: [имя первого файла без расширения]
   ```
   Пример: `Перечень из проекта: Школа_№5_РД`
3. Поле редактируемое — пользователь может изменить до отправки
4. Поле обязательное (нельзя оставить пустым)

**Backend:** при создании задачи `task.name` сохраняется из параметра формы `name`. Поле уже существует в модели Task.

## Блок 3 — Смета из перечня (`ESTIMATE_FROM_LIST`)

### 3.1 Создание задачи — два пути ввода

#### Путь А: загрузить файл
Пользователь загружает Excel-файл с перечнем.  
Из файла парсится **только лист "Перечень"** (нечувствительно к регистру, также принимаются "Перечень работ", "перечень" и т.п.). Если лист не найден — ошибка с понятным сообщением.

#### Путь Б: выбрать из существующих задач
1. Пользователь выбирает задачу типа `LIST_FROM_GRAND` или `LIST_FROM_PROJECT` (только завершённые, `status = "completed"`)
2. Система показывает доступные стадии:
   - **Стадия 1**: исходный перечень (файл результата исходной задачи)
   - **Стадия 2**: перечень после проверки полноты (если соответствующая задача `CHECK_LIST_COMPLETENESS` / `CHECK_PROJECT_COMPLETENESS` выполнена)
3. Пользователь выбирает стадию
4. Данные items берутся из `progress_data["items"]` выбранной задачи (не из файла — из JSON в БД)

**UI:** в форме создания задачи — переключатель "Загрузить файл / Из существующей задачи". При выборе Б: список задач → список доступных стадий.

### 3.2 Обработка на бэкенде

#### Шаг 0 — Подготовка данных
- Путь А: парсинг листа "Перечень" из Excel → список items `{type, name, unit, quantity}`
- Путь Б: items берутся из `progress_data["items"]` выбранной задачи и стадии

#### Шаг 1 — Поиск цен по прайсу (без Claude)
Для каждой позиции по очереди:
1. **Точное совпадение** (`_exact_match_work` / `_exact_match_material`) — normalised string comparison
2. **Embedding-поиск** (`_embedding_match_work` / `_embedding_match_material`) — cosine similarity ≥ 0.82

Используется существующий `price_service` (модули `price_service.py` + `embedding_service.py`).  
**Важно:** для ESTIMATE_FROM_LIST используем ТОЛЬКО шаги exact + embedding из price_service, без web search (шаг 3). Web search для ненайденных — через основной Claude-промпт ниже.

Результат: список matched (с ценой) + список unmatched (без цены).

#### Шаг 2 — Claude для ненайденных позиций
Если unmatched не пустой:
- Разбить на чанки по границам строк типа "Работа" (аналогично `CHECK_LIST_COMPLETENESS`)
- Каждый чанк → запрос к Claude с основным промптом (см. раздел Промпты)
- Claude ищет 3 актуальных цены в г. Екатеринбург, ставит среднюю, указывает источники
- Результаты объединяются

#### Шаг 3 — Сборка итогового результата
- Объединяем matched + результат Claude в исходном порядке
- Для каждой позиции вычисляем:
  - `work_cost = quantity × work_price` (если work_price != null)
  - `material_cost = quantity × material_price` (если material_price != null)
- Добавляем строки-итоги:
  - Сумма по работам = Σ work_cost
  - Сумма по материалам = Σ material_cost
  - Транспортные расходы = 3% от суммы материалов
  - Накладные расходы = 3% от суммы работ
  - **Итого по смете** = сумма всех
- Генерируем Excel с итоговой структурой
- Сохраняем итоговую сумму в `task.cost`
- `task.estimation_status` → `"estimated"`

### 3.3 Структура выходного Excel

Колонки позиций:

| Наименование | Ед. изм. | Кол-во | Цена работ | Стоимость работ | Цена матер. | Стоимость матер. | Из прайса | Источники | Примечания |
|---|---|---|---|---|---|---|---|---|---|

После последней строки — блок итогов:
```
Сумма по работам:       [число]
Накладные расходы 3%:   [число]
Сумма по материалам:    [число]
Транспортные расходы 3%:[число]
ИТОГО ПО СМЕТЕ:         [число]
```

### 3.4 Отображение в проекте

Задача типа `ESTIMATE_FROM_LIST` добавляется в `ESTIMATE_TASK_TYPES`.  
`task.cost` сохраняется автоматически → отображается в карточке задачи в проекте (как уже работает для других estimate-задач).

### 3.5 Пересчёт сметы (комбинированный Б+В)

#### Б — Редактирование ячеек без AI
На странице результата задачи: таблица с редактируемыми ячейками (цена работы, цена материала, количество).  
Изменение → автоматический пересчёт стоимостей и итогов на фронте (математически, без запроса к API).  
Кнопка «Сохранить изменения» → сохраняет обновлённый Excel в БД (PATCH endpoint).

#### В — Переопределить цену одной позиции (Claude)
Кнопка «Переопределить цену» у каждой строки.  
→ Только эта одна позиция уходит в Claude с мини-промптом.  
→ Claude возвращает новую цену + источники.  
→ Цена обновляется в таблице, пересчёт итогов на фронте.

### 3.6 UI-паттерны (как в существующих задачах)
- Кнопка «Стоп» (отмена задачи, `cancelTask`)
- `BatchProgressBar` с прогрессом чанков
- Кнопка «Очистить» / сброс задачи

## Промпты (утверждены)

### Промпт 1 — Основной (ненайденные позиции, чанк)

```
Ты — эксперт по строительному сметному делу в России.

Тебе переданы позиции перечня работ и материалов, для которых НЕ
найдено совпадений в корпоративном прайсе. Твоя задача — определить
рыночную цену для каждой позиции.

Текущая дата: {current_date}
Регион: г. Екатеринбург, Свердловская область

Для каждой позиции:
1. Найди 3 актуальных рыночных цены (г. Екатеринбург)
   - Для работ: квалифицированные подрядчики с лицензиями/допусками СРО
   - Для материалов: известные поставщики, нормальное качество
2. Поставь среднюю из трёх найденных цен
3. Укажи все 3 источника с ценами в поле sources
4. Цена работ → в поле work_price (если тип "Работа")
5. Цена материалов → в поле material_price (если тип "Материал")

НДС (22%): для каждой позиции укажи в notes:
  "Цена без НДС: X / НДС: Y / Цена с НДС: Z"
  Для работ на УСН: НДС = 0, указать "УСН, НДС не облагается"

Позиции для оценки:
{unmatched_items_json}

Верни результат СТРОГО в формате JSON, без markdown, первый символ {,
последний }:
{
  "items": [
    {
      "type": "Работа" | "Материал",
      "name": "Наименование позиции",
      "unit": "Ед. изм.",
      "quantity": число,
      "work_price": число или null,
      "material_price": число или null,
      "price_list_name": null,
      "sources": "Источник 1: цена; Источник 2: цена; Источник 3: цена",
      "notes": "Примечание по НДС"
    }
  ]
}
```
