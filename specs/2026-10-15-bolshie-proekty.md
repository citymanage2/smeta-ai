# Спецификация: проекты до 100 МБ — загрузка и обработка

Дата: 2026-10-15
Исследование: `thoughts/research/2026-10-15-bolshie-proekty.md`
План: `plans/2026-10-15-bolshie-proekty.md`

## Проблема

Проектная документация (ПД/РД одним PDF) часто больше 10 МБ, и такие проекты в
сервисе не проходят. Причины две. Первая — **обработка**: «Перечень из проекта»
рендерит каждый лист чертежа до 7500 px и прикладывает все листы к каждому
запросу в ИИ. Плотный лист A1 в таком виде весит 14,6 МБ при лимите Claude
10 МБ на картинку и 32 МБ на запрос, а больше 20 листов в запросе API не
принимает вовсе. Вторая — **загрузка**: на доске нет серверной проверки и
прогресса, на странице «Новая задача» лимит 20 МБ, а лимит прокси хостинга
неизвестен.

Третья — **разделы** (жалоба пользователя 15.10.2026: «пропускает разделы и
делает всё одним файлом»). Из нескольких приложенных PDF считается только
первый; раздел позиции пишется лишь в примечание, и перечень выходит одним
листом; одноимённая позиция второго раздела выбрасывается как дубль; упавшая
часть PDF (кроме первой) пропускается молча вместе со своими позициями.

## Цель

Менеджер загружает PDF проектной документации **до 100 МБ** с доски проекта или
со страницы «Новая задача» и получает перечень работ и материалов **по всем
разделам проекта, лист на раздел**. Проекты, которые сейчас считаются нормально,
считаются так же (кроме раскладки по разделам).

## Решения пользователя (15.10.2026)

| Вопрос | Решение |
|---|---|
| Потолок | До 100 МБ |
| Объём задачи | Загрузка **и** обработка |
| Симптом | Неизвестен — чиним оба места |
| Как разложить по разделам | Лист на раздел в одном файле и вкладки в редакторе (как сводная и перечень из гранд-сметы) |
| Сбой части PDF | Остановить и продолжить: задача останавливается с перечнем необработанных страниц, готовое сохранено, «Возобновить» продолжает с этой части |

## Сценарий

1. Менеджер на доске проекта создаёт карточку на этапе «Перечень», выбирает
   «Перечень из проекта» и прикладывает PDF на 60 МБ.
2. Видит процент загрузки, затем карточку в очереди.
3. Обработчик разбирает PDF: текстовые страницы — текстом, листы чертежей —
   картинками в разрешении, которое модель реально видит, пачками, которые
   проходят в лимиты запроса.
4. Менеджер получает перечень; пустые объёмы уточнены по листам, где их можно
   найти, остальные оставлены пустыми с причиной.

## Критерии приёмки

### Загрузка
- [ ] PDF «Перечня из проекта» до 100 МБ принимается с доски
      (`start-task`) и со страницы «Новая задача» (`POST /tasks`).
- [ ] Файл больше 100 МБ отклоняется **на сервере** (413) с понятным текстом, и
      сервер не читает его в память целиком (чтение с лимитом).
- [ ] На фронте больше 100 МБ отсекается до отправки с тем же текстом; лимит в
      одном месте (константа), подсказки показывают 100 МБ.
- [ ] Во время загрузки на доске виден процент; ошибка сервера показывается
      текстом сервера, а не общим «Не удалось создать задачу».
- [ ] Лимит проекта не зависит от `MAX_FILE_SIZE_MB` из панели хостинга
      (собственная константа, как у КП).
- [ ] Если прокси хостинга режет запросы меньше 100 МБ — файл доходит частями
      (см. «Замер прокси» в исследовании; решение фиксируется в плане).

### Обработка
- [ ] Лист чертежа рендерится не больше нативного разрешения модели: длинная
      сторона ≤ 2576 px и ≤ 4784 визуальных токенов (клетка 28×28). Закреплено
      тестом с точными числами для A1, A3, A4.
- [ ] Картинка больше 9 МБ в base64 перекодируется в JPEG (лимит API — 10 МБ).
- [ ] В одном запросе ≤ 20 картинок и ≤ 24 МБ base64 картинок. Закреплено тестом
      разбиения на пачки с точными числами.
- [ ] Все листы влезают в одну пачку → поведение прежнее: каждая текстовая часть
      идёт со всеми листами, проход 2 — со всеми листами, промпты прежние (кроме
      поля раздела — см. «Разделы»).
- [ ] Листов больше одной пачки → проход 1: текстовые части без картинок плюс по
      части на пачку листов; проход 2: по пачкам, с промптом, где «нужного листа
      нет среди переданных» — законный null, а не повод угадать.
- [ ] Позиция, найденная повторно с объёмом, заполняет пустой объём ранее
      найденной позиции с тем же именем и типом (иначе объём с чертежа теряется
      при дедупликации).
- [ ] Каждая картинка подписана номером страницы PDF.
- [ ] Рендер идёт в отдельном потоке (heartbeat не останавливается), листы
      хранятся во временной папке, а не в памяти; папка удаляется в любом исходе.
- [ ] Resume (пауза по балансу, перезапуск) продолжает с необработанной части
      прохода 1 и с необработанной пачки прохода 2.
- [ ] Обработчик читает из хранилища только PDF, по одному, без base64-копии
      всех файлов.

### Разделы
- [ ] Обрабатываются **все** PDF задачи по порядку загрузки, а не только первый.
      Файл другого формата не пропускается молча: его имя и причина («поддерживается
      только PDF») попадают в пояснительную записку перечня.
- [ ] У каждой позиции перечня есть раздел (поле строки `sheet`, правило №14):
      марка комплекта по штампу или заголовку («АР», «ОВ», «ЭОМ»). Позиция с
      пустым разделом наследует раздел предыдущей позиции того же файла —
      материал не отрывается от своей работы. Раздела нет и наследовать не от
      чего — лист «Прочее», а не потеря.
- [ ] Два и больше раздела → лист на раздел в xlsx и вкладка на раздел в
      редакторе. Раздел один или не найден ни один → прежний единственный лист
      «Перечень» со сводками «Работы» и «Материалы».
- [ ] Наименование раздела одно на весь проект: каждой следующей части
      передаются уже найденные разделы и раздел, которым закончилась предыдущая
      часть; совпадающие без учёта регистра и лишних пробелов наименования
      сводятся к первому написанию. **Разные марки не склеиваются** («ОВ» и
      «ОВиК» — два листа). Закреплено тестом с точными примерами.
- [ ] Дубль — это тот же **раздел**, имя и тип. Одноимённая позиция другого
      раздела остаётся отдельной строкой на своём листе. Исключение — одна и та
      же находка с чертежа (совпали имя, тип, единица и ненулевой объём) в
      разных разделах: это дубль, и он называется в пояснительной записке.
- [ ] Уточнение объёма в проходе 2 не меняет раздел позиции.
- [ ] Сбой любой части прохода 1 (после повторов) останавливает задачу с текстом,
      где названы часть, файл и страницы. Всё посчитанное до неё сохранено;
      «Возобновить» продолжает с этой части. Молчаливого пропуска части нет.
      Обрезанный по лимиту ответ не останавливает задачу — часть делится
      пополам. Отмена и таймаут остаются отменой и таймаутом.
- [ ] Кнопка «Возобновить» есть у упавшей задачи с сохранённым прогрессом — в
      панели карточки и на доске (сейчас только у паузы).
- [ ] «Полнота по проекту» сохраняет раздел: позиции ответа ИИ, в том числе
      дописанные материалы, получают лист своего чанка (как полнота по
      гранд-смете). Разделы доезжают до сметы.
- [ ] Перечни, посчитанные раньше, не меняются; раскладка по разделам появляется
      при пересчёте.

### Регрессия
- [ ] Весь набор бэкенда и фронта зелёный; существующие тесты resume
      `test_list_from_project_resume.py` проходят без правок смысла.

## Ограничения

- Лимиты Claude API: 32 МБ запрос, 10 МБ картинка, >20 картинок — ≤2000 px.
- Память обработчика: `WORKER_TASK_MEM_MB=400` на задачу.
- Heartbeat job: `JOB_VISIBILITY_TIMEOUT_S=900` — событийный цикл нельзя
  блокировать.
- Правило №2: входной файл заказчика не перезаписывается.

## Вне рамок

- Резка крупного листа на фрагменты для лучшей читаемости мелкого текста
  (качество распознавания чертежей — отдельная задача).
- Файлы «Проект»/«ТЗ» как контекст оптимизации (`_load_client_context`) и
  PDF гранд-сметы — другие пути, лимиты там прежние.
- Files API Anthropic.
- Распознавание проекта из картинок и сканов не в PDF (jpg, png), dwg, docx —
  такие файлы называются в пояснительной записке, но не считаются.
- Разведение уже посчитанных перечней по разделам без пересчёта.
