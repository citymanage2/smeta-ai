# Spec: эталонный прайс из сметы
**Date:** 2026-09-02
**Author:** пользователь (руководитель проекта)

## Проблема

Есть смета с ценами, которые в компании считаются верными. Сегодня залить их в
прайс можно только merge-импортом: цены подрядчиков по той же позиции остаются
рядом, а позиция, записанная в прайсе или в кеше веб-поиска под другим
названием, продолжает подставляться в расчёт. В результате «верная» цена не
единственная, и какая из них попадёт в смету — зависит от того, как ИИ напишет
наименование позиции.

## Цель

Один проход в Каталоге прайсов, после которого по позициям из файла в системе
остаётся **ровно одна цена — из файла**, а всё, что человек признал тем же
самым под другим написанием, удалено.

## Область

### Входит

1. Режим «эталон» у загрузки файла в Каталоге прайсов (рядом с «↑ Импорт»).
2. Разбор двух форматов:
   - файл сметы нашего формата — колонки «Тип», «Наименование», «Ед. изм.»,
     «Цена работы (за ед.)», «Цена материала (за ед.)»: работы и материалы
     берутся из одного файла, тип строки читается из колонки «Тип»;
   - простая таблица «Наименование / Ед. изм. / Цена» — тип задаётся селектом,
     как у нынешнего импорта.
3. **Предпросмотр до записи**: что будет добавлено, что переоценено, какие
   чужие цены будут стёрты (с именем подрядчика и числом), что пропущено и
   почему.
4. **Вытеснение** у совпавших по наименованию позиций:
   - работа: из `prices` удаляются все цены подрядчиков, остаётся одна запись
     `«Из смет»` с ценой из файла; `min_price` пересчитывается;
   - материал: `price` перезаписывается ценой из файла.
5. **Список возможных дублей** — позиции прайса и записи кеша веб-поиска,
   похожие по смыслу, но названные иначе. Показываются с наименованием, ценой,
   единицей, источником (прайс/кеш) и оценкой похожести.
6. **Удаление дублей только по галочке.** По умолчанию не отмечено ничего.
7. После применения — перезагрузка кеша прайса в памяти, чтобы расчёт видел
   новые цены сразу.

### Не входит

- Разбор ГРАНД-Сметы (базисные цены, НР/СП/ФОТ, материалы внутри расценки).
  Такой файл сначала прогоняется через систему обычным путём и выгружается в
  нашем формате.
- Кнопка в редакторе сметы — вход только через Каталог прайсов.
- Автоматическое удаление дублей без человека.
- Обучение системы на этих ценах, правила в промптах — см. правило №9.

## Критерии приёмки

- [ ] В Каталоге прайсов у загрузки файла есть режим «эталон»; обычный импорт
      работает ровно как раньше (merge, цены подрядчиков сохраняются).
- [ ] Файл сметы нашего формата разбирается целиком: работы и материалы из
      одного файла, по колонке «Тип».
- [ ] Предпросмотр ничего не меняет в базе: повторный вызов даёт тот же ответ.
- [ ] Предпросмотр показывает по каждой совпавшей позиции, какие именно цены
      будут стёрты — подрядчик и число.
- [ ] После применения у работы из файла в `prices` ровно один ключ — «Из смет»,
      и `min_price` равен цене из файла.
- [ ] После применения у материала из файла `price` равен цене из файла.
- [ ] Цена за «100 м2» в файле превращается в цену за «м2» — как в
      `price_bulk` (`unit_price_factor`).
- [ ] Позиция, у которой единица в файле **несводима** с единицей позиции
      прайса (мешок ↔ кг), не вытесняется; причина показана человеку.
- [ ] Дата «Цена от» двигается только у позиций, где цена реально изменилась
      (число, единица или состав цен); у остальных остаётся прежней.
- [ ] Дубли не удаляются, пока человек не отметил их галочками; отмеченные —
      удаляются, неотмеченные остаются нетронутыми.
- [ ] Список дублей включает записи кеша веб-поиска, помеченные как кеш.
- [ ] Если у прайса нет векторов, операция всё равно проходит: вытеснение по
      точным совпадениям работает, а в ответе честно сказано, что поиск дублей
      отключён.
- [ ] Позиция без наименования или без внятной цены не пишется и попадает в
      сводку «пропущено» с причиной.
- [ ] Файл сверх потолка позиций отклоняется с понятным сообщением, а не молча
      обрезается.
- [ ] Права: режим доступен тем же ролям, что и остальная работа с прайсами
      (менеджерские роли), рядовой менеджер проектов его не видит.

## Ограничения

- Правило №8 CLAUDE.md: единица — часть ключа цены. Несводимые единицы —
  отказ от вытеснения, а не «перезапишем и ладно».
- Правило №15: `updated_at` — дата цены; двигает её только переоценка
  (`utils/price_change.py`), `onupdate` не появляется.
- Правило выбора цены одно на весь проект — `utils/price_min.compute_min_price`.
- Прайс общий на всех: удаление необратимо, поэтому всё, что удаляется по
  догадке системы, требует подтверждения человеком.
- Обратная совместимость: существующий `POST /admin/price-lists/{type}` и его
  поведение не меняются.
- Эмбеддинги локальные (FastEmbed) — денег не стоят, но занимают CPU: операция
  синхронная, число позиций в одном файле ограничено.

## Не цели

- Не делаем «умное» слияние дублей с переносом цен подрядчиков в выжившую
  позицию — только удаление отмеченного.
- Не трогаем механизм подбора цены при расчёте сметы и порог похожести.
- Не храним историю операций «эталон» — журнал корректировок (правило №9) сюда
  не относится: это не правка строки документа человеком.
