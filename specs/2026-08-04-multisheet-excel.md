# Спецификация: мультилистовые Excel во всём цикле

Дата: 2026-08-04
Исследование: `thoughts/research/2026-08-04-multisheet-excel.md`

---

## Проблема

Заказчики присылают гранд-сметы и перечни, разбитые на несколько листов Excel — по одному листу
на раздел, корпус или этап работ. Сервис берёт **только первый лист** и молча теряет остальные.
Менеджер этого не видит: задача завершается успешно, файл выглядит нормальным, просто в нём нет
двух третей работ. Ошибка обнаруживается на аукционе — когда сумма контракта занижена и её уже
не поправить.

## Цель

Файл с несколькими листами обрабатывается целиком. Документ показывает вкладки с названиями
листов исходного файла. Весь цикл — перечень → полнота → смета → оптимизация — работает по всем
вкладкам.

## Область

**Входит:**

1. `LIST_FROM_GRAND` (xlsx): перечень из гранд-сметы по всем листам.
2. `ESTIMATE_FROM_LIST` Path A: смета из загруженного Excel по всем листам.
3. `ESTIMATE_FROM_LIST` Path B, `CHECK_LIST_COMPLETENESS`, `ESTIMATE_OPTIMIZATION`: сохраняют
   разбивку по листам, пришедшую с предыдущего этапа.
4. Документ исходного файла заказчика (`file_slot='input'`): все листы.
5. Редактор: вкладки листов, правка внутри вкладки, итоги по вкладке и по документу.
6. Скачиваемые файлы: перечень, полнота, смета, оптимизация — лист на лист.

**Не входит:**

* `LIST_FROM_PROJECT` / `CHECK_PROJECT_COMPLETENESS` — источник PDF, листов там нет.
* Переименование, добавление и удаление листов из редактора. Набор листов задаёт исходный файл.
* Перенос строк между листами мышкой.
* Сводная смета проекта — она собирается из карточек, а не из листов.

## Критерии приёмки

### A. Перечень из гранд-сметы

* **A1.** Файл с N листами, где на каждом есть таблица позиций → в перечень попадают позиции со
  всех N листов.
* **A2.** Лист, из которого не извлеклось ни одной позиции (титульный, подписи, пустой), в
  документ не попадает и вкладку не создаёт.
* **A3.** Позиции одного листа не смешиваются с позициями другого при отправке в ИИ: чанк целиком
  принадлежит одному листу.
* **A4.** Скачиваемый файл содержит по листу на каждый исходный лист (имя = имя исходного листа)
  плюс «Пояснительная записка». Листы «Работы» и «Материалы» при нескольких листах не создаются.
* **A5.** Файл с одним листом обрабатывается ровно как раньше: 4 листа
  (Перечень / Работы / Материалы / Пояснительная записка), вкладок листов в редакторе нет.

### B. Полнота

* **B1.** Проверка полноты перечня с N вкладками возвращает результат с теми же N вкладками.
* **B2.** Позиция, добавленная ИИ как недостающая, попадает на вкладку той позиции, к которой она
  относится.
* **B3.** Чанк проверки не смешивает листы.

### C. Смета

* **C1.** Path A: загруженный Excel с N листами → смета с N вкладками.
* **C2.** Path B: перечень (или полнота) с N вкладками → смета с N вкладками.
* **C3.** Скачиваемый файл сметы содержит по листу на вкладку. На каждом листе — свой блок итогов
  (сумма работ, накладные %, сумма материалов, транспортные %, ИТОГО по листу).
* **C4.** Последним идёт лист «Итого по смете»: строка на каждый лист с его итогом и строка
  «ВСЕГО» с общей суммой.
* **C5.** `task.cost` равен «ВСЕГО» — сумме итогов всех листов.
* **C6.** Смета из одного листа даёт файл прежнего вида: один лист «Смета» с блоком итогов в
  конце, без листа «Итого по смете».

### D. Оптимизация

* **D1.** Смета с N вкладками открывается в оптимизации с теми же N вкладками.
* **D2.** Версии оптимизации сохраняют разбивку по листам.
* **D3.** Скачиваемый оптимизированный файл содержит по листу на вкладку.

### E. Редактор

* **E1.** Документ с несколькими листами показывает полосу вкладок листов над таблицей. Имя
  вкладки = имя исходного листа, рядом — число строк.
* **E2.** Документ с одним листом (или строками без признака листа) полосу вкладок не показывает.
* **E3.** Таблица показывает строки только активной вкладки. Существующие фильтры
  «Все / Работы / Материалы» и поиск работают внутри активной вкладки.
* **E4.** Колонки берутся у строк активной вкладки: у разных листов набор колонок может
  отличаться.
* **E5.** Новая строка (кнопка «Добавить строку», вставка из прайса, вставка из буфера) попадает
  на активную вкладку.
* **E6.** Удаление, перетаскивание и отмена (Ctrl+Z) действуют внутри активной вкладки и не
  трогают строки других вкладок.
* **E7.** «Применить» записывает **весь** документ, включая вкладки, которые сейчас не открыты.
* **E8.** Блок итогов показывает «ИТОГО по листу «‹имя›»» и «ВСЕГО по смете» — обе строки
  одновременно. У документа с одним листом — прежний вид, одна строка «ИТОГО».
* **E9.** Активная вкладка живёт в адресе страницы (`?sheet=`): по ссылке коллега видит то же
  самое.
* **E10.** Выгрузка-ведомость по документу с вкладками создаёт лист на вкладку.

### F. Совместимость

* **F1.** Документы, созданные до этой правки, открываются без ошибок и ведут себя как раньше:
  строк без признака листа — один безымянный лист, вкладок нет.
* **F2.** Черновик, сохранённый до правки, применяется без потери строк.
* **F3.** Разделы сводной, собранные из смет с вкладками, содержат все строки всех вкладок.

### G. Числа

* **G1.** Итог на экране и итог в скачанном файле совпадают до копейки — по каждому листу и по
  документу целиком. Закреплено тестом с точными числами.
* **G2.** `task.cost`, итог редактора и «ВСЕГО» в файле — одно и то же число.

## Ограничения

* Excel не допускает в имени листа `: \ / ? * [ ]`, имя длиннее 31 символа, пустое имя и
  повторы. Имя исходного листа приводится к допустимому, и дальше по всему циклу — в документе,
  на вкладке и в файле — используется именно оно. Иначе имя на вкладке и имя листа в скачанном
  файле разошлись бы, а документ пересобирается из файла и обратно. Практическое следствие:
  название длиннее 31 символа обрезается.
* Порядок листов в документе и в файле = порядок листов в исходном файле.
* Хранилище строк не меняется: строки всех листов лежат одним массивом в `EstimateVersion.rows`,
  признак листа — поле строки. Миграции БД не требуется.
* Правило проекта «у строки один писатель» и «входной файл заказчика не перезаписывается» —
  в силе.

## Не-цели

* Не оптимизируем стоимость обработки: N листов = пропорционально больше запросов к ИИ. Это и
  есть заказанная работа.
* Не меняем формат хранения строк и не вводим новых сущностей в БД.
* Не трогаем ветку задач из PDF-проекта.
