# Spec: Единый редактор таблиц

**Дата:** 2026-08-02
**Заказчик:** руководитель отдела продаж CityManage
**Исследование:** `thoughts/research/2026-08-02-edinyy-redaktor-tablic.md`

---

## Проблема

Пять типов документов (перечень, полнота, смета, версии оптимизации, сводная) редактируются пятью разными таблицами, открываются тремя разными способами, а смета к тому же хранится в двух местах одновременно — правка на странице задачи и правка в онлайн-редакторе пишут в разные хранилища и молча расходятся. Пользователь может увидеть три разных числа для одной строки: на странице задачи, в редакторе и в скачанном файле. Ошибка в смете = финансовые потери на тендере.

## Цель

Один редактор таблиц с единым поведением для всех пяти типов документов, один источник правды по каждому документу, одна страница на смету вместо трёх, плюс четыре новые функции: выгрузка-ведомость, коэффициент, поиск аналогов через ИИ, работа с прайсом.

---

## Область работ

### Входит

**Единый редактор**
- Одна оболочка редактора для всех пяти типов документов: одинаковый вид, одинаковые кнопки, одинаковое поведение.
- Редактор встроен в страницу документа + кнопка «на весь экран» (открывается поверх текущего экрана).
- Набор колонок и доступных действий определяется типом документа.
- Автосохранение в черновик + явная кнопка «Применить» + предупреждение при закрытии с непринятыми правками.
- Простая история правок для всех типов: «Иванов, 02.08.2026 14:31, изменил цену работ в строке 12: 3000 → 2500», с возможностью откатиться.
- Вкладки версий (там, где версии есть) видны в любом способе открытия.
- Ссылка на конкретный документ / версию / вкладку.

**Умения таблицы**
- Поиск по наименованию; вкладки «Работы / Материалы»; галочки на строках и действия над выделенным.
- Отмена / повтор (Ctrl+Z / Ctrl+Y).
- Добавить строку вручную; добавить позицию из прайса (после текущей строки, можно несколько); удалить строку; удалить работу вместе с её материалами.
- Перетаскивание строк мышкой.
- Автопересчёт «цена × объём = стоимость»; блок итогов сверху.
- Копирование и вставка диапазона из Excel; перемещение по ячейкам стрелками и Tab.
- Подсветка групп А/В/С; отрицательный объём = «не считается»; пометка «цена из прайса»; пересчёт цены строки через ИИ.

**Единый источник правды**
- Смета хранится только в рабочей версии (`EstimateVersion`); `task.progress_data['items']` перестаёт быть источником правды.
- Разовая миграция существующих смет с отчётом о расхождениях.

**Одна страница на смету**
- Страница карточки сметы поглощает страницу задачи: этапы, файлы, ход обработки, стоимость, ошибки, встроенный редактор.
- Чат-уточнение убирается.
- Старый адрес `/tasks/:id/status` редиректит на новую страницу с нужным этапом.
- Канбан-доска остаётся как есть, скачивание файлов из неё сохраняется.

**Новые функции**
1. **Выгрузка-ведомость** на каждом документе: окно в два шага (настройка → предпросмотр), фильтр по типу строк, выбор столбцов, выбор позиций двумя способами (галочками в таблице и в предпросмотре), пресеты «Ведомость работ» / «Ведомость материалов», настраиваемая шапка, скачивание xlsx.
2. **Коэффициент** — обратимая настройка документа: общий и отдельно на работы / материалы; применяется ко всем позициям или к выделенным; попадает в итоги, в выгрузку и в скачиваемый файл.
3. **Найти аналоги** (смета и оптимизация): по выделенным позициям ИИ ищет более дешёвые замены при том же результате, 3 варианта на позицию, показывает наименование, ед. изм., цену, разницу в деньгах, обоснование и источник; кнопка «Заменить» подставляет аналог вместо исходной строки.
4. **Добавить в прайс** (смета и оптимизация): выделенные позиции уходят в прайс; работы — в псевдо-подрядчика «Из смет», материалы — ценой; единицы измерения нормализуются; при совпадении наименования цена из сметы заменяет прежнюю цену «Из смет», а цены подрядчиков остаются нетронутыми (решение пользователя 2026-08-03; изначально предполагалось хранить и прежние цены).

**Прочее**
- Проценты накладных и транспортных настраиваются на уровне проекта, по умолчанию 3%.
- Починка многострочных шапок Гранд-сметы при разборе xlsx.
- Права: менеджер правит только свои документы, руководитель отдела продаж — любые.
- Пока задача считается — редактор в режиме просмотра с надписью «идёт расчёт».
- Баннер «Иван сейчас редактирует этот документ» и запрет сохранить поверх чужих изменений.
- Входной файл заказчика становится доступен только для чтения и никогда не перезаписывается.

### Не входит

- Бланк «Сводная» (18 фиксированных строк расчёта) — остаётся как есть.
- Тестовая вкладка Fortune-Sheet в админке — остаётся как есть.
- Редактор в стиле Excel: формулы, объединённые ячейки, оформление.
- Переработка канбан-доски.
- Дополнительные строки итога (прибыль, НДС, налог) в обычных документах — остаются только в сводной.
- Совместное редактирование в реальном времени (двое одновременно печатают в одну таблицу).
- Мобильная версия редактора.

## Критерии приёмки

**Единый редактор**
- [ ] Все пять типов документов открываются одним и тем же компонентом редактора; `GenericGrid.tsx`, `GenericEditorModal.tsx`, `EstimateEditorModal.tsx` и inline-таблица в `TaskStatus.tsx` удалены из кода.
- [ ] Ни один редактор не открывается через iframe.
- [ ] Редактор виден встроенным в страницу документа, кнопка «на весь экран» открывает его поверх текущего экрана без потери состояния.
- [ ] Правки автоматически уходят в черновик; кнопка «Применить» активна только при наличии непринятых правок; при попытке закрыть с непринятыми правками показывается предупреждение.
- [ ] История правок доступна для всех пяти типов, показывает автора, время, строку, поле, старое и новое значение; откат возвращает документ в прежнее состояние.
- [ ] Ссылка вида «документ + версия + вкладка» открывает ровно то состояние, из которого её скопировали.

**Умения таблицы** (проверяется на смете, где доступны все)
- [ ] Работают: поиск, вкладки «Работы / Материалы», галочки, Ctrl+Z / Ctrl+Y, добавление строки вручную, добавление из прайса, удаление строки, удаление работы с материалами, перетаскивание строк, автопересчёт «цена × объём», блок итогов.
- [ ] Диапазон ячеек копируется в буфер и вставляется в Excel; диапазон, скопированный из Excel, вставляется в таблицу начиная с выделенной ячейки.
- [ ] Перемещение по ячейкам работает стрелками и Tab.
- [ ] Подсветка групп А/В/С, отрицательный объём («не считается»), пометка «цена из прайса», пересчёт цены строки через ИИ — доступны в смете и оптимизации.
- [ ] Документ на 2000 позиций открывается и прокручивается без заметных задержек; ввод в ячейку не подтормаживает.

**Единый источник правды**
- [ ] Правка сметы в любом месте интерфейса меняет ровно одно хранилище; итог задачи, содержимое редактора и скачанный файл показывают одно и то же число.
- [ ] Миграция существующих смет выполнена; отчёт о расхождениях сформирован; ни одна смета не потеряна.

**Одна страница на смету**
- [ ] Смета имеет одну страницу, на которой видны этапы, файлы, ход обработки, стоимость, ошибки и редактор.
- [ ] Старый адрес `/tasks/:id/status` открывает новую страницу на нужном этапе.
- [ ] Чат-уточнение удалён из интерфейса.

**Новые функции**
- [ ] Кнопка «Сформировать выгрузку» есть на каждом из пяти типов документов и даёт xlsx по заданным фильтрам, столбцам, позициям и шапке; пресеты «Ведомость работ» и «Ведомость материалов» работают в один клик.
- [ ] Коэффициент задаётся, меняется и снимается; цены и итоги пересчитываются; исходные цены не теряются; коэффициент виден в интерфейсе, попадает в выгрузку и в скачиваемый файл.
- [ ] «Найти аналоги» по выделенным позициям возвращает до 3 вариантов на позицию с наименованием, ед. изм., ценой, разницей в деньгах, обоснованием и источником; «Заменить» подставляет вариант в строку; перед запуском показывается оценка объёма работы.
- [x] «Добавить в прайс» записывает выделенные позиции: работы — в подрядчика «Из смет», материалы — ценой; единицы измерения нормализованы; при совпадении наименования обновляется цена «Из смет», а цены подрядчиков остаются нетронутыми.
- [x] Цена, добавленная из сметы, имеет приоритет при расчёте следующих смет; когда её нет — работает минимум по подрядчикам (решение пользователя 2026-08-03).
- [x] «Добавить из прайса» ищет по смыслу, позволяет выбрать несколько позиций и вставляет их после текущей строки.

**Права и совместная работа**
- [ ] Менеджер не может сохранить чужой документ; руководитель отдела продаж — может.
- [ ] Во время расчёта задачи редактор в режиме просмотра с надписью «идёт расчёт».
- [ ] При открытии документа, который уже редактирует другой сотрудник, показывается баннер с его именем; попытка сохранить поверх его изменений отклоняется с понятным сообщением.
- [ ] Входной файл заказчика ни при каких действиях не перезаписывается.

**Прочее**
- [ ] Проценты накладных и транспортных задаются на уровне проекта, по умолчанию 3%, применяются в итогах документов проекта.
- [ ] Перечень из Гранд-сметы с многострочной шапкой разбирается без мусорной первой строки вида «2 / 3 / 1 / 4 / 5 / 6».

## Ограничения

- **Технические:** React 18 + TypeScript, react-data-grid 7.0.0-beta.47 (MIT), FastAPI + SQLAlchemy async, PostgreSQL. Платные библиотеки не используем.
- **Совместимость:** старые ссылки на страницу задачи должны работать; уже созданные документы должны открываться в новом редакторе без ручного вмешательства; изменения моделей — только через миграции с `IF NOT EXISTS` (следующий номер 042).
- **Производительность:** 2000 позиций — рабочий потолок; открытие документа не дольше 2 секунд, ввод в ячейку без видимой задержки.
- **Стоимость:** «Найти аналоги» использует платный веб-поиск; обязательны подтверждение с оценкой и учёт в существующем лимите веб-поиска.
- **Безопасность:** права на запись проверяются на сервере, а не параметром в адресе страницы (сейчас режим просмотра задаётся через `read_only=1` в URL и обходится).
- **Переходный период:** старый редактор остаётся доступен под флагом, пока новый не подтверждён на каждом типе документа.

## Не является целью

- Сделать «Excel в браузере» — работаем с данными, а не с оформлением файла.
- Унифицировать бланк сводной себестоимости.
- Переделать канбан-доску и структуру проектов.
- Ввести совместное редактирование в реальном времени.
- Свести оба формата данных (плоский и осмысленный) в один — они остаются разными под общей оболочкой.
