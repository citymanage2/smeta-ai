# Spec: Использование файлов "Проект", "ТЗ", "Другое" при оптимизации сметы

## Проблема

При оптимизации сметы пользователи прикрепляют проектную документацию и ТЗ, но эти файлы игнорируются. Claude работает "вслепую" и вынужден угадывать границы работ, технологические ограничения, требования заказчика — что снижает точность оптимизации.

## Цель

Передавать содержимое файлов "Проект", "ТЗ", "Другое" в Claude на релевантных этапах оптимизации, чтобы AI мог принимать решения на основе реальной документации.

## Scope

**Входит:**
- Загрузка файлов заказчика из `task_input_files` по метаданным из `user_prompt`
- Парсинг содержимого в текст (через существующий `parse_file()`)
- Добавление контекстного блока в промпты этапов: completeness, redundancy, technology, materials
- Truncation для защиты от переполнения контекста (лимит 8000 символов на файл)

**Не входит:**
- Передача PDF как image_blocks в Claude Vision (следующая фаза)
- Поддержка GSN формата
- UI изменения

## Acceptance Criteria

1. Если к задаче прикреплён файл с типом "Проект", "ТЗ" или "Другое" — его содержимое добавляется в промпт этапов completeness, redundancy, technology, materials
2. Если файлов нет — поведение не меняется (промпт без контекста)
3. Файл с типом "Смета" (уже обрабатывается) — не дублируется в промпт
4. Содержимое усекается до 8000 символов с пометкой "(обрезано)" если больше
5. Промпты этапов дополнены инструкцией использовать переданный контекст
6. Все существующие тесты проходят

## Constraints

- Не менять сигнатуру `call_claude()` — работаем только через текст в промпте
- Не менять модели данных / миграции
- Парсинг только через уже существующий `parse_file()` из `file_parser.py`

## Non-Goals

- Передача PDF через Vision API
- Изменения в UI
- Кэширование контента файлов
