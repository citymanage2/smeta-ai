# Спека: метрики затрат и времени по стадиям

Дата: 2026-08-06
Исследование: `thoughts/research/2026-08-06-metriki-stoimosti-po-stadiyam.md`

## Проблема

Сервис тратит деньги на API Anthropic (≈$10 на одну смету), но в карточке сметы
этих цифр нет. Нельзя ответить на вопросы: сколько стоила конкретная смета,
где деньги утекают — на основной обработке или на допзапросах, сколько задача
простояла в очереди против того, сколько реально считалась.

Хуже: 6 из 7 мест, где сервис платно ходит в ИИ **после** формирования файла
стадии (поиск цены строки, массовое проставление цен, аналоги, предложения по
оптимизации), не пишут вызов в `api_call_log` вовсе — их стоимость не видна
нигде, включая админский дашборд.

Отдельно: колонка «Сумма» в списке смет всегда показывает «—», хотя сумма
сформированной сметы в системе есть (`task.cost`).

## Цель

Человек, открывая карточку сметы, видит по каждой стадии, во что она обошлась
и сколько шла; в шапке сметы и шапке проекта — те же цифры суммарно.

## Область (Scope)

### 1. Учёт: закрыть дыру в логировании
Все платные вызовы ИИ пишутся в `api_call_log` и помечаются как основные или
дополнительные.

«Доп» — платный запрос к ИИ по уже сформированному файлу стадии: поиск цены,
поиск аналогов, предложения по оптимизации отдельных строк.

### 2. Метрики стадии
Для каждой из четырёх стадий (перечень, полнота, смета, оптимизация):

| Показатель | Определение |
|---|---|
| Токены | `input + output + cache_read + cache_creation` по основным вызовам |
| Стоимость, $ | `SUM(cost_usd)` по основным вызовам |
| Время ожидания | `started_at − created_at` |
| Время работы | `finished_at − started_at` |
| Допы: токены | те же токены, но по вызовам с признаком «доп» |
| Допы, $ | `SUM(cost_usd)` по вызовам с признаком «доп» |

### 3. Итог по смете
Сумма по четырём стадиям: токены (вкл. допы), $ (вкл. допы), время ожидания,
время работы. Подписано **«Сумма затрат»** — чтобы не путалось с суммой сметы.

### 4. Итог по проекту
Сумма по всем сметам проекта: токены, $, время реализации (ожидание + работа).

### 5. Колонка «Сумма» в списке смет
Показывает сумму сформированной сметы в рублях: из последней стадии оптимизации,
если она есть, иначе из стадии сметы. «—» только когда сметы ещё нет.

## Критерии приёмки

1. **AC-1.** В раскрытой секции каждой стадии справа видна строка:
   токены · $ · ожидание · работа · допы (токены, $).
2. **AC-2.** Стадия без единого вызова ИИ (файл загружен вручную) показывает
   прочерки, а не нули, и не ломает вёрстку.
3. **AC-3.** Идущая задача показывает время работы, растущее в реальном времени;
   не начатая — растущее время ожидания.
4. **AC-4.** Поиск аналогов и поиск цены строки увеличивают именно «допы»
   соответствующей стадии, а не основные токены.
5. **AC-5.** Итог по смете равен сумме показателей её стадий, включая допы.
   Проверяется тестом с точными числами.
6. **AC-6.** Итог по проекту равен сумме итогов его смет. Проверяется тестом.
7. **AC-7.** Колонка «Сумма» показывает `optimization.cost ?? estimate.cost`,
   отформатированную в рублях; «—» только если обеих нет.
8. **AC-8.** Метрики видны всем ролям (admin, head_of_sales, project_manager)
   в пределах их обычной видимости смет — новых ограничений нет.
9. **AC-9.** Поллинг карточек не стал тяжелее: метрики едут в уже существующем
   ответе `files-meta`, число SQL-запросов на карточку не зависит от числа стадий.
10. **AC-10.** Существующие тесты бэкенда и фронтенда зелёные; `tsc --noEmit`
    и `ruff` чисты.

## Ограничения

- Не создавать новых таблиц: метрики агрегируются из `api_call_log`.
- Не перезаписывать входной файл заказчика (общее правило проекта).
- Любое изменение `models/*.py` → сначала миграция с `IF NOT EXISTS`.
- Числа на экране и в API считаются одной формулой в одном месте.

## Вне области (Non-Goals)

- Пересчёт исторических данных: вызовы, залогированные до этой фичи, остаются
  помечены как основные (кроме тех, что вовсе не логировались — их не вернуть).
- Конвертация $ в рубли по курсу.
- Изменение админского дашборда затрат (он начнёт видеть допы автоматически,
  но его вёрстку не трогаем).
- Бюджеты, лимиты, алерты по перерасходу.
