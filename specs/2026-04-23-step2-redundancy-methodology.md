# Методология: Шаг 2 — Проверка на лишние позиции

**Дата:** 2026-04-23  
**Статус:** Согласовано  
**Контекст:** Второй шаг модуля оптимизации. Работает с Версией 1 (результат Шага 1). Если Версия 1 не создана — работает с исходной сметой.

---

## Цель

Найти в смете позиции, которые **не нужны** или **задвоены** — без изменения конечного результата работ.

Четыре категории лишних позиций:

| Категория | Код | Описание |
|---|---|---|
| Дублирование | `duplicate` | Одна и та же работа/материал присутствует в двух строках с одним назначением и разными наименованиями |
| Нормативное включение | `norm_included` | Позиция уже входит в состав другой расценки по нормам ГЭСН (double-counting) |
| Вне проекта | `out_of_scope` | Позиция явно не применима к данному типу работ / объекту |
| Нет у заказчика | `not_in_client` | Позиции из `extra_in_ours` Шага 1.1, предзаполненные автоматически |

---

## Входные данные

- **Версия 1** (или исходная, если Версия 1 не создана) — список строк `EstimateRow[]`
- **Список `extra_in_ours`** из подшага 1.1 — автоматически предзаполнен (может быть пустым)
- **Файл заказчика** (если загружен) — как дополнительный контекст

---

## Один шаг — одна кнопка

Шаг 2 не имеет подшагов. Claude анализирует все четыре категории за один запрос.

---

## Промпт Claude

**Вход:** JSON сметы + список pre-populated подозрительных `row_id` из 1.1

```
Ты — опытный инженер-сметчик со знанием ГЭСН-2017/ФСНБ-2022.

Тебе передана смета строительных работ (JSON).
Также предварительно помечены позиции, которых нет в смете/ТЗ заказчика: [список row_id].

Найди в смете ЛИШНИЕ позиции по четырём категориям:

1. ДУБЛИРОВАНИЕ — одна и та же работа или материал указаны дважды с одним назначением (под разными наименованиями или кодами ГЭСН).
   ВАЖНО: один и тот же материал может встречаться в нескольких строках, если он используется для разных работ — это НЕ дубль.
   Примеры:
   - «Цемент М500» на стяжку (строка №5) и «Цемент М500» на штукатурку (строка №22) — НЕ дубль, разные работы
   - «Грунтовка» для стен (строка №8) и «Грунтовка» для потолка (строка №9) — НЕ дубль
   - «Грунтовка стен» (строка №8) и «Нанесение грунта на стены» (строка №11) — ДУБЛЬ, одна работа, разные слова
   Дубль — только когда совпадают и материал/работа, И назначение (объект или вид работ).

2. НОРМАТИВНОЕ ВКЛЮЧЕНИЕ — позиция входит в состав другой расценки по нормам ГЭСН/ФСНБ и уже оплачивается в её составе.
   Типичные примеры:
   - «Очистка и обеспыливание поверхности» → входит в расценки грунтования (ГЭСН 15-04)
   - «Разметка осей» → входит в расценки монтажа перегородок и каркасов
   - «Подготовка основания» → входит в расценки укладки большинства напольных покрытий
   - «Снятие старого крепежа» → входит в расценки демонтажа соответствующих конструкций

3. ВНЕ ПРОЕКТА — позиция явно не применима к данному типу работ или объекту, исходя из общего состава сметы.

4. НЕТ У ЗАКАЗЧИКА — для каждой помеченной позиции оцени: действительно ли её отсутствие у заказчика означает, что она лишняя в нашей смете? Укажи своё заключение.

Правило точности: не добавляй позиции, в которых не уверен. Лучше пропустить сомнительную, чем предложить удалить нужную. Для каждого предложения указывай реальный уровень уверенности.

Верни JSON:
{
  "redundant_proposals": [
    {
      "row_id": "id строки",
      "name": "Наименование",
      "category": "duplicate" | "norm_included" | "out_of_scope" | "not_in_client",
      "confidence": "high" | "medium" | "low",
      "reason": "Детальное обоснование с указанием нормативного источника (для norm_included)",
      "related_row_id": "id связанной строки или null",
      "related_name": "Наименование связанной строки или null"
    }
  ],
  "summary": "Краткое резюме: сколько нашли по категориям и ориентировочная экономия"
}
```

### Действия с предложением

- **[Удалить]** — строка помечается «к удалению» в гриде: зачёркнутый текст, красный фон. Счётчик «Принято к удалению» обновляется.
- **[Оставить]** — предложение отклонено, строка без изменений. Статус предложения: `rejected`.
- Оба действия можно отменить повторным нажатием (toggle).
- Грид Версии 1 рядом отображает «принятые к удалению» строки в реальном времени.

### Кнопка фиксации версии

Кнопка **[Зафиксировать как Версию 2]** активна сразу после того, как анализ завершён (даже если принято 0 предложений).

| Состояние | Лейбл кнопки |
|---|---|
| Анализ ещё не запущен | Неактивна |
| Анализ завершён, принято 0 | «Зафиксировать Версию 2 без изменений» |
| Принято ≥ 1 | «Зафиксировать как Версию 2» |

При фиксации с нулём изменений строки Версии 2 идентичны Версии 1. Это означает «Шаг 2 пройден, лишних позиций не принято».

**Версия 2 обязательна.** Без её создания кнопка Шага 3 остаётся неактивной. Пропустить Шаг 2 нельзя — пользователь должен либо принять предложения, либо явно зафиксировать «изменений нет».

## Решения по UX

1. **Нормативное включение (norm_included):** под каждым таким предложением выводить оговорку:
   > ⚠ Рекомендуем проверить по ГЭСН вручную перед удалением

2. **Уверенность low:** скрыты за спойлером. В конце списка основных предложений:
   > Ещё 2 неуверенных предложения  ▶ Показать
   При раскрытии выводятся с явной пометкой «низкая уверенность».
