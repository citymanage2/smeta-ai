# Спецификация: запрос КП у отдела производства работ

Дата: 2026-09-14
Исследование: `thoughts/research/2026-09-14-zapros-kp.md`
План: `plans/2026-09-14-zapros-kp.md`

## Проблема

Цена позиции в смете берётся из прайса, кеша или ИИ-поиска. Для дорогих или
редких материалов и работ этого мало: реальную цену знает только поставщик или
подрядчик. Сейчас менеджер продаж запрашивает КП вне системы — в мессенджере,
письмом, — получает файлы, вручную переносит цены в смету и никак не отмечает,
какие цены подтверждены КП. Отдела производства работ в системе нет, задачу
ему не поставить, результат не отследить.

## Цель

Менеджер продаж за минуту ставит задачу «запросить КП» по выбранным позициям;
ответственный сотрудник отдела производства работ получает её, прикладывает КП,
система распознаёт цены, сотрудник проверяет и завершает задачу; менеджер
продаж одной кнопкой проставляет цены из КП в смету оптимизации и видит, какие
позиции подтверждены КП.

## Пользователи

* **Менеджер продаж** (`project_manager`, `head_of_sales`, `admin`) — ставит
  запросы, применяет цены.
* **Менеджер снабжения** (`supply_manager`) — новая роль; отвечает за материалы.
* **Менеджер по работе с подрядчиками** (`contractor_manager`) — новая роль;
  отвечает за работы.

Роли снабжения и подрядчиков вместе — «отдел производства работ».

## Сценарий

1. Администратор заводит сотрудника с ролью «Менеджер снабжения» или
   «Менеджер по работе с подрядчиками» на странице «Сотрудники».
2. Менеджер продаж в документе на стадии перечень / полнота / смета /
   оптимизация отмечает строки и жмёт «Запросить КП».
3. В окне видит позиции, разбитые на «Материалы → снабжение» и «Работы →
   подрядчики», выбирает исполнителя каждой группы, пишет комментарий
   (сроки, объект, требования) и отправляет. Создаётся по одному запросу на
   группу.
4. Исполнитель заходит в систему — его стартовая страница «Мои задачи КП» со
   счётчиком новых. Открывает запрос: позиции (наименование, единица, объём,
   лист, № в исходной смете), комментарий автора, объект.
5. Загружает файл КП (PDF, XLSX, XLS, JPG, PNG), указывает поставщика.
   ИИ распознаёт цены по позициям запроса. Сотрудник видит сравнительную
   таблицу «позиция × КП», правит и подтверждает цены, указывает НДС.
   КП на запрос может быть несколько.
6. Пишет отчёт («запрошено у 4, ответили 2, сроки поставки…») и завершает
   задачу.
7. Менеджер продаж видит в карточке «КП получены», открывает оптимизацию,
   жмёт «Цены из КП», видит предпросмотр и применяет — появляется новая версия
   оптимизации с ценами из КП, эти строки подсвечены.

## Критерии приёмки

### Роли и доступ
1. На странице «Сотрудники» можно создать сотрудника и сменить роль на
   «Менеджер снабжения» и «Менеджер по работе с подрядчиками».
2. Пользователь этих ролей после входа попадает на «Мои задачи КП»; в меню нет
   проектов, архива, создания задач, прайсов и прочих разделов.
3. Любой API-запрос такого пользователя вне авторизации и роутера КП получает
   403. Закреплено тестом, перебирающим все маршруты приложения: новый роутер
   без явного разрешения автоматически закрыт.
4. Внутри роутера КП исполнитель видит и меняет только запросы, где он
   исполнитель; скачивает только файлы своих запросов.
5. Менеджеры продаж видят все запросы (проекты общие — правило доступа проекта).

### Постановка запроса
6. Кнопка «Запросить КП» есть в редакторе на стадиях перечень, полнота, смета,
   оптимизация и активна при выделенных строках; в режиме «Свернуть дубли»
   выделение группы даёт все её строки.
7. Выделение разбивается на материалы и работы; позицию без определённого типа
   человек относит сам в окне; строки-разделы и строки без наименования в
   запрос не попадают.
8. Одинаковые позиции выделения (тип + наименование + единица, без учёта
   регистра и лишних пробелов) становятся одной позицией запроса с суммой
   объёма; строки с отрицательным объёмом объём не увеличивают.
9. Исполнитель выбирается из активных сотрудников нужной роли; если такой один —
   подставлен. Нет ни одного — отправка группы невозможна, причина показана.
10. Позиции запроса — снимок на момент отправки: последующая правка документа
    запрос не меняет.
11. Автор или менеджер может отменить запрос и переназначить исполнителя
    (например, сотрудник уволен).

### Работа исполнителя
12. «Мои задачи КП»: списки «Новые / В работе / Завершённые», объект, карточка,
    автор, число позиций, дата. В шапке счётчик новых, обновляется без
    перезагрузки (опрос).
13. Открытие запроса переводит его из «Новый» в «В работе».
14. К запросу можно приложить несколько КП; у КП — поставщик, дата, режим НДС
    («цены с НДС» / «без НДС» / «поставщик без НДС»), файл. Файл хранится в S3,
    скачивается, удаляется исполнителем до завершения.
15. После загрузки файл разбирается ИИ в фоне; пока идёт разбор — видно
    состояние; ошибка разбора показывается текстом и не мешает ввести цены
    вручную; разбор можно перезапустить.
16. ИИ возвращает цены **только для позиций запроса**; для каждой — цену за
    единицу, единицу КП, наименование в КП, уверенность. Позиция, которой в
    КП нет, остаётся пустой. Выдуманный id позиции отбрасывается.
17. Распознанная цена — черновик: подсвечена как неподтверждённая, пока
    человек её не подтвердит или не исправит. Ручной ввод цены сразу считается
    подтверждённым.
18. Сравнительная таблица: строки — позиции, колонки — КП, в ячейке цена в
    единице КП и приведённая цена (единица позиции, без НДС). Минимальная
    приведённая цена по позиции выделена; можно отметить другое КП как
    выбранное — выбор переживает перезагрузку.
19. Несводимая единица (мешок ↔ кг) — приведённой цены нет, цена в минимуме не
    участвует, причина видна в ячейке (правило №8).
20. Приведение НДС: «с НДС» → цена ÷ 1,22; «без НДС» и «поставщик без НДС» →
    как есть. Закреплено тестом с точными числами.
21. «Завершить» требует непустой отчёт и отсутствие неподтверждённых цен;
    КП может не быть вовсе (поставщики не ответили) — тогда отчёт обязателен
    всё равно. Завершённый запрос исполнитель не правит; автор может вернуть его
    в работу с комментарием.

### Применение в оптимизации
22. В карточке сметы виден список запросов КП со статусами и числом
    завершённых, но не применённых.
23. В редакторе оптимизации кнопка «Цены из КП» активна, если у карточки есть
    завершённые запросы с ценами и у оптимизации есть строки.
24. Первый шаг — предпросмотр, **ничего не пишет**: сколько строк получат цену,
    старая → новая цена, какое КП; какие позиции не найдены; какие
    неоднозначны (подходят несколько строк с разными наименованиями/листами)
    — для них человек выбирает строку или пропускает.
25. Сопоставление: `row_id` источника (если запрос создан на этой оптимизации)
    → № в исходной смете + наименование → тип + нормализованные наименование и
    единица. Неоднозначное совпадение само не берётся.
26. «Применить» создаёт новую версию оптимизации «Цены из КП» от последней
    неоткатанной версии; предыдущая не меняется, новая откатывается как любая
    версия. Для материала пишется `price_material`, для работы — `price_work`,
    цена без коэффициента и без НДС, в единице строки.
27. Если на одну строку есть цены из нескольких запросов — берётся выбранная
    (или минимальная) по каждому запросу, затем минимальная из них.
28. Строка с ценой из КП подсвечивается в редакторе как «цена из КП»; в
    подсказке — поставщик, дата КП, число КП по позиции, ссылка на запрос.
    Та же пометка красит строку в скачиваемом xlsx оптимизации.
29. Применение — автоматическая операция: не пишет сигналы журнала
    корректировок, пишет запись истории «Цены из КП: N строк».
30. Одновременная правка документа коллегой → конфликт версии (как у
    «Применить»), ничего не записано.

## Ограничения

* Входной файл заказчика не трогается (правило №2); цена в строке — исходная,
  коэффициент сверху (правило №3).
* Экран и файл считают одинаково (правило №4) — применение меняет только цены
  строк, формулы итогов не трогаются.
* ИИ не сопоставляет позиции со строками сметы — только с позициями запроса по
  их id; сопоставление со строками детерминированно.
* Стоимость разбора КП учитывается в журнале вызовов API (правило №13).
* Файл КП ≤ 50 МБ, PDF ≤ 100 страниц (ограничение Claude).

## Не входит

* Отправка запроса поставщику из системы (почта, портал) — исполнитель
  запрашивает КП сам.
* Запись цен из КП в прайс — отдельная функция, через подтверждение человеком.
* Запрос КП из раздела сводной.
* Сроки/дедлайны задач, SLA, эскалации.
* Уведомления по почте/Telegram — только счётчики в интерфейсе.
* Автоматическое применение цен при завершении запроса.
