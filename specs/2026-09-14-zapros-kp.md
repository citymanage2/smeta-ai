# Спецификация: запрос КП у отдела производства работ

Дата: 2026-09-14
Исследование: `thoughts/research/2026-09-14-zapros-kp.md`
План: `plans/2026-09-14-zapros-kp.md`

## Проблема

Цена позиции в смете берётся из прайса, кеша или ИИ-поиска. Для дорогих или
редких материалов и работ этого мало: реальную цену знает только поставщик или
подрядчик. Сейчас менеджер продаж запрашивает КП вне системы — в мессенджере,
письмом, — получает файлы, вручную переносит цены в смету и никак не отмечает,
какие цены подтверждены КП. Отдела производства работ в системе нет, задачу
ему не поставить, результат не отследить, полученные цены не остаются в прайсе.

## Цель

Менеджер продаж за минуту ставит задачу «запросить КП» по выбранным позициям;
отдел производства работ получает её, прикладывает КП, система распознаёт цены,
сотрудник проверяет и завершает задачу; подтверждённые цены сразу пополняют
прайс, а менеджер продаж одной кнопкой проставляет их в смету оптимизации и
видит, какие позиции подтверждены КП.

## Пользователи

* **Менеджер продаж** (`project_manager`, `head_of_sales`, `admin`) — ставит
  запросы, прикладывает материалы к запросу, применяет цены.
* **Менеджер снабжения** (`supply_manager`) — новая роль; материалы.
* **Менеджер по работе с подрядчиками** (`contractor_manager`) — новая роль; работы.

Роли снабжения и подрядчиков вместе — «отдел производства работ».

## Решения пользователя (14.09.2026)

| Вопрос | Решение |
|---|---|
| Как цены из КП попадают в запрос | ИИ разбирает файл КП, человек проверяет |
| Несколько КП на позицию | Минимальная цена по умолчанию, выбор можно сменить |
| Когда цены идут в оптимизацию | Кнопкой, новой версией |
| Доступ новых ролей | Только задачи КП своей роли |
| НДС | При загрузке КП: цены с НДС или без, ставка НДС при необходимости |
| КП «работа с материалами» | Отметка и подсветка, ничего само не обнуляется; в прайс работ такая цена не пишется |
| Доставка, сроки, минимальная партия | Только в отчёте; выбор КП — вручную |
| Кому адресован запрос | Всем сотрудникам роли одновременно (и снабжение, и подрядчики) |
| Что видит исполнитель | Позиции запроса + вложения автора (спецификации, ТЗ) |
| Уведомления | Счётчик в интерфейсе, без почты и Telegram |
| Цены из КП и прайс | Пишутся в прайс напрямую при завершении запроса; у работы цена из КП важнее «Из смет» |

## Сценарий

1. Администратор заводит сотрудника с ролью «Менеджер снабжения» или «Менеджер
   по работе с подрядчиками».
2. Менеджер продаж в документе на стадии перечень / полнота / смета /
   оптимизация отмечает строки и жмёт «Запросить КП».
3. В окне видит позиции, разбитые на «Материалы → снабжение» и «Работы →
   подрядчики», пишет комментарий, прикладывает файлы (спецификация, ТЗ) и
   отправляет. Создаётся по запросу на группу; каждый адресован всей роли.
4. Все сотрудники роли видят новый запрос на «Мои задачи КП» со счётчиком.
   Кто-то жмёт «Взять в работу» — коллеги видят, у кого запрос, но работать
   с ним тоже могут.
5. Сотрудник загружает КП (PDF, XLSX, XLS, JPG, PNG), указывает поставщика,
   «цены с НДС / без НДС» и ставку; для работ — «цена включает материалы».
   ИИ распознаёт цены по позициям запроса. Сотрудник видит сравнительную
   таблицу «позиция × КП», правит и подтверждает цены. КП может быть несколько.
6. Пишет отчёт (кто ответил, сроки поставки, доставка) и завершает задачу.
   Подтверждённые цены записываются в прайс.
7. Менеджер продаж видит в карточке «КП получены», в оптимизации жмёт «Цены из
   КП», смотрит предпросмотр и применяет — появляется новая версия с ценами из
   КП, эти строки подсвечены.

## Критерии приёмки

### Роли и доступ
1. На странице «Сотрудники» можно создать сотрудника и сменить роль на
   «Менеджер снабжения» и «Менеджер по работе с подрядчиками».
2. Пользователь этих ролей после входа попадает на «Мои задачи КП»; в меню нет
   проектов, архива, создания задач, прайсов и прочих разделов.
3. Любой API-запрос такого пользователя вне авторизации и роутера КП получает
   403. Закреплено тестом, перебирающим все маршруты: новый роутер без явного
   разрешения автоматически закрыт.
4. Внутри роутера КП сотрудник производства видит и меняет только запросы своей
   роли (снабжение — материалы, подрядчики — работы) и скачивает только их файлы;
   запрос чужой роли для него не существует (404).
5. Менеджеры продаж видят все запросы (проекты общие — правило доступа проекта).

### Постановка запроса
6. Кнопка «Запросить КП» есть в редакторе на стадиях перечень, полнота, смета,
   оптимизация и активна при выделенных строках; в режиме «Свернуть дубли»
   выделение группы даёт все её строки.
7. Выделение разбивается на материалы и работы; позицию без определённого типа
   человек относит сам; разделы и строки без наименования в запрос не попадают.
8. Одинаковые позиции выделения (тип + наименование + единица, без учёта
   регистра и лишних пробелов) — одна позиция запроса с суммой объёма; строки с
   отрицательным объёмом объём не увеличивают.
9. Запрос адресуется роли. Если в системе нет ни одного активного сотрудника
   этой роли — отправка группы невозможна, причина показана.
10. Позиции запроса — снимок на момент отправки: правка документа запрос не меняет.
11. К запросу автор прикладывает файлы (PDF, XLSX, XLS, DOC, DOCX, JPG, PNG, до
    50 МБ, до 10 файлов) — при создании и позже; сотрудники роли их скачивают.
12. Автор или руководитель продаж может отменить запрос.

### Работа отдела производства
13. «Мои задачи КП»: «Новые / В работе / Завершённые» по своей роли; объект,
    автор, число позиций, дата, кто взял в работу. В шапке счётчик новых,
    обновляется без перезагрузки (опрос).
14. «Взять в работу» переводит запрос из «Новый» в «В работе» и записывает, кто
    взял; загрузка КП в новый запрос делает то же. Остальные сотрудники роли
    продолжают видеть запрос и могут с ним работать.
15. К запросу можно приложить несколько КП; у КП — поставщик, дата, «цены с
    НДС / без НДС», ставка НДС (по умолчанию 22 %, правится), для работ —
    «цена включает материалы», файл, кто загрузил. Файл хранится в S3,
    скачивается, удаляется до завершения.
16. После загрузки файл разбирается ИИ в фоне; состояние разбора видно; ошибка
    показывается текстом и не мешает ввести цены вручную; разбор можно
    перезапустить.
17. ИИ возвращает цены **только для позиций запроса**: цену за единицу, единицу
    КП, наименование в КП, уверенность. Позиции нет в КП — пусто. Выдуманный id
    отбрасывается. Догадки ИИ о поставщике, дате, НДС и ставке заполняют только
    пустые поля КП.
18. Распознанная цена — черновик, подсвечена, пока человек её не подтвердит или
    не исправит. Ручной ввод сразу подтверждён.
19. Сравнительная таблица: строки — позиции, колонки — КП; в ячейке цена в
    единице КП и приведённая (единица позиции, без НДС). Минимальная приведённая
    цена выделена; можно отметить другое КП как выбранное; выбор сохраняется.
    Цена «включает материалы» помечена в ячейке.
20. Несводимая единица (мешок ↔ кг) — приведённой цены нет, в минимуме не
    участвует, причина видна (правило №8).
21. Приведение НДС: «с НДС» → цена ÷ (1 + ставка/100); «без НДС» → как есть.
    Закреплено тестом с точными числами для ставок 22, 20, 10, 5 и 0 %.
22. «Завершить» требует непустой отчёт и отсутствие неподтверждённых цен; КП
    может не быть вовсе — отчёт обязателен всё равно. Завершённый запрос отдел
    производства не правит; автор или руководитель продаж может вернуть его в
    работу.

### Цены в прайс
23. При завершении запроса подтверждённые цены записываются в прайс:
    * **материал** — выбранная (или минимальная) приведённая цена позиции
      перезаписывает цену материала в прайсе;
    * **работа** — цена каждого КП пишется отдельным подрядчиком «КП:
      <поставщик>»; прежние цены подрядчиков и «Из смет» не трогаются.
24. Наименование и единица в прайсе — позиции запроса (как в смете, а не как в
    КП): так цена найдётся в следующей смете. Единица не сводится с позицией
    прайса — цена не пишется, причина в сводке (правило №8).
25. Цена работы с отметкой «включает материалы» в прайс **не пишется**, в
    сводке — «не записано: цена включает материалы».
26. В расчёт сметы у работы идёт минимум по ценам «КП: …»; нет цен из КП — как
    раньше: «Из смет», затем минимум по подрядчикам. Закреплено тестом с
    точными числами.
27. Дата «Цена от» двигается по общему правилу (правило №15): повторное
    завершение с той же ценой дату не меняет.
28. Сводка записи в прайс (добавлено / обновлено / пропущено с причинами) видна
    в запросе. Сбой записи не отменяет завершение запроса: показывается ошибка и
    кнопка «Записать в прайс ещё раз».

### Применение в оптимизации
29. В карточке сметы — список запросов КП со статусами и числом завершённых, но
    не применённых.
30. В редакторе оптимизации кнопка «Цены из КП» активна, если у карточки есть
    завершённые запросы с ценами и у оптимизации есть строки.
31. Первый шаг — предпросмотр, **ничего не пишет**: какие строки получат цену
    (было → стало, КП), какие позиции не найдены, какие неоднозначны — для них
    человек выбирает строку или пропускает; сколько цен «включают материалы».
32. Сопоставление: `row_id` источника (если запрос создан на этой оптимизации)
    → № в исходной смете + наименование → тип + наименование + единица.
    Неоднозначное само не берётся.
33. «Применить» создаёт новую версию оптимизации «Цены из КП» от последней
    неоткатанной; предыдущая не меняется, новая откатывается как любая версия.
    Материал — `price_material`, работа — `price_work`; цена без коэффициента,
    без НДС, в единице строки; коэффициент версии сохраняется.
34. Несколько запросов на одну строку — по каждому выбранная (или минимальная),
    затем минимальная из них.
35. Строка с ценой из КП подсвечена «цена из КП»; подсказка — поставщик, дата,
    число КП. Цена работы «включает материалы» подсвечена отдельно с подсказкой
    «проверьте материал позиции»; цена материала при этом **не меняется**.
    Та же пометка — в скачиваемых xlsx оптимизации.
36. Применение — автоматическая операция: не пишет сигналы журнала
    корректировок; в истории — «Цены из КП: N строк».
37. Одновременная правка коллегой → конфликт версии, ничего не записано, новой
    версии нет.

## Ограничения

* Входной файл заказчика не трогается (правило №2); цена в строке — исходная,
  коэффициент сверху (правило №3); экран и файл считают одинаково (правило №4).
* Цены строк сметы и прайса — без НДС.
* ИИ сопоставляет только с позициями запроса по их id; со строками сметы и
  прайса сопоставление детерминированное.
* Стоимость разбора КП — в журнале вызовов API (правило №13).
* Файл КП ≤ 50 МБ, PDF ≤ 100 страниц.
* «Эталон» (правило №18) по-прежнему оставляет у работы один ключ «Из смет» —
  цены «КП: …» он тоже стирает и показывает это в предпросмотре.

## Не входит

* Отправка запроса поставщику из системы.
* Учёт доставки, сроков и минимальной партии в сравнении цен.
* Запрос КП из раздела сводной.
* Сроки/дедлайны задач, SLA, эскалации.
* Почта и Telegram.
* Автоматическое применение цен в смету при завершении запроса.
* Отдельная роль руководителя отдела производства работ.
